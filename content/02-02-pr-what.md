## 先把一句话说死：PR 是什么 {#what}

:::goal 能用一句话说出 PR 的输入和输出（netlist → GDSII），能分清 PD/DE/ME 三个岗位，能说出 block 与 top 的区别、三种线分别是什么。
:::

**PR = Place and Route = 布局和布线。** 它在做的事情只有一件：

> 把综合之后的 **netlist（网表）**，变成可以送去工厂流片的 **GDSII**。

:::term PR / PnR | 布局布线
Place and Route 的缩写，写作 PR 或 PnR 都行，指同一个流程：先把单元"摆"到芯片上的具体坐标（Place），再用金属线把该连的连起来（Route）。
:::

:::term netlist | 网表
综合工具吐出来的电路描述文件，后缀一般是 `.v.gz`（压缩的 Verilog）。它只说明"哪个引脚连哪个引脚"——**逻辑连接**，不含任何坐标、长度、层信息。
:::

:::term GDSII | 版图文件
送工厂加工用的版图文件（II 指的是二进制形式）。它描述每一层金属、每一个孔、每一个单元在硅片上的**真实形状和坐标**——**物理连接**。
:::

用装修打个比方：综合给你的是"水电点位图"（哪个插座接哪根线，纸上画得清），PR 要把它变成"墙里真的埋进去的线管，位置精确到毫米"。图纸和施工图不是一回事，netlist 和 GDSII 也不是一回事。

:::pitfall 把 netlist 当版图
**现象**：面试被问"你交付的成果是什么"，答"综合出来的 netlist"。
**原因**：netlist 是逻辑网表，没有面积、没有坐标、没有金属层，工厂拿它没法生产。
**正确说法**：PR 的交付物是 GDSII（以及配套的 def、报告、时序数据库），netlist 只是 PR 的**输入**。
:::

## 综合给的是逻辑连接，PR 才给出物理连接 {#logic-vs-physical}

完整链条上有三个关键节点，别混：

| 阶段 | 谁做 | 产物 | 关键特征 |
|---|---|---|---|
| 综合（RTL → 电路） | 前端 | netlist（.v.gz） | 器件按功能连起来，**只有逻辑关系** |
| 布局布线（PR） | 后端 | GDSII + def + 报告 | 器件有坐标，线有层与宽度，**物理可实现** |
| 签核（STA / PV / PA） | 后端/签核组 | 通过的数据库 | 证明它在各种 corner 下都能工作 |

举个具体例子理解"逻辑 → 物理"：

写一行 RTL `always @(negedge rst) cnt <= 0;`，意思是"rst 下降沿把 8 位寄存器 cnt 清零"。综合工具会把它翻译成一堆真实的门：反相器、与门、或门、多路选择器、触发器——**逻辑上等价**。但这时候还没有任何东西告诉工具：这个触发器放在芯片的哪个角落？它到下一个触发器的线要走第几层金属、绕多远？

这些正是 PR 要回答的问题。器件放得远、线绕得长，延迟就大，时序就过不去；放得挤，布线绕不开，DRC 就爆。所以 PR 不是"画图"，是**在面积、时序、可制造性三者之间不停做交易**。

## 三个岗位缩写：PD / DE / ME {#roles}

看招聘 JD 时最先撞上的三个词：

:::term PD | 物理设计工程师
Physical Design Engineer，也就是"后端"。负责把 netlist 做到 GDSII：floorplan、place、cts、route，以及中间无数轮优化。**PR 就是 PD 的主战场。**
:::

:::term DE | 设计工程师（前端）
Design Engineer。写 RTL、做综合、给后端交网表的人。后端发现"这条路径逻辑太深，怎么摆都过不了"时，要找 DE 改 RTL。
:::

:::term ME | 中端工程师
Middle End Engineer。夹在前后端之间：DFT（扫描链插入）、formal、低功耗结构、网表质量检查，也常负责 MMMC 环境与 sdc 的整合。**不是所有公司都设这个岗，但大厂很常见。**
:::

一句话记法：**DE 写逻辑，ME 加结构，PD 落到硅片上。**

## 后端的两个方向：物理设计与时序设计 {#two-tracks}

后端不只 PR 一件事，粗分两条线：

| 方向 | 干什么 | 常见工具 |
|---|---|---|
| 物理设计（Physical Design） | 布局、布线、时钟树、供电、DRC/LVS 收敛 | Innovus、ICC2 |
| 时序设计（Timing / STA） | 判断信号能不能"按时到达"，出时序报告、定约束 | PrimeTime、Tempus |

两者不是上下级，是**互相拉扯**：PR 把线绕短一点，时序就好一点；时序要求太狠，PR 就得更费力地摆和绕，面积和功耗跟着涨。真实项目里这两个角色每天都要对账——所以本站后面既讲 Innovus，也单独讲 STA。

## block 级和 top 级：你接到的活是哪一种 {#block-top}

后端设计按层级分两类，**决定了你每天要操心的东西完全不同**：

:::term block / tile | 模块（块级设计）
一个完整芯片被切成若干块，分给不同的人做。**block 和 tile 是一个意思**，就是"分给你的那块活"。块级设计的边界是别人定好的：面积多大、从哪进哪出（port 位置），你只管把块内部做干净。
:::

:::term top | 顶层（顶层设计）
把各个 block 拼成一颗完整芯片的那一层。要定整颗芯片的面积、每个 block 摆在哪、block 之间的连线怎么走，还要把电源网络从 pad 一路送到每个 block 里。
:::

| | block 级 | top 级 |
|---|---|---|
| 边界 | 别人给（面积 + port 位置） | 自己定 |
| 主要矛盾 | 块内时序、拥塞、DRC | 块间连线、电源网络、全局拥塞 |
| 交付 | 干净的 block（def/lef/GDS） | 整颗芯片 GDSII |
| 交接方式 | top 用 **def** 把面积和 port 位置发给 block owner | 收回各 block 的 def/GDS 拼装 |

这张表里"top 用 def 把面积和 port 位置发给 block owner"是后面第 4 课的重点：**def 是块级与顶层之间的合同**，写错一个 port 坐标，块里所有接口逻辑都得重做。

## 布局：什么必须人摆，什么能自动摆 {#place}

"布局"听着像全部自动，其实分三类器件，待遇完全不同：

:::term macro / mem / sram | 宏单元、存储器
第三方厂商做好的成品 IP（内存、SRAM、模拟模块、PLL 等），有固定形状和固定引脚位置。**必须由人（或脚本按人的策略）摆放到确定位置**——工具不会自动帮你摆，因为摆错会同时毁掉时序和布线通道。
:::

:::term stdcell | 标准单元
标准单元库里的基本逻辑门（与、或、非、触发器等），**等高、宽度不同、按行（row）排列**。因为有统一的 lib/lef 描述，工具可以自动摆放、自动优化。
:::

:::term physical cell | 物理单元
只有物理信息、**没有逻辑功能**的单元：tap cell（阱接触）、endcap（行端帽）、decap（去耦电容）、filler（填充）。它们不进网表，是 PR 阶段按规则补进去的。
:::

为什么 mem 要人摆？三个原因，面试常问：

1. **引脚位置固定**：mem 的 pin 在哪一侧是工艺决定的，摆错方向，线要从远处绕过来，时序和拥塞一起爆。
2. **面积大**：一个 mem 可能顶几千个 stdcell 的位置，摆歪了整块的布线通道就断了。
3. **有物理禁忌**：mem 上方通常禁止走线（routing blockage）、周围要留 halo，靠工具自动摆很容易踩规则。

所以真实项目里 floorplan 阶段最花时间的就是"mem 怎么摆"，摆完才轮到工具自动放 stdcell。

## 布线：三种线，三种命 {#route}

"布线"不是一种线，是三种，优先级和做法都不同：

| 线 | 干什么 | 为什么特殊 |
|---|---|---|
| **供电**（power） | 把电源/地从 pad 送到每个单元 | 要够宽、要成网（mesh/strap）、要算 IR drop 和电迁移 |
| **时钟**（clock） | 把时钟送到每个触发器的 clock 端 | 要求"同时到达"（低 skew），要单独做时钟树，普通布线器不许随便动 |
| **信号**（signal） | 其余所有数据/控制线 | 数量最多，是拥塞和 DRC 的主要来源 |

这三条线分别对应流程里的三步：**powerplan（打供电）→ cts（绕时钟）→ route（绕信号）**。下一课就把整个流程串起来。

:::note 一句话记住优先级
供电最硬（做不好芯片会烧/不工作），时钟第二（做不好时序全崩），信号最后（做不好就慢慢修）。
:::

## 模块分级与芯片分类：面试的"广度题" {#scale}

**模块分级**：一颗芯片按层级切成一级模块、二级模块、三级模块。越往上（一级）越大越接近顶层，越往下越像"一个具体功能块"。分给你的活通常落在二级或三级模块上——这也解释了为什么招聘会写"负责 XX 模块的 PR"。

**芯片分类**（知道各自算什么就行，面试常拿来探你的知识面）：

| 类型 | 是什么 | 典型厂商/场景 |
|---|---|---|
| SOC | 片上系统，把 CPU、总线、外设、存储接口集成到一颗 | 手机主芯片、车规芯片 |
| CPU | 通用处理器，看核心数、主频 | Intel、AMD |
| GPU | 图形处理器，大量并行计算 | NVIDIA、AMD |
| NPU | 神经网络加速单元 | 手机/服务器 AI 芯片 |
| DSP | 数字信号处理，音频、图像、通信基带 | 音频/基带芯片 |
| DDR | 缓存/内存接口控制器 | 内存条、SoC 的存储接口 |
| USB / PCIE | 高速串行传输接口 | 外设、板级互连 |
| VCN | 视频/音频编解码处理 | 多媒体芯片 |

这些名字不影响你摆一个 stdcell，但影响你判断"这个项目大概多难"：**接口类（DDR/USB/PCIE）对时序和信号完整性极敏感，NPU/GPU 则是面积和功耗的大户**。

## 这一课在项目里的位置 {#in-project}

把这一课放回真实时间线：

1. DE 交来 netlist（第 N 版），ME 补好 DFT 和 MMMC 环境；
2. 你作为 PD 接手，先搞清楚**这块活的边界**（block 还是 top、面积多大、port 在哪）；
3. 导入数据（netlist + lef + lib + sdc + MMMC）；
4. 走完 init → floorplan → powerplan → place → cts → optcts → route → optroute → chipfinish；
5. 交出 GDSII + def + 报告，交给签核组做 STA / PV / PA。

下一课就把第 4 步这九个阶段一个一个拆开讲，并且告诉你每个阶段"做完怎么看它做得好不好"。

:::lab 用一张纸画出这条链
在一张纸上从左到右写五个框：`RTL` → `netlist` → `PR` → `GDSII` → `流片`。然后在每个箭头下面写一行字：这一步的产物是什么、谁做、下一个环节拿它干什么。

验收标准：能不看资料说清 netlist 和 GDSII 的差别（一个有坐标一个没有）、能说出 block 与 top 各交付什么、能说出三种线分别对应流程里的哪一步。
:::

PR 的输入和输出分别是什么？| 输入是综合后的 netlist（网表）；输出是 GDSII（版图），以及 def、报告、时序数据库等配套文件。
