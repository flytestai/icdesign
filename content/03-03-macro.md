## 宏单元为什么难 {#why}

标准单元小、均匀、可以随便挪。宏单元（SRAM、PLL、模拟 IP）不一样：

- **大**：一个 SRAM 可能占 5% 的芯片面积。
- **硬**：形状固定、引脚位置固定、不能旋转任意角度（只能 90° 翻转）。
- **吸线**：一个 SRAM 可能有 200 个引脚，全往一个方向出线。

所以宏单元周围是拥塞的高发区。**拥塞不是布线工具无能，是布局没给够空间。**

## 通道要留多宽：一个能用的估算 {#calc}

思路：数一数这个通道要过多少根线，再看每根线占多少横向空间。

```
通道宽度 ≈ (穿过该通道的连线数 × 每线间距) ÷ 可用金属层数 + 余量
```

举例：两个 SRAM 之间的竖直通道，中间要过 300 根线，工艺 M2~M5 可用于横向走线（4 层），每根线间距 0.2µm：

```
单层能过：300 / 4 = 75 根
需要宽度：75 × 0.2 = 15 µm
加 30% 余量：≈ 20 µm
```

所以这个通道至少留 20µm。工具默认给的 `-channel` 有时候是 10µm，不够。

:::term Channel | 通道
两个宏单元之间（或宏单元与边界之间）留给走线的空间。太窄 → 拥塞；太宽 → 浪费面积。

**经验值：小设计 10~20µm，中等设计 20~40µm，大 SRAM 密集区 40µm 以上。**
:::

:::scene 用 flyline 判断摆得对不对
Innovus 有个可视化功能叫 **flyline**：把每条连线的两端用直线连起来。

摆完宏单元，打开 flyline 看一眼：

- 线密集交叉、形成"蜘蛛网" → 摆错了，连接多的模块离得太远。
- 线基本平行、短 → 摆得不错。

这比看数字直观得多，也是 review 时最常用的说服材料。
:::

## 摆放的四条硬规则 {#rules}

1. **靠边**：宏单元贴芯片边缘放，中间留给标准单元。中间放一个 SRAM，等于把标准单元区切成两半。
2. **对齐**：几个 SRAM 的边对齐，形成整齐的通道。错位会产生"死角"，那里永远布不通。
3. **朝向**：pin 一律朝向标准单元区。Innovus 里用 `MY`（上下镜像）、`MX`（左右镜像）调。
4. **留 halo**：宏单元周围设一个"禁放区"（halo / blockage），防止标准单元贴着它摆，把通道堵死。

```tcl
# 摆宏单元并指定朝向
placeInstance u_sram0 50 80 MY
placeInstance u_sram1 50 260 MY

# 给宏单元加 halo（四周各留 8µm 不放标准单元）
createPlaceBlockage -type halo -box 50 80 180 200 -name halo_sram0
# box 格式：llx lly urx ury（左下角 + 右上角坐标）

# 或者用更简单的方式：设置宏单元周围的 keepout margin
setPlaceMode -place_global_module_padding {u_sram0 8 u_sram1 8}

# 检查：有没有重叠、有没有超出边界
checkFPlan -reportUtil
```

:::term Halo / Blockage | 保护环 / 禁布区
- **Halo**：宏单元周围一圈不许放标准单元的区域，防止挤死通道。
- **Blockage**：明确禁止布线/摆放的区域，常用于电源网格下方或特殊 IP 周围。

区别：halo 是"给这个宏单元留的缓冲"，blockage 是"这块地不许用"。
:::

:::pitfall 宏单元贴太近，布线阶段无解
现象：布线跑到 70% 卡住，报

```
Routing congestion detected in region (1200, 800) - (1800, 1400)
```

打开热图，红色区域正是两个 SRAM 之间的 6µm 缝隙。

此时的选择只有两个：把 SRAM 挪开（重做布局+CTS，8 小时），或者硬着头皮让工具拆线（DRC 清不干净，最后还是要重做）。

**结论：floorplan 阶段多花 30 分钟算通道，能省后面 8 小时。**
:::

## 检查清单（摆完必做） {#checklist}

| 检查项 | 怎么做 | 通过标准 |
|---|---|---|
| 重叠 | `checkFPlan` | 无 overlap |
| 出界 | `checkFPlan` | 全部在 core 内 |
| 利用率 | `report_area` | 与目标差 <5% |
| 通道 | 目视 + flyline | 无 <10µm 的窄缝 |
| 朝向 | 看 pin 位置 | 全部朝标准单元区 |
| halo | `reportPlaceBlockage` | 关键宏单元都有 |

## 一个真实的数字 {#real}

我们在一套 45nm 开源库上跑过万门设计（9390 单元、6 个 SRAM 通道）。第一版没算通道，直接按默认间距摆：

- 布线 DRC：**6000 条**
- 局部拥塞：红色区域 5 处

改成"按出线数算通道 + halo + 对齐"之后：

- 布线 DRC：**0**（同一套布线参数）

**这就是 floorplan 的威力：不是优化出来的，是布局对了自然就通了。**

:::lab 动手：算通道宽度
条件：某通道要过 420 根信号线，可用 4 层金属横向走线，线间距 0.16µm，余量 30%。

```bash
python3 -c "
n=420; layers=4; pitch=0.16; margin=1.3
per=n/layers; w=per*pitch*margin
print('单层线数', per)
print('需要通道宽度 %.1f um' % w)
"
```

预期：单层 105 根，通道 ≈ 21.8µm。

过关标准：把层数改成 2 层，算出需要多宽，并解释"为什么减少层数会让通道变宽"。
:::

:::check
- 会用"线数 ÷ 层数 × 间距 × 余量"估算通道宽度
- 知道 halo 和 blockage 的区别
- 会看 flyline 判断宏单元摆得好不好
- 记得摆完跑 `checkFPlan`
- 能说出宏单元贴太近的两个后果
:::

:::quiz
通道宽度怎么估算？|穿过通道的线数 ÷ 可用金属层数 × 线间距 × 安全余量（约 1.3）。
halo 和 blockage 有什么区别？|halo 是围绕宏单元的一圈禁止摆放区（防挤死通道）；blockage 是任意指定区域的禁止摆放/布线。
为什么宏单元要"靠边对齐"？|靠边能把完整区域留给标准单元；对齐能形成整齐通道，避免死角。
flyline 用来判断什么？|直观判断宏单元相对位置是否合理——连接多的模块应该靠近，线应该短而平行。
布局阶段没留够通道，布线阶段能补救吗？|基本不能。布线只能绕线，绕不开物理空间不足，最终要么大量 DRC，要么回头重做 floorplan。
:::
