## 一条线看全局 {#why}

:::goal 能按顺序说出设计全流程的七个环节及各环节的交付物；能说清前端/中端/后端各用什么工具（VCS / DC 或 Genus / Innovus 或 ICC2）、各自的边界在哪；能说出 GDSII 之后到封装出货要经过哪几步；能指出后端里哪些环节手动、哪些自动。
:::

你现在学的 PR 只是这条链上的一段。**不知道上下游在干什么，就无法判断"这个数据对不对、这个 bug 该找谁"**——而这两件事，恰恰是新人最常卡住的地方。

```
需求/架构 → 前端 RTL 编码 → 前端仿真 → 中端综合 → 形式验证 → 后端物理实现 → GDSII
   ↑甲方        ↑DE            ↑VCS       ↑DC/Genus   ↑Formality   ↑PD(你在这里)     ↓
                                                                              代工厂流片
                                                                                    ↓
                                                        出货 ← 封装 ← 切割 ← 晶圆测试
```

## 第一段：需求与架构 {#spec}

芯片设计始于**甲方的需求**。文档举的例子很具体：像比亚迪这样的整车厂发标，要一颗什么功能的芯片。

接手的是两类架构师：

- **顶层架构师**：定**工艺制程**（几纳米）与**模块组成**（CPU 计算、DDR 存储、USB 传输……）。选择工艺是成本、功耗、性能的三角权衡——先进工艺更贵，但同样面积能塞更多逻辑；
- **底层架构师**：定模块之间的**具体逻辑连接**，也就是后面 RTL 要写的东西。

这一步的产出是**设计规格（spec）**：有什么模块、跑多快、功耗上限多少、面积预算多少。**后面所有人的工作，都是把这纸规格变成实物。**

## 第二段：前端 RTL 编码与仿真 {#frontend}

:::term RTL | Register Transfer Level 寄存器传输级
用硬件描述语言描述"每个时钟沿，数据从哪些寄存器经过哪些逻辑搬到哪些寄存器"的层级。**它只描述逻辑，不含任何物理信息**（没有延迟、没有面积、没有位置）。
:::

前端工程师（**DE**，Design Engineer）用 **Verilog** 或 **VHDL** 把架构师的连接关系写成 RTL 代码：

```verilog
// 一个 8 位计数器：每个时钟上升沿加 1，rst 为低时清零
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) cnt <= 8'b0 ;        // 复位：清零
    else        cnt <= cnt + 1'b1 ;  // 正常：每拍加一
end
```

写完之后必须**仿真验证**：

:::term 仿真 | simulation（工具：VCS）
用软件模拟电路行为，给一组输入激励，看输出是否符合预期。目的是**消灭逻辑 Bug**。
:::

文档强调了一个关键点：**仿真阶段不涉及物理延迟（Delay）**。VCS 只看"逻辑对不对"，不问"信号要跑多久"。因为这个阶段网表还不存在，没有门、没有线，自然也谈不上延迟。

:::pitfall 以为"仿真通过就没问题了"
**现象**：RTL 仿真全绿，综合之后时序一塌糊涂，或者后端发现某条路径根本收敛不了。

**原因**：仿真验的是**功能**，不是**时序**。一条组合逻辑链写得太长（比如一个周期里串了 30 级逻辑），功能完全正确，但物理上根本跑不到目标频率。

**分工**：功能归前端仿真管，时序归后面 STA/PR 管。**仿真通过只代表"逻辑对"，不代表"能做出来"。**
:::

## 第三段：中端综合 {#synthesis}

:::term 综合 | synthesis（工具：DC / Genus）
把 RTL 代码翻译成**门级网表**：选用库里真实存在的标准单元（与门、触发器……），并把它们连起来。输入是 RTL + 库 + 约束，输出是 netlist。
:::

两家工具，性格不同（文档的对比很实用）：

| 工具 | 厂商 | 特点 |
|---|---|---|
| **DC**（Design Compiler） | Synopsys | 成熟稳定，**不易报错**，业界老牌 |
| **Genus** | Cadence | 综合时就**考虑时序信息**，对后续时序分析更友好 |

文档提到一个真实做法：**不少公司两种工具都跑一遍，比较结果挑更好的那版**。这不是折腾——综合结果直接决定后面 PR 有多难做，值得多花一天机时。

综合阶段要做三件事：

1. **读 SDC 约束**——按目标频率决定用什么单元、什么驱动强度；
2. **选 Memory 宏单元**——存储不用触发器堆，直接用第三方 IP（SRAM）；
3. **初步 STA 检查**——先看个大概，**详细的静态时序分析由后端做**。

:::term SDC | Synopsys Design Constraints
时序约束文件，告诉工具"要在什么频率下工作、外部给多少延迟"。**综合和 PR 都读它**，是贯穿前后端的"要求文档"（阶段二后面有专课）。
:::

综合完还要过一道关：**形式验证**。

:::term 形式验证 | Formality（工具名）
用数学方法证明"综合后的网表"与"原始 RTL"**功能完全等价**。它不是仿真（不跑激励），而是穷举证明。
:::

为什么必须要它？因为综合工具做优化时会重写逻辑（合并、替换单元、删冗余）。**万一它优化错了，仿真是发现不了的**——你仿的是 RTL，不是网表。Formality 通过，才敢说"网表就是那份 RTL"。

## 第四段：后端物理实现（你的战场） {#backend}

后端（**PD**，Physical Design Engineer）接手三样东西：**netlist + SDC + 库（lib/lef）**，然后：

| 环节 | 谁在干活 | 关键动作 |
|---|---|---|
| **Floorplan** | **人手动，工作量最大** | 定芯片面积、摆 Memory 宏单元、摆 IO 端口位置 |
| **Placement** | 工具自动 | 摆几百万个标准单元，设密度与间距 |
| **CTS** | 工具 + 人调 | 建时钟网络，保证满足 setup 与 hold |
| **Routing** | 工具自动 | 连信号线 + 布电源线（VDD/VSS，通常做网状供电） |
| **输出 GDSII** | 工具 | 交付给代工厂的版图文件 |

两个必须记住的判断：

:::tip 后端里"手动"和"自动"的分界
- **手动最多的是 Floorplan**：Memory 摆哪儿、IO 端口放哪边，直接决定后面能不能绕通、时序好不好。这也是为什么课表给 floorplan 排了 10 学时。
- **标准单元摆放（Placement）是工具自动的**：几百万个 cell 人根本摆不过来，人做的是**设参数**（密度、间距、优化目标）。
:::

另外，文档提到每个阶段之后都会有 **OPT（优化）**：布局优化、CTS 优化、布线优化。**PR 不是"跑五步就完"，而是"跑一步、修一轮、再跑下一步"的循环**（后面流程课会展开）。

## 第五段：流片、制造与封装 {#fab}

GDSII 交付之后就离开设计团队了，进入制造：

:::term GDSII | GDS II 版图文件
交付给代工厂的最终版图数据，含每一层掩模的全部几何图形。**它是设计阶段的终点，制造阶段的起点。**
:::

制造链路：

1. **代工厂（Foundry）流片**：台积电、三星、中芯国际这类厂，用**光刻、刻蚀**等工艺把版图一层层"印"到硅晶圆上；
2. **晶圆（wafer）**：一片晶圆上同时做几百上千颗相同的芯片；
3. **晶圆测试（CP/Wafer Sort）**：逐颗测，把坏片标出来——**先筛掉再切割，省封装费**；
4. **切割（Dicing）**：切成一颗颗独立的 die；
5. **封装（Packaging）**：装进外壳、引出引脚，做成能焊到板子上的芯片；
6. **成品测试（FT）→ 分选编袋 → 出货**：成为你在市场上买到的那个封装件。

:::term foundry | 代工厂
只做制造、不做设计的晶圆厂（台积电、三星、中芯国际）。与之相对的是 Fabless（只设计不制造，如英伟达、高通）和 IDM（设计制造都做，如英特尔）。
:::

## 分工边界：一张表记住谁管什么 {#boundary}

| 角色 | 干什么 | 工具 | 交付物 |
|---|---|---|---|
| 架构 | 定规格、定模块 | — | spec |
| **DE**（前端） | 写 RTL、跑仿真 | Verilog/VHDL、**VCS** | RTL 代码 |
| **ME**（中端） | 综合、形式验证 | **DC/Genus**、**Formality** | 门级 netlist + SDC |
| **PD**（后端） | 物理实现 | **Innovus / ICC2** | **GDSII** + 各种报告 |
| Foundry | 制造 | 光刻/刻蚀 | 晶圆 |
| 封测厂 | 切割封装测试 | — | 封装芯片 |

:::tip 新人最容易搞错的三件事
1. **"网表跑不通"不等于后端问题**——先确认 netlist 版本与 SDC 版本是否配套；
2. **前端不会替你做时序**——仿真通过只是功能对，时序是后端（和 STA）的活；
3. **GDSII 不是终点**——后面还有 DRC/LVS 签核、流片、封测，任何一环挂掉都要回头改。
:::

```bash
# 3. 约束文件的后缀是什么？

```

验收标准：不看课能按顺序说出"需求→RTL→仿真→综合→形式验证→后端→GDSII→流片→封测"，并说清每一环的交付物与负责人。
:::

:::quiz
前端仿真用的是什么工具？它验证的是什么，不验证什么？| VCS。验证逻辑功能是否正确，不验证物理延迟（那个阶段还没有门和线）。
综合的作用是什么？DC 和 Genus 各有什么特点？| 把 RTL 翻译成门级网表；DC 成熟稳定不易报错，Genus 综合时考虑时序、对后续时序分析更友好，很多公司两者都跑再比较。
为什么综合之后还要做形式验证（Formality）？| 综合工具会重写逻辑做优化，万一优化出错，仿真（仿的是 RTL）发现不了；Formality 用数学方法证明网表与 RTL 功能等价。
后端接手的三个核心输入是什么？| 门级 netlist、SDC 约束、库（lib/lef，走 MMMC 配置）。
后端里手动工作量最大的是哪一步？为什么？| Floorplan：Memory 摆哪、IO 端口放哪直接决定绕线资源与时序质量，必须人来决策；而几百万 cell 的摆放是工具自动的。
GDSII 之后到出货要经过哪些步骤？| 代工厂流片（光刻刻蚀）→ 晶圆 → 晶圆测试筛坏片 → 切割 → 封装 → 成品测试 → 分选出货。
"仿真通过"为什么不能代表"设计没问题"？| 仿真只验功能；组合逻辑链过长等时序问题在功能上完全正确，但物理上跑不到目标频率，需靠 STA/PR 检查。
:::
