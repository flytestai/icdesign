## 先画对象关系，再写查询 {#objects}

:::note 原创专题
本讲参考钉钉目录第 14 项的主题独立编写，不转载原文、图或项目参数。命令用于讲解 Innovus legacy `dbGet` 的查询思路，未在 Innovus 中实测，属性名和选项以本机版本帮助为准。
:::

先区分**实例**和**库单元**。`top` 指当前顶层设计；`top.insts` 是实例集合；实例的 `name` 是设计中的名字，实例的 `cell` 则指向所引用的库单元。同一个库单元可以被多次实例化，所以库单元名与实例名不能混用。若要核对一个宏在版图中出现几次，该数的是实例，不是库单元。

## 查询宏实例：筛选属性，再回溯 {#macro-query}

以下查询以 `baseClass` 为 `block` 作为示例筛选条件。先读取全部实例名，再沿实例到库单元的路径筛选，最后对筛中的实例取名。

```tcl
dbGet top.insts.name
set blocks [dbGet -p2 top.insts.cell.baseClass block]
if {$blocks ne "0x0" && [llength $blocks] > 0} {
    puts [dbGet $blocks.name]
} else {
    puts "未匹配到宏实例"
}
```

`-p` 回溯一层：在该筛选路径上得到符合条件的库单元对象；`-p2` 回溯两层，得到引用这些库单元的实例。**筛选发生在哪层，和最终返回哪层，是两件事。** 假设 `u_buf` 引用 `BUFX2`，`u_sram0` 与 `u_sram1` 都引用同一个 `SRAM_TINY`，且只有后者的库单元类别为 `block`，则结果应包含两个 SRAM 实例名，而不是把它们合并为一个库单元名。

## 空结果不等于设计里没有宏 {#empty-results}

碰到空列表、`0x0` 或报错，先分开处理。报错优先核对是否加载了设计、路径属性是否可用；空结果则先看 `top.insts` 是否有对象，再查 `top.insts.cell.baseClass` 的实际取值，确认既没有筛错类别，也没有查错设计快照或层级范围。如果已知至少有一个 SRAM，也可先按它的实例名定位，单独查看其库单元名字和类别；这样能判断范围有误还是筛选条件不合适。将原始返回中的空指针标记识别出来后再计数：Tcl 的 `llength 0x0` 是 `1`，却不是一个有效实例。示例中的查询和 `puts` 不改设计数据库；排查阶段不要混入 `dbSet` 等修改操作。端口的类似读取见 [Floorplan 实操](/lesson/03-01a-flp-lab/#ports)。

## 自检：你数的是哪一层对象？ {#review}

**题目：** 两个 SRAM 实例引用同一个库单元。要导出两个实例名，筛选后为什么不能停在 `-p`？如果结果只有 `0x0`，可以记为找到一个宏吗？

**答案：** `-p` 停在库单元层，不能用库单元名替代实例名；要用 `-p2` 回到实例层再取 `name`。`0x0` 是空指针标记，不计为宏；应核对当前设计与类别，再判断是否真无匹配。
