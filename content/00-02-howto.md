## 每一课的固定结构 {#structure}

:::goal 学完这一课，你能给自己排出 8 周的学习表，并说清每个练习环节该练什么、练到什么程度算过关。
:::

这门课每一章都是同样的八段，顺序固定。**你不需要每次都读完，但八段缺一段就说明这一课没学完。**

| 段落 | 长什么样 | 你在这段该做什么 |
|---|---|---|
| 本章目标 | 蓝色条，一句话 | 先看，判断这一章值不值得现在读 |
| 工作场景 | 绿色块，写"谁在催你" | 把知识和岗位需求挂上钩，知道学了用在哪 |
| 概念 | 正文 + 生活类比 | 慢读，这一段决定你能不能举一反三 |
| 术语卡 | 灰色卡片，"点击看解释" | **先猜再看**。直接点开等于没记 |
| 命令 / 表格 | 黑底代码块，注释是灰色的 | 注意灰色注释行，那才是"为什么" |
| 动手 | 蓝色框，命令 + 预期输出 | 必须自己跑一遍，哪怕是在页面里的模拟终端 |
| 常见坑 | 橙色块，贴真实报错原文 | 遇到同样报错时回来搜这段 |
| 自测 | 紫色块，点"看答案" | 先在心里回答，再点开对照 |

:::note 为什么顺序是这样
"先给目标、再给场景、最后才给命令"不是排版偏好。0 基础最常见的失败方式是：**先抄命令，抄完不知道自己在干嘛，第二天全忘**。把目标和场景放在前面，是逼你先建立"这件事为什么存在"的记忆锚点。

第二常见的失败方式更隐蔽：**只读不敲**。读的时候每一步都"懂"，合上页面连 `cd` 后面该跟什么都想不起来。
:::

:::scene 周三晚上十点，屏幕上什么都没有
开学第二周，你晚上十点坐在电脑前，对着模拟终端敲了一句：

```
grep VIOLATED reports/timing.rpt
```

回车，光标跳回下一行，**一个字都没输出**。

你不知道是命令拼错了、路径写错了、还是这个文件里本来就没有 VIOLATED。三种可能对应三种完全不同的动作：改命令、改路径、还是换个文件——但你现在分不出来，只能干坐着。

这一课解决的就是这个：让你知道每种练习能验证什么、不能验证什么，以及卡住时按什么顺序排查。
:::

## 三种练法，以及各自的边界 {#threeways}

同一节课的练习可以分三层，越往下越接近真实工作：

| 层级 | 在哪练 | 能练到什么 | 练不到什么 |
|---|---|---|---|
| 一、读懂 | 这一页 | 概念、判据、报告怎么读 | 手感、报错长什么样 |
| 二、模拟终端 | 页面里的黑框（阶段一课程内） | Linux 命令、管道、重定向、脚本 | 真实权限、真机路径、EDA 工具 |
| 三、真机 | 你自己的 Linux 服务器 / 虚拟机 | 全部，包括 EDA 工具与报错 | 需要装环境、要等工具跑 |

**判断标准很简单**：如果你在模拟终端里能把一条管道命令拼出来，说明你理解了管道；但如果你要在真机上跑 `icc2_shell`，那必须去真机——模拟终端里没有 ICC2。

三层的正确顺序是 **读懂 → 模拟 → 真机**，而且每一层都有明确的"过关信号"：

1. **读懂过关**：能合上页面，用自己的话讲出这一节的因果（不是复述句子）。
2. **模拟过关**：能在不看答案的情况下，把这一课的示例命令敲对，并解释每一段在干什么。
3. **真机过关**：能在真实目录里完成同样的任务，并且遇到报错能自己定位。

:::term Sandbox（模拟终端） | 沙箱
一个隔离的、随便折腾都不会坏的环境。本站阶段一的课里内嵌了一个浏览器内运行的假 Linux，有虚拟文件系统和三十多个命令。它的作用是让你在"不敢乱敲"的阶段放心犯错。
:::

## 模拟终端怎么用 {#sandbox}

阶段一的课（01-01 到 01-06）里会出现这样的黑框：

- 点一下黑框就能输入，回车执行；
- `↑` `↓` 翻历史命令，`Tab` 补全命令名和文件名；
- 输入 `help` 看所有可用命令；
- 右上角"重置"把文件系统恢复原样（你新建的目录、改过的文件都会清掉）。

它里面预置了一份练习工程，路径是 `/home/autumn`，和真实项目同构：

```
/home/autumn
├── backend_lab/soc/
│   ├── dc/        dc.tcl、soc.sdc、soc_net.v、dc.log
│   ├── pnr/       pnr.tcl、reports/{timing,paths,drc}.rpt
│   └── rtl/       soc_top.v
├── pdk/nangate45/ lib/ 和 lef/ 各一个文件
├── logs/route.log
├── run.sh         已带执行权限（755）
└── notes.txt      一份三天的工作笔记
```

**第一个练习：把"我在哪"走一遍**（在 basic 预设里依次敲，输出是模拟环境里的真实结果）：

```bash
# 作用：熟悉虚拟工程；在模拟终端 basic 预设下执行，不依赖真机
pwd                          # 输出 /home/autumn，确认起点
ls -l                        # 输出 6 个条目：README.md、backend_lab、logs、notes.txt、pdk、run.sh
cat README.md                # 读项目自述，里面写了每个目录放什么
cd backend_lab/soc/pnr       # 进到布局布线目录，提示符会变成 ~/backend_lab/soc/pnr
ls -l reports                # 看到 drc.rpt、paths.rpt、timing.rpt 三个报告
cat reports/drc.rpt | wc -l  # 输出 12：这份 DRC 报告一共 12 行
grep -n slack reports/timing.rpt   # 输出 32:  slack (MET) 1.58，行号 32
```

**它的六条硬边界**（这张表是逐条在模拟终端里验证过的，别在这里浪费时间）：

| 你想做的事 | 模拟终端的结果 | 真机上 |
|---|---|---|
| `cd -` 回上一个目录 | 报 `cd: -: No such file or directory` | 正常跳回上一个目录 |
| `run.sh > log 2>&1` | 报 `-bash: 1: command not found` | 正常合并错误流 |
| `awk '{s+=$2} END {print s}'` | 无输出（没实现累加） | 正常求和 |
| `find . -type d` | 报 `find: 'd': No such file or directory` | 正常列目录 |
| `ls -lh` 的 `-h` | 不生效，还是字节数 | 变成 4.0K / 1.2M |
| `man ls` | 报 `man: command not found` | 打开手册 |

**这不是模拟器做坏了，而是它的边界**：它练的是"命令怎么拼、路径怎么走、输出怎么读"，不练"工具行为"。上表这几条，到真机上再练。

:::pitfall 模拟终端的报错和真机对不上，以为自己学错了
现象：你在模拟终端里敲 `cd -`，报 `cd: -: No such file or directory`；换到公司服务器上同样的命令却正常。

原因：模拟终端只实现了常用子集。它的报错格式模仿 bash，但没实现的功能会按"参数是文件名"处理，于是报"找不到这个文件"。

怎么查：先看这一课有没有列出边界表；没有的话，把命令拿到真机上再试一次。**判断依据是"这条命令是否依赖真实内核行为"**——涉及文件描述符（`2>&1`）、进程、权限位、工具二进制的，一律去真机。
:::

## 题库、错题本、术语表、搜索 {#tools}

页面顶部那排入口不是装饰，各自解决一个具体问题：

| 入口 | 解决什么问题 | 怎么用最有效 |
|---|---|---|
| 题库 | "看懂了"和"记住了"是两件事 | 每学完一课，抽 10 题；答错的点"不会，记下来" |
| 错题本 | 同一个概念反复错 | 每周清一次；清空了再学下一阶段 |
| 术语表 | 英文缩写看不懂、记不住 | 遇到不认识的先查这里，再看它在哪一课出现 |
| 命令速查 | 写脚本时忘了参数 | 按工具分组（Linux / Innovus / ICC2 / PT），不用翻课文 |
| 搜索 | 记得"讲过"但找不到在哪 | 搜中文或英文都行，命中直接跳到那一小节 |

:::term Spaced Repetition（间隔重复） | 间隔重复
在同一天重复十遍，不如在第 1、3、7、15 天各重复一遍。原因是遗忘曲线在前 24 小时最陡，**在"快要忘"的时候复习，记忆才被加固**。题库的抽题节奏就是按这个设计的。
:::

:::tip 题库的正确用法
不要连续刷。**学完一课当天刷一次，第三天再刷一次，第七天再刷一次**——这是间隔重复，比一口气刷 50 题有效得多。错题本就是替你记"哪几个概念还没过关"。

一个具体动作：错题本里同一道题错了三次，别继续刷，回去把那节课的**工作场景**重读一遍。题答错通常不是记性问题，是"不知道这东西用在哪"。
:::

## 笔记与进度 {#notebook}

每课最下面有"我的笔记"，保存后会同步到服务器（按浏览器匿名 ID 识别，不需要注册）。

笔记别抄课文，写这三种东西最有用：

1. **还没懂的点**：哪一句读了三遍还不通；
2. **自己的一句话解释**：用你妈能听懂的话解释 DRC；
3. **下次要试什么**：比如"试试把利用率从 0.3 改到 0.5，看 DRC 变成多少"。

进度看板（顶部"进度"）按阶段列出每课完成了几章，并给出"下一课"。**卡住的时候先看进度看板**，比在目录里翻要快。

笔记还有一个用法很少有人提：**开工前先翻自己上一篇笔记的"下次要试什么"**。后端的工作是连续迭代的，你昨天想的那个实验，今天正好有机器空着。

给一个三段式模板，照抄就能用（别写成日记）：

```
# 2026-11-22 03-08 CTS
没懂：insertion delay 为什么不是越小越好？功耗我懂，OCV 那段没通。
一句话：skew 是"同一批人到达的时间差"，不是"谁到得早"。
下次试：把 target_skew 从 0.08 改成 0.15，看 buffer 数和 WNS 各变多少。
```

这个模板的价值在于**每一段都对应一个动作**：没懂 → 去搜/去问；一句话 → 自测时的答案；下次试 → 下次上机的第一件事。

进度看板（顶部"进度"）按阶段列出每课完成了几章，并给出"下一课"。**卡住的时候先看进度看板**，比在目录里翻要快。它还有一个反直觉的用法：**如果某一课"读完了但章都没勾"，说明你只是翻过去了**——勾选是按章算的，这个差异是诚实的进度条。

## 一个可执行的 8 周计划 {#plan}

课表 113 学时，加上本站补充的实战共 137 学时。**8 周装不下全部**，所以这张表只排到"能独立跑完 Innovus 全流程、并用 ICC2 对照一遍"——这是求职的最低门槛，约 96 小时。

按每周 12 小时排（工作日 4 天 × 1.5h + 周末 6h），8 周正好 96 小时：

| 周 | 学什么 | 本周任务 | 验收（做不到就补一周） |
|---|---|---|---|
| 1 | 00-01、00-02、01-01、01-02 | 把终端、路径、文件、权限过一遍 | 不看笔记，在模拟终端里从 `~` 走到 `reports/`，说出每一层的绝对路径；能口算 755 的 rwx |

| 3 | 01-06、01-07、02-01、02-02 | 写脚本、版本管理、芯片与流程概念 | 写出带 `set -e` 和日志的 `run.sh`；白板画出九工位流程图 |
| 4 | 02-03、03-01、03-02 | 输入文件、Innovus 入门、floorplan | 说清 `.lef/.lib/.def/.v` 各是什么；能解释 utilization 与 congestion 的取舍 |

| 7 | 03-08、03-09 | CTS、布线 | 读出 skew / insertion delay / transition 三个数，判断先修哪个 |
| 8 | 03-10、03-11、03-12、04-01 | 后 CTS 优化、后布线优化、收尾、ICC2 入门 | 交一份自己的"项目周报"：每步耗时、遇到的两个违例、怎么修的 |

第 9 周之后还剩约 57 学时（ICC2 全流程 10h、UPF 4h、阶段五 24h、STA 深化 9h、功耗 2h、经验与求职 8h），按每周 12 小时另排 4~5 周。**不要为了赶 8 周把签核部分砍掉**——面试里最容易被问倒的恰恰是"你怎么判断这条路径能不能过"。

:::term Baseline（基线） | 基线
每一步跑完之后存下来的"当前最好结果"，后面所有改动都跟它比。比如 CTS 后 hold 最差 -0.15ns 就是基线，OptCts 之后如果变成 -0.30ns，说明这一轮改坏了，要回退。

没有基线，你就只能凭感觉说"好像好了一点"。
:::

## 卡住时的四步自救 {#debug}

新手卡住时最常见的反应是"再读一遍课文"，但八成的问题不在课文里。按这个顺序查，能解决大部分情况：

**第一步：确认自己在哪。** `pwd`。九成的"命令没反应"是路径不对——你在 `~/` 下执行 `cat reports/timing.rpt`，当然没有这个文件。

**第二步：确认文件在不在、有没有内容。** `ls -l 目标`。文件 0 字节，说明上一步根本没产出；文件不存在，说明路径或名字错了。

**第三步：把命令拆开跑。** 管道没输出时，先单独跑第一个命令：

```bash
# 作用：管道没输出时定位是哪一段断了；在报告所在目录执行
grep -c VIOLATED timing.rpt        # 第一步：单独跑 grep，看它自己能捞到几行
grep -n VIOLATED timing.rpt | head -3   # 第二步：加 -n 看命中在哪几行
```

如果 `grep -c` 就是 0，那问题在"文件里没有这个词"，不在管道。**先证明每一段单独能跑，再连起来。**

**第四步：搜原文。** 把报错第一行原样粘进搜索框（不要意译）。报错文本是全站索引的，别人踩过就能命中。

:::lab 动手：跑通一条完整的"定位链"
**任务**：在模拟终端（text 预设，起点就在 `reports/`）里完成下面四步，并记下每一步的输出。

```bash
# 作用：从"我在哪"走到"我捞到了什么"；模拟终端 text 预设，无需真机
pwd                              # 1. 确认起点：/home/autumn/backend_lab/soc/pnr/reports
ls                               # 2. 确认文件：drc.rpt、paths.rpt、timing.rpt
wc -l timing.rpt                 # 3. 确认文件非空：应输出 32（行数，wc 数的是换行符）
grep -n "slack" timing.rpt       # 4. 捞关键行：输出 32:  slack (MET) 1.58
```

**过关标准**：四步的输出都能对上；并且能回答"如果第 4 步什么都没输出，你先改哪一步"。参考答案：先看第 3 步行数是否为 0，再确认 `slack` 这个词是不是写成了 `Slack`（grep 区分大小写）。
:::
