ECO 是已经有基线时做的受控修改。先保存设计快照，记录目标实例或网络、时序视图、要求的裕量和允许改动范围。`setEcoMode` 设置 ECO 工作模式，它本身不会修正一条路径。`ecoChangeCell` 改变实例引用的库单元，例如改成逻辑相同、驱动能力不同的型号；大驱动可能带来更高输入电容，不能只看输出端。`ecoAddRepeater` 在指定网络连接上加中继单元；执行前应确认选的是目标分支还是整网，并检查极性、单元用途及合法工作条件。

```text
Baseline snapshot + reports
           |
           v
Scope -> logical delta -> legal placement -> incremental routing
                                                    |
                                                    v
Accept or roll back <- review <- extracted STA + physical checks
```

每个箭头都要有前后证据：目标连接、摆放位置、受影响网络或签核结果。如此才能判断坏结果来自选错分支、合法化移动了邻居，还是布线寄生改变了路径。

## 改完网表不等于改完版图 {#place-route}

网表确认新单元已串接在目标分支，不代表它已合法放置或走线已重连。在提供 `ecoPlace` 的流程中，由这个步骤处理 ECO 摆放与合法化；其他版本按项目指定命令操作。`ecoRoute` 负责 ECO 布线，需要复查重连范围、过孔、保留走线以及有无新开路。工具模式可能自动处理部分摆放或布线，仍要查日志与物理差异，不应从命令名称推断执行结果。

对单分支修复，优先建立允许变化的引脚清单和附近保护对象：新单元要落在授权供电域和合法位点，未选分支应仍由原网驱动。逻辑不动不代表物理完全不变，例如增缓冲会改变原网负载，原支路时序也可能随之变化，必须对照检查。

## Post-mask ECO 不能沿用任意换单元的假设 {#post-mask}

**Pre-mask** 是掩膜冻结前的变更，仍受摆放、供电、保留区域和项目流程约束，但经许可可以新增标准单元及调整走线。**Post-mask** 必须读取已经冻结的层和批准修改的掩膜清单。若仅允许改部分金属和过孔，通常先找已经摆好、接好电源的备用单元，或使用工艺与项目准许的可编程资源，再判断其端口能否在许可层连接。一个备用单元“靠得近”不代表端口一定可达；若需要改冻结层，就不能执行该分支。

例如下文的做法需要在空白合法位点新放一枚延迟单元，因此只用于 Pre-mask。若收到的是仅改上层金属的任务书，就要重制 ECO 方案，检查备用单元的逻辑、供电、连接层、掩膜差异以及相同的时序和物理验收。不能把 Pre-mask 的结果直接标记成 Post-mask 通过。

## 判断只有哪一个分支需要加延迟 {#lab-input}
合成基线 `E10` 内，`u_launch/Q` 经 `n_data` 同时驱动 `u_fast/D` 和 `u_peer/D`。在最小延迟视图 `V_MIN`，只有 `u_fast` 的 hold 失败，`u_peer` 仍为正裕量；最大延迟视图 `V_MAX` 下，两条路径 setup 都为正。假设已核实所有时钟和约束，报告表明 `u_fast` 的分支数据延迟偏短，不是时钟漏约束或路径误分组。项目批准只在 `u_fast/D` 分支加非反相延迟，不能动 `u_peer/D` 的逻辑连接。

```text
合成基线 E10 / slack ps / 同一组约束
path                            hold V_MIN      setup V_MAX
u_launch/Q -> u_fast/D                 -20               70
u_launch/Q -> u_peer/D                  32               65
connectivity: n_data -> {u_fast/D, u_peer/D}
allowed region: PD_CORE / SITE_21 (vacant), mask state: PRE
```

先复核失败路径的发射、捕获引脚及模式，尤其不要把 `-20 ps` 当作全设计都需要加 20 ps 的证据。若用换驱动大小或整网插入，未选分支也被改变，且可能把 hold 问题换成 setup 问题；本例因此选择只切分目标分支。

## 执行变更：核对分支、位点和走线 {#lab-change}
按本机版本帮助设置工作模式并执行针对目标引脚的插入。新单元 `u_eco_dly` 输入保留在 `n_data`，输出由新网 `n_data_fast` 只连接 `u_fast/D`，`u_peer/D` 仍留在 `n_data`。确认该非反相型号在约定角落可用，再按项目流程把它摆在 `PD_CORE` 的合法位点 `SITE_21`；做增量布线并保存逻辑、摆放和布线差异。即使某一步不报警，也应核对目标引脚图，防止命令匹配了整网或错误层级。

在归档差异中，原网不需要保留到 `u_fast/D` 的旧连线；新网也不应接到 `u_peer/D`。确认新增单元供电、无邻居越界且走线变化在批准区域。再重新提取寄生参数，以相同约束和多角视图做时序比较，不能直接用布线前的估算替代验收。

## 对比签核结果，决定合入还是回退 {#lab-verify}
```text
合成复核 E10 -> E11                              基线       改后
u_fast/D hold V_MIN / setup V_MAX (ps)            -20/70      +5/39
u_peer/D hold V_MIN / setup V_MAX (ps)            +32/65     +30/63
目标外新增负裕量端点                               0           0
物理连接 / 新增 DRC                               正常/0      正常/0
功能保持等价比较                                   参考         通过
批准范围外的实例/网络逻辑差异                      0           0
```

结果符合本例设定的目标 hold 至少 `+5 ps`，两条路径 setup 仍为正，`u_peer` 的时序变化也已记录。还须核查所有约定模式角落、最大转换时间和电容等适用约束，并按项目签核要求执行 DRC、连通性及 LVS。功能保持类 ECO 用前后形式等价比较；若有意改功能，则应以获批的新逻辑为参考。Post-mask 另比对物理数据的层差异，而不只核对网表。签核概览见 [ECO 课程](/lesson/03-11-eco/)。

- 改动前锁定 `E10` 数据库、网表、寄生、约束和基线报告，登记获批范围。
- 改动后保留操作记录、新旧连接、图层差异和同口径报告；若任何验收门槛失败，隔离候选，不交付混合版本。
- 回退时从 `E10` 恢复关联产物，确认无残留 `u_eco_dly` 或 `n_data_fast`，复算原有分支连接和 hold 状态，再择案处理。

## 从失败的验收项反推该查哪一步 {#failure-triage}
如果 `u_fast` 的 hold 达标却出现 setup 负裕量，先核查提取后的单元和走线延迟各贡献多少，再判断是否有符合批准范围的较小延迟候选，不能在失败方案上再随手改一项让表面数字转正。如果 `u_peer` 的连线没变却有时序恶化，应查原网新增负载及其寄生变化；若 `u_peer` 真的被接到新网，则是逻辑选择错误，先恢复基线并纠正插入目标，不应靠摆放或布线掩盖。

如果物理检查通过但功能等价失败，先确认参考网表版本与设计意图，再看新增单元极性及连接变化；功能保持场景不得仅凭“单元不反相”就假定等价。若时序和功能都通过、但新布线越过批准边界，仍不能交付。批准范围和时序门槛是独立条件，不是可互相抵消的分数。回退复核时按同一套视图和快照标识比对，避免恢复了布局却仍引用候选版寄生文件。若恢复之后基线数字与原记录不一致，先排查分析输入版本，不能把差异当成这次修改的收益。

## 一条 hold 路径修好了就能交付吗 {#review}
:::quiz
在 n_data 上对整网加延迟为什么不符合本例授权？| 可能同时改变 u_peer 的逻辑连接；本例只批准切分 u_fast 分支，仍需复查 u_peer 的时序。
哪里有空白合法位置，就能在 Post-mask 加一枚单元吗？| 不能；新增单元可能涉及冻结层，需核对允许层清单和可达的已授权资源。
目标 hold 从 -20 ps 变成 +5 ps，可以直接交付吗？| 不可只凭单项交付；还要根据验收清单核查全视图时序、电气、连接、物理与功能证据。
:::

## 名义上已回退，实际吃的是哪一版 {#eco-rollback-manifest}
独立桌面题。候选 `R1` 因改线越过批准边界被拒绝；实现人员恢复 `R0`，签核工作区却只更新了数据库和网表引用。下表记的是分析实际打开的工件，不是文件名推断；短标识只是教学版号，不是真实校验值。网名和连接未变，故两版的回标覆盖都可以是 `48/48`。

| 工件 | `R0` 归档应有 | 工作区实际读取 | 比对 |
|---|---|---|---|
| 版图数据库 | `db-0` | `db-0` | 一致 |
| 逻辑网表 | `nl-0` | `nl-0` | 一致 |
| 慢角 `RCmax` SPEF | `max-0` | `max-0` | 一致 |
| 快角 `RCmin` SPEF | `min-0` | `min-1` | 错版，来自 `R1` |
| 分析配置 | `cfg-0` | `cfg-0` | 一致 |

:::lab 验证一次完整回退，而不是再做一笔 ECO
1. 已知 `R0` 的固定端点 Setup 为 `800 − 812 = −12 ps`，Hold 为 `108 − 100 = +8 ps`。工作区 Setup 同样是 `−12 ps`，但 Hold 到达只有 `97 ps`。计算实际 Hold 为 `−3 ps`，比可追溯基线少 `11 ps`。不能把差异归因给 `R0` 版图，也不能用 `48/48` 证明版本一致。
2. 停止发布混版报告，按成组归档把快角有效输入切回 `min-0`，排除缓存和路径别名仍指向 `min-1`；核对所有角的来源指纹，并重新生成报告而非复制旧结论。
3. 恢复后确认 `−12 / +8 ps`、两角覆盖和批准边界的复核均与 `R0` 一致。登记“回退完成，原 Setup 缺口仍待修”，而不是“设计签核通过”。若输入一致而数字仍不同，继续查实际库、约束与分析设置，不签回退单。
:::

交接单分开签两项：实现方核对数据库、网表和物理差异，时序方核对每角实际读取的寄生及报告来源；只交一个目录名不能证明这两项都已恢复。把这张清单用于 [03-13 的验收和回退](/lesson/03-13-mmmc-eco-lab/#lab-acceptance)，再判断另一笔候选是否独立达标。
