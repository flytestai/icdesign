## Die Size：先核对谁提供了什么 {#die-size}

:::note 资料来源
本讲参考钉钉目录第 08 项的主题安排，正文与练习为原创，不转载钉钉原文、图片或项目参数。TAUREN 仅保留为资料中的名词；这里不推断其内部流程，不提供其定制命令。
:::

Die Size 不是把单元面积除以目标利用率就能定下来。先区分哪些是上游硬约束、哪些是暂定值：例如顶层给子模块的占位与长宽比、关联模块的接口边、宏与标准单元面积估算、电源与布线预留。若是整芯片，还要核对封装与芯片边界相关要求。把每项的来源、版本、单位和坐标原点一并记录。输入冲突时，先与约束提供方确认，不要用摆放工具静默覆盖。

## 先对齐 IO Pin，再按层级看 Memory {#pin-and-memory}

先按信号对接方向划分端口边，核对允许层、轨道对齐和组内次序。对于总线，既核对端口名称是否齐全，也核对排列方向和邻接关系，避免与相邻模块反向对接。Memory 则可先按所属层级建组，在 GUI 中分组染色，观察同一子模块的宏与逻辑或端口是否隔得过远，再按真实连接确认是否需要重新分组。颜色只用来识别，不会改变摆放约束。决定宏的朝向时，还要留出电源接入和信号引脚逃逸空间；把宏排得整齐不是验收标准。

## 脚本化：让 Kick-Off Run 能从头重复 {#kickoff-run}

GUI 用来试方案，交付要能从干净的初始数据库复现。把 Die/Core、端口分配和宏位置/朝向放进受版本管理的脚本或输入文件，同时保存上游清单和对照报告。把教学中的 Kick-Off Run 当作一次最小试跑：从固定输入导入、应用 Floorplan 约束并保存检查点，验证设计坐标、端口状态、宏位置和任何未应用的约束。用报告把试跑结果与预期逐项核对，不只检查脚本是否报错。边界、切角和端口清单的基本检查可回看 [Floorplan 实操](/lesson/03-01a-flp-lab/)。

## 练习：GUI 正确，重跑却偏移 {#exercise}

**题目**：GUI 手调时端口位置正确；同样的坐标写进脚本重跑后，一整组端口沿边统一偏移。你会先比对什么？

**参考作答**：先比对两次运行的 Die/Core 边界、坐标原点和单位，再查有无自动吸附或后续脚本覆盖。选总线首尾两个端口，记录预期位置、数据库实际位置及差值；确认原因后修正输入或脚本，并从干净数据库重跑验收，不能只在 GUI 把端口挪回去。
