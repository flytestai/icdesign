## 先把 Memory 总面积算对 {#memory-area}

:::note 这一讲在流程里的位置
**Floorplan 面积核算** · 承接上一讲的"Floorplan 到 Place"。上一讲说要检查"摆不摆得下"，本讲回答"怎么算才准"。面积账算错，后面所有密度和利用率判断都是错的。
:::


:::fig innovus-practice-c.svg | 原创教学示意图 · Memory 面积不能直接当作占用率
:::

:::note 资料来源
本讲参考钉钉目录第 07 项的主题安排，讲解与数值均为原创教学示例，不是钉钉原文、截图或项目参数的转载。
:::

用物理库中宏的外形尺寸，按**实例**统计，而不是按宏类型计一次。四个 100 × 80 µm 的 Memory 和两个 120 × 100 µm 的 Memory，面积分别为 32,000 和 24,000 µm²，总计 56,000 µm²。旋转不改面积，但会改变横纵向占地与周边摆放行，影响后续通道判断。库尺寸若以微米给出而数据库坐标以数据库单位记录，须先转换再相乘，别把单位错误扩成平方倍数。

准备清单时用实例完整层级名核对漏项和重复导出。多个实例共享同一个宏定义是正常的；同一实例因报告分类被列了两次才是重复。Memory 体面积不含外围留白、硬禁放区或其他宏，不要把按每块宏导出的「宏加留白面积」直接跟体面积相加。

## 评估 Floorplan：分母是可摆放面积 {#floorplan-budget}

本例 Core 为 200,000 µm²，宏及禁放等占区交集去重后共 70,000 µm²，因此简化的可摆面积为 130,000 µm²。若标准单元面积为 78,000 µm²，按可摆面积计算的利用率是 60%；以整个 Core 代替分母只得 39%。两者不是一项指标，交接时写清采用哪一个，以免误判还剩多少余量。

取面积时应把对象裁在 Core 范围内，再求并集；某禁放区若覆盖了部分留白，只扣一次。对实际有站点限制的项目，还要用剩余摆放行或可用站点核对结果。几何面积可能看似足够，若被宏和禁放区切成许多短行，较宽的单元仍无合法位置。部分禁放通常约束区域容量，不能直接按硬禁放整块扣除；采用工具口径时应核对其定义。

```text
教学面积账（um^2）
Core                                          200000
Memory：4 × 8000 + 2 × 12000                  56000
外围留白原始面积                                9000
硬禁放原始面积                                  7000
外围留白与硬禁放的交叠                          2000
不可放并集：56000 + 9000 + 7000 - 2000          70000
可摆放面积                                      130000
标准单元面积                                     78000
口径：留白面积已排除宏体；硬禁放不与宏体相交。
```

## 读 Place 报告：总量和位置缺一不可 {#placement-reports}

第一遍先核对检查点、阶段和统计范围，总面积是否包含物理专用单元，网格尺寸与局部密度分母如何定义。第二遍查未摆实例、重叠、非法站点及摆放行对齐。第三遍把高密区域叠到宏边、阻挡和拥塞图；不要在不同网格大小或不同图例阈值之间直接比较颜色。基础概念可回看 [Place](/lesson/03-07-place/)。

小窗可能仅余少量可用行，少数单元即可把比例推高。反过来，靠近宏引脚的区域即使没有摆多少单元，也可能因为轨道被占、引脚密集而难布线。因此高密要同时给出可用面积、实际占用面积、受影响网络及布线资源；单纯调低颜色上限很容易遮掉需要追踪的问题。

## 面积三项账对不上：先定差在哪个集合 {#practice-step-04}
面积账最好分成三层：从库和网表得到原始实例账；从几何数据库得到 Core 内的占据并集；从摆放行得到实际可用站点。库或网表一更新就重算第一层，宏位置变化则重算后两层。两个方案如果只是硬禁放区平移，原始对象面积不变，但禁放与留白的交叠可能改变，因此实际可摆面积仍要重算。

遇到工具数字与手算差异，先核对数据是否来自同一检查点，再挑一个边角面积小、对象清楚的窗口逐项对账。检查是 Core 边沿裁切、硬禁放与留白重叠，还是连续宽度不足以凑满合法站点。若报告包含填充、边界或其他物理专用单元，给它们单独记账，并说明流转到下一阶段时会不会增减。不要为了让两张表相等，把解释不了的差直接加进留白。

对本例可做一个反算：若不去掉 2,000 µm² 的交叠，就会把分母从 130,000 错算为 128,000 µm²，得到接近 60.94% 的利用率。误差看似不到一个百分点，却会把相交处的可用资源性质说错；更大的方案比较中，同样的错法还可能改变两个候选方案的排序。

## 三个观察窗怎么放到同一套网格上比 {#practice-step-05}
使用合成数据，不需 Innovus。假定问题窗 A 在两块 Memory 间的通道边缘，邻窗 B 有连续摆放行，观察窗 C 靠近宏引脚且受供电占轨影响。A 的可用面积 800 µm²，已占 720 µm²，所以局部密度 90%。全局先按面积汇总再计算，不能对三个窗的百分比取平均；这三个窗也不是整块设计。

```text
合成网格示意（不按比例；只标调查对象）
+-------------+---------+-------------+
|   Memory 1  | 窗口 A  |   Memory 2  |
|      引脚 ->|         |<- 引脚 C    |
+-------------+---------+-------------+
|             窗口 B：连续摆放行       |
+--------------------------------------+
```

以网格编号和边界坐标把密度表与拥塞表对齐，分别记面积和目标层、方向上的溢出轨道数。面积按单元与窗的相交部分统计，跨窗单元不把整块面积记给两个窗。对 A 检查它不是宏体占据了多数面积后的纯分母效应；对 C 不因密度低而跳过，转查引脚接入与该层可用轨道。

## 面积预算不变，把单元从热窗挪到连续行 {#practice-step-06}
从同一基线分支只调整 A 附近一组实例的摆放引导，把可移的 120 µm² 单元挪向 B 的连续行。不改变宏位置、硬禁放或总标准单元面积；重新合法化和估算布线。这里的动作是操作设计，不是可直接执行的 Innovus 命令。检查是否有实例越过区域限制，并确认所追踪网络没有被挪成另一条长绕路。

```text
合成对比                    基线                 调整后
A 占用/可用 (um^2)          720/800 = 90%        600/800 = 75%
B 占用/可用 (um^2)          700/1400 = 50%       820/1400 ≈ 58.6%
C 占用/可用 (um^2)          300/1000 = 30%       300/1000 = 30%
A / B / C 溢出轨道数         6 / 0 / 4            1 / 0 / 4
未摆放 / 重叠实例数          0 / 0                0 / 0
全局估算利用率                60%                  60%
```

搬移在 A 和 B 之间守恒：A 少了 120，B 多了 120，全局利用率不变；A 溢出下降而 B 未新增溢出，支持 A 存在局部摆放压力。A 仍有一条轨道溢出，C 完全未改善，所以本轮不是布线通过；尤其 C 应检查宏侧接入和供电资源，而非继续压低标准单元密度。若项目要合入此分支，还须回查实际关注路径的时序和其他窗口，而不能只凭此表定案。

## 改善还是搬家：看相邻窗口有没有跟着溢出 {#practice-step-07}
- A 改善但 B 或邻窗开始溢出：判为热点搬家，恢复基线，缩小搬移范围或改变候选区域后重试。
- 面积合计不守恒且没有明确增删单元：先查相交面积统计和检查点，不用这份对照作决策。
- 出现非法摆放、关键路径明显退化或影响区域超出预期：保留试验报告，回到基线，而不是事后补开例外。
- 交接保留宏实例账、面积算法和单位、检查点编号、带边界的网格清单、同口径密度与拥塞结果。

## 全局利用率 60%、局部密度 90% 哪个算问题 {#exercise}
以全局 78,000 ÷ 130,000 和 A 窗 720 ÷ 800 为例，先写出全局利用率与局部密度，再指出哪个数字能证明已有布线拥塞。两个比例的分母不同；窄通道、站点碎片或宏边接入的问题，都需要另一份位置明确的布线资源报告来区分。

:::quiz
只按两种 Memory 宏各算一次为什么不对？| 宏类型不是实例；本例要计入四个小宏和两个大宏，合计 56,000 µm²。
A 窗 90% 与全局 60% 能同时成立吗？| 能，A 只统计其局部可用面积，整个设计用全局占用面积除以全局可用面积。
C 窗密度仅 30% 却仍有溢出，应先查什么？| 查目标层和方向的可用轨道、供电占用及宏脚接入，不仅查附近标准单元数量。
:::

## "还有面积"为什么放不下：站点碎片与容量上限 {#deep-lab-region-cap-denominator}
**模拟区域容量报告（面积均为 µm²）。** 交接方要给后续一批面积为 24 的单元预留位置，区域 A、B 均允许这批单元进入。本题单元面积可以直接按站点面积记账，且两窗站点连续、没有跨窗单元。A 的专项约束是“最多使用合法站点面积的 75%”；B 不限容。下面的站点容量已经扣除了几何可放区内无法形成完整站点的碎片。

```text
模拟区域   窗口面积   几何可放   合法站点   已占用   允许比例
A          800        600        480        342      75%
B          800        620        520        342      100%
```

**先独立交付。** 为 A 分别计算窗口占比、物理站点占比和限容使用率，写清三个分母各回答什么。算出两窗还可接纳的面积，为这批单元选择一个窗口；给出拒绝另一个窗口的数量依据，不凭两窗相同的已占面积作决定。

**标准判断。** A 的三个比例分别为 `342/800=42.75%`、`342/480=71.25%` 和 `342/360=95%`。它物理上尚有 138 的站点，但可分配的只剩 18；新增后会占 366，超限 6。B 尚余 178，新增后占 366，小于 520。这批应预留在 B；不能把 A 的允许比例乘到整个窗口或几何可放面积上，也不能把 A 的 95% 写成物理站点利用率。

**验收与回退。** 在候选布局完成合法化后，按同一窗口、站点规则和限容配置复导容量表，核对 B 新增恰是这批实例、A 原占用未被挤动，并检查区域约束和相邻窗。实际若找不到连续合法站点，或发生跨区迁移，撤销预留分配，回到原检查点；先更正站点清单，再选窗口。
