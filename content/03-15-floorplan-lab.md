## 题目：六个数字定一个 die {#problem}

:::goal 学完这一课，你能拿到"单元数 + 宏单元清单 + 引脚数"这三样输入，独立交出一页纸的 floorplan 方案：die 尺寸、通道宽度、电源走廊、引脚排布，每个数字后面都写着它的假设。
:::

《Floorplan：先定房子的格局》讲的是"三个决定"和公式。这一课不讲新概念，只做一件事：**把公式套到一个具体设计上，从头算到尾，并且承认中间要做取舍。**

现实里的 floorplan 不是"套公式得答案"，是"套公式得到三个互相矛盾的答案，然后选一个能交代过去的"。这一课就把这个选择过程摊开。

题目如下，三样输入：

| 输入 | 数值 | 备注 |
|---|---|---|
| 标准单元数 | 12,000 个 | 综合后、未插 buffer |
| 单元平均高度 | 8 track | 库的行高，不是单元高度 |
| 宏单元 | 6 个 SRAM，每个 200µm × 400µm | 引脚在短边，每颗 150 个信号脚 |
| 封装引脚 | 320 个 | 含电源地 60 个，信号 260 个 |
| 目标利用率 | 0.65 | **口径待定**，这是本题第一个坑 |

:::scene 周五要交方案，周一还在算面积
周一早上，leader 把这三样输入发给你，说："周五评审，交一页纸：die 多大、通道多宽、电源怎么走、pin 怎么排。每个数字我要能问出依据。"

你打开 Excel，先算了 `25200 ÷ 0.65`，得到 197µm，心想这芯片真小。然后你看了眼宏单元清单——一颗 SRAM 就是 200×400。**一颗 SRAM 比整个 die 还大。**

你把这一版删掉，重新想：这个 0.65 到底是谁的 0.65？
:::

:::term Pad-Limited | 焊盘受限
芯片尺寸不是由内部逻辑决定的，而是由"边上要放多少引脚"决定的。

判断方法：把需要的引脚数 × 引脚间距，和 die 周长比。前者大于后者，就是焊盘受限——这时候加大 die 不是为了放逻辑，是为了放引脚。
:::

:::term Core-Limited | 核心受限
芯片尺寸由内部单元和宏单元的面积决定，引脚在周长上放得下还有富余。

多数中小规模设计是核心受限；引脚多、逻辑少的接口芯片（比如 SerDes、DDR PHY）常是焊盘受限。
:::

## 第一步：把 12000 个单元变成一个面积 {#step1}

面积算错，后面全错。这一步看起来只是乘法，但有两个地方会错。

### "8 track 高"到底多高

标准单元只能摆在"行"（row）上，行的高度由库决定，而库的高度用 track（轨道）数表示。track 是布线网格的最小间距，40nm 工艺的 M2 track 间距约 0.14µm（典型值，具体查 tech LEF）。

```
行高 = track 数 × track 间距 = 8 × 0.14 = 1.12 µm
```

这里的 8 track 是**行高**，不是单元高度。所有标准单元的高度都等于行高（或者是它的整数倍，叫 multi-height cell），宽度则各不相同。

### 平均单元面积

综合报告不会直接给你"平均单元面积"，要自己估。两种估法：

1. **用总面积反推**：`report_area` 给出总面积，除以单元数。
2. **用宽度估**：平均宽度 × 行高。40nm 下平均单元宽度约 1.9µm（约 10 个 site，典型值）。

第二种更适合早期估算（还没有布局的时候）：

```
平均单元面积 = 1.9 × 1.12 ≈ 2.1 µm²
标准单元总面积 = 12000 × 2.1 = 25,200 µm²
```

这个 25,200 后面要用三次（算 die、算条带高度、算利用率），写下来，别每次重算。

### 宏单元面积

```
单个 SRAM = 200 × 400 = 80,000 µm²
6 个      = 480,000 µm²
```

现在把两个数并排放：

| 项目 | 面积 | 占比 |
|---|---|---|
| 标准单元 | 25,200µm² | 5.0% |
| 宏单元 | 480,000µm² | 95.0% |
| 合计 | 505,200µm² | 100% |

:::term Macro Ratio | 宏单元占比
宏单元总面积 ÷（宏单元 + 标准单元）总面积。

它决定这个设计"像什么"：占比低于 20%，floorplan 主要考虑标准单元的 row 和通道；占比高于 50%，**宏单元的排布形状就成了 die 尺寸的主约束**，利用率公式退居次要。
:::

这个 95% 就是本题的第一个转折点。**宏单元是标准单元的 19 倍**，意味着这颗芯片的形状基本由 6 个 SRAM 怎么摆决定，12,000 个单元只是"填空"。

先把这个结论记住，下一步会用到。

## 第二步：die 尺寸，先算一个荒谬的答案 {#step2}

按基础课的公式，第一步永远是：

```
core 面积 = 标准单元总面积 ÷ 目标利用率
```

代进去：

```
core = 25,200 ÷ 0.65 = 38,769 µm²
边长 = √38,769 = 197 µm
```

197µm 见方。听起来很合理，直到你想起宏单元。

### 现实检查：197µm 放不下一颗 SRAM

一颗 SRAM 是 200 × 400µm。197µm 的 core，**宽度比 SRAM 的短边还窄 3µm**。

所以这个 0.65 一定不是"标准单元 ÷ core 面积"。它只能是下面两种之一：

- **口径 A**：标准单元 ÷（core 面积 − 宏单元面积），也就是"可用区利用率"，基础课里说的工具口径。
- **口径 B**：全部单元面积（含宏）÷ core 面积，也就是"总面积利用率"。

用口径 A 重算：

```
core = 25,200 ÷ 0.65 + 480,000 = 38,769 + 480,000 = 518,769 µm²
边长 = √518,769 = 720 µm
```

720µm 见方，理论上装得下 6 个 SRAM。**但"理论上"要接受几何检查。**

### 几何检查：6 个 SRAM 怎么排

SRAM 是 200 × 400。想让 6 个排得整齐，只有两种摆法：

| 摆法 | 占地（含通道） | 问题 |
|---|---|---|
| 3 列 × 2 行，不旋转（200 宽 × 400 高） | 660 宽 × 830 高 | 高度 830 > 720，放不下 |
| 2 列 × 3 行，旋转（400 宽 × 200 高） | 870 宽 × 680 高 | 宽度 870 > 720，放不下 |

两种都塞不进 720 见方。这就是"面积够、形状不够"——**面积公式给的是下限，不是答案。**

所以真正决定 core 宽度的是宏块：按 2 列 × 3 行旋转摆，宽度至少 `2×400 + 1 条通道`。通道宽度下一步算，先按 70µm 估：

```text
# 示意图：core 的最终分区（比例不准确，只表示结构）
┌──────────────────────────────────────────┐
│  ┌─────────┐  70µm   ┌─────────┐         │
│  │ SRAM 0  │◀───────▶│ SRAM 1  │  400×200 │
│  └─────────┘         └─────────┘         │
│        40µm 横通道（电源）                 │
│  ┌─────────┐         ┌─────────┐         │
│  │ SRAM 2  │         │ SRAM 3  │         │
│  └─────────┘         └─────────┘         │
│        40µm 横通道（电源）                 │
│  ┌─────────┐         ┌─────────┐         │
│  │ SRAM 4  │         │ SRAM 5  │         │
│  └─────────┘         └─────────┘         │
│        40µm 通道                          │
│  标准单元条带 870 × 45（12,000 个单元）    │
└──────────────────────────────────────────┘
        core = 870 × 765
```

算 core 的高度：

```
宏块高度 = 3 × 200 + 2 × 40 = 680 µm
标准单元条带高度 = 38,769 ÷ 870 = 44.6 → 45 µm
core 高度 = 680 + 40 + 45 = 765 µm
core = 870 × 765 = 665,550 µm²
```

### 回算一遍利用率，验证没算错

标准单元条带是 870 × 45 = 39,150µm²，装 25,200µm² 的单元：

```
条带内利用率 = 25,200 ÷ 39,150 = 64.4%   ← 就是目标 0.65
```

对上了。但工具会报另一个数：

```
工具口径 = 25,200 ÷ (665,550 − 480,000) = 25,200 ÷ 185,550 = 13.6%
```

13.6% 和 64.4% 差了五倍。原因很简单：185,550 里包含了宏块内部的通道、宏块与条带之间的通道——这些地工具算作"可放单元"，实际放不了。

**评审时一定会被问这个数。** 正确答法不是"利用率 13.6%"，而是："宏块占 core 的 72%，标准单元集中在底部 45µm 的条带里，条带内利用率 64%，工具报的 13.6% 是含通道的口径，没有参考意义。"

:::pitfall 用工具口径报利用率，被追问"那为什么这么低"
现象：你报"利用率 13.6%，很松"，组长问"那为什么布线还是紧"，你答不上来。

原因：13.6% 的分母包含了宏块内部通道，而那些通道根本不能放单元。真实密度在底部条带里，是 64%。

怎么避免：报数时永远带两个数——"整体口径"和"标准单元区口径"。宏单元占比超过 50% 的设计，只看前者会严重低估密度。
:::

顺带把 die 记下来：core 870 × 765，按常规四边各 20µm 边距，die 是 910 × 805，周长 3430µm。先记这个数，下一步它会出问题。

## 第三步：通道与电源走廊 {#step3}

通道宽度基础课给过公式，这里直接代。区别在于：本题的 SRAM 引脚在**短边**（200µm 那条），旋转之后短边变成竖直的，所以引脚朝左右，**信号通道是两列之间的那一条竖通道**——两侧的 SRAM 都朝它出线。

### 信号通道：70µm 怎么来的

```
出线总数 = 两侧引脚数 × 每脚出线数
        = 2 × 150 × 2 = 600 根
单层线数 = 600 ÷ 4 层 = 150 根
信号宽度 = 150 × 0.28（pitch）× 1.3（余量）= 54.6 µm
电源走廊 = 10 µm（下一步算）
通道总宽 = 54.6 + 10 = 64.6 → 取 70 µm
```

向上取到 70 而不是 64.6，有两个原因：布线网格对齐（取 5µm 的整数倍），以及给后期 ECO 留一点空间。

横向那两条通道（40µm）不承担 SRAM 引脚出线，只走电源和少量穿越信号：

```
电源走廊 10µm + 两侧各 15µm 给穿越信号 = 40 µm
```

### 电源走廊：从电流算宽度

基础课讲了电源的三层结构（ring / stripe / rail），这里只算"走廊要多宽"。

先算总电流：

```
标准单元：12000 × 3µA = 36 mA（3µA/单元是 40nm 500MHz 的量级估计）
SRAM：    6 × 8mA = 48 mA
合计：    84 mA → 按 90 mA 设计，留 7% 余量
```

再算需要几条 stripe。M5 竖条，间距 30µm，core 宽 870µm：

```
条数 = 870 ÷ 30 ≈ 29 条
每条电流 = 90 ÷ 29 = 3.1 mA
```

按 EM 规则反推宽度。40nm 厚金属的电流密度上限约 2mA/µm（典型值，查工艺 EM 规则）：

```
最小宽度 = 3.1 ÷ 2 = 1.55 µm → 取 2 µm（工艺最小宽度通常也在这附近）
```

走廊宽度要把 stripe、间距、通孔包边都算进去：

```
走廊 = 2（线宽）+ 2×1.5（两侧间距）+ 2×1（via 包边）= 7 µm → 取 10 µm
```

10µm 的走廊在 40µm 的横向通道里占四分之一，这就是为什么横向通道不能按 20µm 给——**电源先占，剩下的才是信号的。**

顺手做一个压降量级检查：一条 2µm 宽、350µm 长的 M5，方块电阻按 0.05Ω/□ 算：

```
方块数 = 350 ÷ 2 = 175
电阻 = 175 × 0.05 = 8.75 Ω
单条压降 = 8.75 × 3.1mA = 27 mV
```

27mV 是标称 1.0V 的 2.7%，单条看有点紧。但 29 条并联、加上 M6 横向网格，实际局部压降会明显低于这个数。**这一步只做量级判断，最终以 IR 分析工具为准**——课程环境跑不了 IR 分析，真实项目里你会看到一张按颜色分级的压降图。

:::pitfall 先摆宏单元，再想电源
现象：宏块排完、通道留了 70µm，画电源 stripe 时发现竖条正好压在 SRAM 的电源引脚上，或者横条要穿过一条 40µm 的通道但走廊只有 10µm。

原因：宏单元的电源引脚位置是固定写在 LEF 里的，stripe 必须对齐它。先摆后画，等于让电源去适应既成事实。

怎么避免：先定 stripe 的间距和起点，再摆宏单元，让每列 SRAM 的电源脚落在同一条竖条上。本题 2 列 SRAM，两条主竖条正好对齐两列的中心。
:::

## 引脚：320 个脚放不下的时候 {#pins}

这是本题第二个转折点，也是最容易被跳过的一步。

### 先算周长够不够

```
die 周长 = 2 × (960 + 855) ≈ 3630 µm
需要的边长 = 320 个 × 20µm（pitch）= 6400 µm
```

6400 > 3630，**现有的边只够 57%，缺 43%。**

如果按最初的 20µm 边距（die 910 × 805，周长 3430），差得更多。这就是 **pad-limited（焊盘受限）**：die 尺寸被引脚数顶住了。

三条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| 双排交错焊盘 | 内外两排错开半个 pitch，等效 pitch 10µm | 边距从 20µm 加到 45µm，die 变大 |
| 加大 die | 边长加到 1600µm 才够单排 | 面积翻 2.5 倍，荒谬 |
| flip-chip | 凸点阵列铺在面上，不受周长限制 | 封装成本高，万门级设计不值 |

选第一条。边距从 20µm 加到 45µm：

```
core 870 × 765
die = (870 + 90) × (765 + 90) = 960 × 855
周长 = 3630 µm
双排等效需求 = 320 × 10 = 3200 µm
余量 = (3630 − 3200) ÷ 3630 = 11.8%
```

11.8% 的余量刚好够放电源环的拐角和四个角的空位。**这就是"IO 反过来决定 die 尺寸"的具体样子**——不是逻辑放不下，是脚放不下。

:::term Staggered Pad | 交错焊盘
把焊盘排成内外两排，外排和内排在切线方向错开半个间距。

这样两排焊盘在切线方向上的投影互不重叠，等效间距减半。代价是径向要多占一条焊盘加走线的宽度，边距通常要加 20~25µm。
:::

### 四边怎么分：按信号流向，不按平均

320 个脚平均分到四边是每边 80 个。这是最省事的做法，也是最差的做法。

正确的分法只有一条原则：**引脚靠近它服务的逻辑，总线保持连续。**

本题的分配（假设数据流从左进、从右出）：

| 边 | 放什么 | 数量 | 理由 |
|---|---|---|---|
| 左 | 输入数据总线、参考时钟 | 90 | 数据从左进来，直接进核心 |
| 右 | 输出数据总线、测试口 | 80 | 数据从右出去，走线不交叉 |
| 下 | 配置总线、复位、中断 | 60 | 低速信号，离核心控制区近 |
| 上 | 电源地 + 少量模拟 | 90 | 电源在四边均匀分布，上边补足 |
| 四角 | 电源地 | 含在上面 | 角落放电最稳 |

电源地 60 个要**均匀摊到四边**，不能全挤一边——一侧供电不足，IR drop 会在那一侧集中。所以上表里每边的数字都含了一部分电源脚。

### `editPin` 的四个要素

命令名在不同版本里可能是 `editPin` 或 `create_io_pin`，但四件事永远不变：**哪条边、哪一层、什么顺序、多大间距。**

```tcl
# 作用：把 32 位输入总线按顺序摆到 die 左边，双排交错，间距 10µm
# 用法：floorplan 与电源规划之后执行；pin 名必须与网表端口名完全一致
editPin -pin {din[0] din[1] din[2] din[3] din[4] din[5] din[6] din[7]} \
        -side Left \
        -layer M5 \
        -spreadType range \
        -start {45 300} -end {45 460} \
        -spacing 10
# -side：放哪条边（Left/Right/Top/Bottom）
# -layer：焊盘所在金属层，要和封装打线/凸点匹配
# -spreadType range：在 start 到 end 这一段里均匀铺开（center 是整边居中）
# -start/-end：这一段的两端坐标，用来把总线约束在某个区间
# -spacing：相邻 pin 中心距；双排时给 10，等于单排的 20
```

四个要素里最容易错的是**顺序**。`-pin` 列表的顺序就是物理顺序，写反了（`din[0]` 到 `din[7]` 摆成从下往上还是从上往下）不会报错，但走线会交叉。摆完开飞线看一眼，比看坐标快。

:::pitfall 引脚按平均分，总线被打散
现象：布局后飞线图上一片交叉，32 位数据总线从四个方向进来，在核心区门口拧成一团。

原因：为了"四边数量均衡"，把一组总线拆到了两条边，甚至对角。

怎么避免：先按信号流向分组（一组总线一条边），再看四边数量是否失衡。失衡就调低速信号的位置，**永远不拆总线**。
:::

## 方案表：每个数字都要有假设 {#sheet}

一页纸方案长这样。左列是数字，右列是依据——评审时被问任何一格，都能当场答出来。

| # | 数字 | 值 | 依据 / 假设 |
|---|---|---|---|
| 1 | 标准单元总面积 | 25,200µm² | 12,000 × 2.1µm²（行高 1.12、均宽 1.9） |
| 2 | 宏单元面积 | 480,000µm² | 6 × 200 × 400 |
| 3 | 宏单元占比 | 95% | 480,000 ÷ 505,200，决定形状由宏块主导 |
| 4 | 宏块外形 | 870 × 680 | 2 列 × 3 行（旋转），竖通道 70、横通道 40 |
| 5 | 标准单元条带 | 870 × 45 | 38,769 ÷ 870，条带内利用率 64% |
| 6 | core | 870 × 765 | 宏块 680 + 通道 40 + 条带 45 |
| 7 | die | 960 × 855 | 双排焊盘，四边各 45µm |
| 8 | 长宽比 | 1.12 | 960 ÷ 855，在 1.2 以内 |
| 9 | 竖通道 | 70µm | 600 根 ÷ 4 层 × 0.28 × 1.3 + 电源 10 |
| 10 | 电源走廊 | 10µm | 2µm 线宽 + 两侧 1.5 间距 + 2×1 包边 |
| 11 | 总电流 | 90mA | 单元 36 + SRAM 48，留 7% |
| 12 | 焊盘 | 320 个 / 2 排 | 周长 3630 vs 需求 3200，余量 11.8% |

十二个数字里有三个是"拍的"：平均单元面积 2.1µm²、单元电流 3µA、EM 上限 2mA/µm。这三个都要标"典型值"，并且在方案里写明"以综合报告 / 工艺规则为准"。**拍的数字不可怕，不标注才可怕。**

这张表的用法不是交上去就完了。任何一次参数改动，都要顺带重算受影响的几行：把利用率从 0.65 改成 0.55，动的是条带高度、core 高度、die 高度、焊盘余量这四行；换一颗更大的 SRAM，动的是宏块外形和所有通道，几乎是全表重算。**分清哪些数字会连锁、哪些不会，是这张表最大的价值。** 评审时某个数字被质疑，改一行、重算四行，五分钟就能给出新版本；没有这张表，就要从头再来一遍。

还有一条纪律：表里每个数字只允许有一个来源。同一个面积，不要一处按 25,200、一处按 25,536，差 300µm² 看起来无所谓，传到 die 尺寸上就是半毫米，传到成本上就是几个点。**一个数一个出处，改就全改。**

## 三个利用率方案 {#scenarios}

目标利用率是本题唯一一个"可以商量"的输入。把 0.55 / 0.65 / 0.72 各算一遍。

因为宏块固定 870 × 680，利用率只影响底部条带的高度：

| 利用率 | 需要的条带面积 | 条带高度 | core 高度 | die 高度 | die 面积 |
|---|---|---|---|---|---|
| 0.55 | 45,818µm² | 53µm | 773µm | 863µm | 828,480µm² |
| 0.65 | 38,769µm² | 45µm | 765µm | 855µm | 820,800µm² |
| 0.72 | 35,000µm² | 41µm | 761µm | 851µm | 816,960µm² |

先看最后一列：**0.55 到 0.72，die 面积只差 1.4%。**

这个结果和基础课里"利用率从 0.62 提到 0.72，面积省 12%"完全相反。原因就是宏单元占比 95%——利用率只作用在 5% 的面积上，杠杆几乎没有。

结论很直接：**在这个设计里，省面积这个理由不成立，应该往松了给。**

| 方案 | 好处 | 风险 |
|---|---|---|
| 0.55 | 条带多 8µm（约 7 行），布线和 ECO 都有余量；IR drop 更好 | 多花 0.9% 面积，几乎无成本 |
| 0.65 | 常规值，好交代 | 条带 45µm，40 行，走线密度中等 |
| 0.72 | 条带 41µm，省 0.4% 面积 | 条带内只剩 36 行，局部拥塞概率明显上升；后期 ECO 没地方插单元 |

推荐 0.55~0.60。理由不是"保守"，是**这笔交易的赔率不对**：省 1.4% 面积，换的是布线阶段可能多花两天。

如果评审坚持要 0.72，也不是不能做，但要换来两件事：一是把省下的空间明确记成"无 ECO 余量"，后面所有插 buffer 的动作都要走正式 ECO 流程；二是在电源规划上多给一点，因为条带变矮、单元变密，局部电流密度上升，IR drop 会比 0.55 方案差几个毫伏。**每一个"省"都要在别处标出它的账。**

这也是一条可以带走的判断规则：**宏单元占比超过 50% 的设计，利用率这个旋钮基本失效，决策重心应该转到宏块形状和通道宽度上。**

## 评审看六个数字 {#review}

一页纸交上去，评审不会逐行看。他们只看六个数，每个数对应一个失败模式。

| # | 数字 | 合格判据 | 不合格的后果 |
|---|---|---|---|
| 1 | die 尺寸与长宽比 | 长宽比 ≤1.2，尺寸能被封装接受 | 封装对不上，整版重做 |
| 2 | 宏单元占比 | 与综合报告一致，且说清它对决策的影响 | 面积预算错，后面每步都以为还有空间 |
| 3 | 标准单元区利用率 | 条带内 55%~70%，并说明口径 | 报 13.6% 这种数会被追问到答不上 |
| 4 | 最小通道宽度 | 每条 ≥ 算出来的值，且能当场复现算式 | 布线 70% 卡死，回退两天 |
| 5 | 引脚数 / 排数 / 封装版本 | 数量、边、层、顺序与封装文件一致 | pin 晚到，floorplan 全推翻 |
| 6 | 电源走廊宽度与 stripe 覆盖 | 走廊 ≥ stripe + 间距 + 包边；宏电源脚落在 stripe 上 | IR drop 超标或 stripe 压 pin |

第 3 项和第 5 项是最容易翻车的两个。前者是口径问题（说错一句话，数字全被怀疑），后者是版本问题（用了临时 pin 文件，做得再对也要重来）。

六个数之外还有一项不写在表里、但必须口头说明：**这一版数据库的文件名和日期**。评审记录里只写"floorplan 已评审"没有意义，要写"基于 db/02_floorplan_v3.enc，11 月 20 日"。三个月后有人拿错版本，这一行字能救两天。数字是给人看的，版本是给流程用的，两样都要留。

## 工作中怎么用：方案是要签字的东西 {#in-work}

**谁做**：PR 工程师出方案，宏单元位置和 pin 分配要和封装、模拟、架构三方对齐。

**交付什么**：一页纸（就是上面那张表）+ 一版 floorplan 数据库 + 一份自检输出。三样缺一样，评审就没法签字。

**谁签字**：组长或项目负责人。签字的含义是"这一版的 die 尺寸和宏块位置，后面不再改"——所以签字前必须把六个数字过一遍。

**做错了会怎样**：floorplan 的错误是**乘法级**的。通道少 20µm，布线多两天；die 大 5%，成本涨 5% 且无法回收；pin 方向错，封装要重新打样。这三件事都不可逆。

**一条经验**：方案里所有"典型值"都要写出处（"库手册第几页"或"上个项目实测"）。评审最爱问的就是"这个 2.1µm² 哪来的"——答"我估的"会被打回，答"按行高 1.12 × 均宽 1.9 估的，误差 ±10%"就能过。

:::lab 动手：交一页纸方案
**任务**：用本课给的输入，独立跑一遍计算，产出一页纸方案（十二行表 + 三条风险）。

```bash
# 作用：把本题的十二个数字一次算出来，改参数可以看结果怎么变
# 用法：任意目录 python3 直接跑；输出贴进方案表
python3 - <<'EOF'
import math
cells, cell_area = 12000, 2.1                    # 单元数、平均面积（行高 1.12 × 均宽 1.9，取整）
std = cells * cell_area                          # 标准单元总面积 25,200
mac = 6 * 200 * 400                              # 宏单元总面积 480,000
util = 0.65                                      # 目标利用率（条带口径）

strip_area = std / util                           # 条带需要的面积 38,769
mac_w, mac_h = 2*400 + 70, 3*200 + 2*40           # 宏块外形：2 列 3 行，竖通道 70
strip_h = math.ceil(strip_area / mac_w)           # 条带高度，向上取整到 1µm
core_h = mac_h + 40 + strip_h                     # core 高度
print("std=%.0f mac=%.0f strip=%.0f core=%dx%d" % (std, mac, strip_area, mac_w, core_h))

die_w, die_h = mac_w + 90, core_h + 90            # 双排焊盘，四边各 45
peri = 2 * (die_w + die_h)
print("die=%dx%d peri=%.0f" % (die_w, die_h, peri))
print("pin 需求 %d，余量 %.1f%%" % (320*10, (peri-3200)/peri*100))
print("条带内利用率 %.1f%%" % (std/(mac_w*strip_h)*100))
for u in (0.55, 0.72):                            # 对比另外两个方案
    h = math.ceil(std/u/mac_w)
    print("util %.2f -> 条带 %d, die 高 %d" % (u, h, mac_h+40+h+90))
EOF
```

**预期**：`std=25200 mac=480000 strip=38769 core=870x765`；`die=960x855`；条带内利用率约 `64.4%`；util 0.55 的 die 高约 863，0.72 约 851。

**步骤**：
1. 跑上面的脚本，把输出和自己的手算对一遍（差在 300µm² 以内算对）。
2. 把十二个数字填进方案表，每个数字右边写依据。
3. 写三条风险：最可能返工的是哪一项、触发条件是什么、代价多大。
4. 把长宽比、通道宽度、pin 余量三个数圈出来，这是评审必问的。

**过关标准**：能回答四个追问——为什么 die 是 960 而不是 910（差的是双排焊盘）；为什么条带内是 64% 而工具报 13.6%（口径）；为什么 6 个 SRAM 必须旋转（不旋转高度 830 放不进 765）；为什么利用率从 0.65 放到 0.55 只多花 0.9%（宏单元占 95%，杠杆失效）。
