## 为什么是 tcsh {#why}

你可能会问：Linux 默认不是 bash 吗，为什么还要学 tcsh？

因为历史。EDA 工具在 1990 年代定型，那会儿主流是 csh/tcsh，于是所有公司的环境脚本、流程脚本都写成了 tcsh，一直沿用到现在。你今天进公司，看到的 `setup.csh`、`run.csh` 基本都是 tcsh。

现实一点说：**你可以用 bash 干活，但你读不懂 tcsh 脚本，就看不懂公司的流程。**

:::term Tcsh | 增强版 C Shell
csh 的改进版，语法接近 C 语言。特点是变量分两类（shell 变量和环境变量），用 `set` 和 `setenv` 分别设置。提示符常见 `%` 或 `>`。

查看当前 shell：`echo $SHELL`；临时切进 tcsh：直接敲 `tcsh`，退出用 `exit`。
:::

## 变量分两种，这是 tcsh 最容易搞混的地方 {#vars}

| 类型 | 设置命令 | 读取方式 | 能否传给子进程 |
|---|---|---|---|
| shell 变量（本地） | `set x = 1` | `$x` | ❌ 不能 |
| 环境变量 | `setenv X 1` | `$X` | ✅ 能 |

```csh
set n = 10                # 定义本地变量 n，等号两边可以有空格
echo $n                   # 10

setenv PROJECT ipa        # 定义环境变量
echo $PROJECT             # ipa

set path = ( /usr/bin /bin $HOME/bin )   # path 是 tcsh 的特殊数组变量
# 注意：tcsh 里 PATH 用小写 path，是数组不是冒号字符串
```

:::pitfall tcsh 的 path 是数组，不是冒号串
bash：

```bash
export PATH=/a:/b:$PATH        # 冒号分隔的字符串
```

tcsh：

```csh
set path = ( /a /b $path )     # 空格分隔的数组，小写
```

在 tcsh 里写 `export PATH=...` 会直接报错；写 `setenv PATH /a:/b` 虽然不报错，但很多工具读的是 `path` 数组，行为会不一致。**记住：tcsh 加路径用 `set path = ( 新目录 $path )`。**
:::

## 别名：把长命令变短 {#alias}

```csh
alias ll 'ls -lht'
alias la 'ls -la'
alias .. 'cd ..'
alias grep 'grep --color=auto'

# 看所有别名
alias

# 取消
unalias ll
```

常驻要写进 `~/.cshrc`。老工程师的 `.cshrc` 里通常有十几个别名，那是十几年攒下来的效率。

:::term Alias | 别名
给一条（或一串）命令起个短名字。敲 `ll` 等于敲 `ls -lht`。

别名只在当前 shell 有效，所以写在 `.cshrc` 里才会每次登录都有。
:::

## 通配符与命令历史 {#glob}

```csh
ls *.tcl              # * 匹配任意多个字符
ls run?.log           # ? 匹配单个字符
ls run[1-9].log       # [] 匹配范围内一个字符
ls {a,b,c}.tcl        # {} 展开成 a.tcl b.tcl c.tcl，csh 特有，很好用

!!                    # 重复上一条命令
!$                    # 上一条命令的最后一个参数
!*                    # 上一条命令的所有参数
history               # 看历史命令列表
```

:::tip `!$` 是省时间的神器
```csh
ls /home/autumn/backend_lab/ipa_soc/pnr
# 输出一堆文件
cd !$                 # 等价于 cd /home/autumn/.../pnr
```

长路径只敲一次，后面用 `!$` 复用。
:::

## 控制流：if 和 foreach {#flow}

```csh
# if：注意 then 和 endif 都是独立一行
if ( -f run.tcl ) then
    echo "found run.tcl"
else
    echo "no run.tcl"
endif

if ( $n > 5 ) then
    echo "big"
endif

# foreach：遍历一组值，end 结束
foreach f ( *.tcl )
    echo "processing $f"
end

# 遍历数字：csh 没有 range，用 seq 生成
foreach i ( `seq 1 5` )
    echo "round $i"
end
```

判定条件常用写法：

| 写法 | 含义 |
|---|---|
| `-f file` | 是普通文件 |
| `-d dir` | 是目录 |
| `-e path` | 存在（不管类型） |
| `-z "$str"` | 字符串为空 |
| `$a == $b` | 数值相等 |
| `"$a" == "$b"` | 字符串相等（加引号） |

:::pitfall tcsh 与 bash 的五个致命差异
| 场景 | bash | tcsh |
|---|---|---|
| 设环境变量 | `export A=1` | `setenv A 1` |
| 设本地变量 | `A=1` | `set A = 1` |
| if 语句 | `if [ ... ]; then` | `if ( ... ) then` |
| 循环 | `for x in ...; do` | `foreach x ( ... )` |
| 脚本第一行 | `#!/bin/bash` | `#!/bin/tcsh -f` |

还有一条最坑的：**tcsh 的 `set` 不给等号右边加引号时，空格会被当成语法**。`set msg = hello world` 会报错，必须 `set msg = "hello world"`。
:::

:::lab 动手：写第一个 tcsh 脚本
```csh
# 建文件 hello.csh
cat > hello.csh <<'EOF'
#!/bin/tcsh -f
# -f 表示不读 .cshrc，脚本跑得更快、更可复现（重要！）

set who = "backend engineer"
setenv RUN_MODE "test"

echo "hello, $who"
echo "mode = $RUN_MODE"

foreach f ( a b c )
    echo "file: $f"
end
EOF

chmod +x hello.csh
./hello.csh
```

预期输出：

```
hello, backend engineer
mode = test
file: a
file: b
file: c
```

过关标准：把 `foreach` 改成遍历当前目录下所有 `.tcl` 文件；如果目录里没有 tcl 文件，脚本应该打印一句 "no tcl files"（提示：先用 `ls *.tcl >& /dev/null` 判断，`>&` 是 tcsh 的重定向写法）。
:::

:::scene 你会在哪种场合用到这些
- 组长给你一个 `run_all.csh`，让你"改一下 top 名字跑另一版"。你得看懂 `setenv DESIGN xxx` 在哪。
- 你要批量跑 8 组利用率参数，手敲 8 次不如写个 `foreach`。
- 工具的启动脚本报错，你得判断是 `set path` 写错了还是 `setenv` 漏了。

**tcsh 不需要学到能写复杂程序，但要能读懂、能改。**
:::

:::quiz
tcsh 里设置环境变量用什么命令？|`setenv NAME value`（bash 是 `export NAME=value`）。
`#!/bin/tcsh -f` 里的 `-f` 是什么意思？|不读取用户的 `.cshrc`。好处是启动快、结果可复现，不受个人配置影响。
tcsh 里给 PATH 加目录正确写法是什么？|`set path = ( /new/dir $path )`，小写 path，是数组。
`set msg = hello world` 为什么会报错？|因为 tcsh 把空格当分隔符，认为 `world` 是多余参数。要写成 `set msg = "hello world"`。
`!$` 是什么？|上一条命令的最后一个参数，常用于复用长路径。
:::
