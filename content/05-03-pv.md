## 四种检查：交房前的四张验收单 {#four}

:::goal 学完这一课，你能拿到一份 DRC/LVS 报告，说清每条违例是"哪条规则、在哪个坐标、哪个层、差多少"，并判断它该自己修、该回 PR 修、还是该申请豁免。
:::

把版图交给工厂，类似把装修好的房子交给业主。业主不会只看照片，他会拿四张单子逐项验：

- **墙面平不平**（几何规则）→ DRC
- **水电有没有接错**（连接关系）→ LVS
- **有没有漏电、接地不良**（电气规则）→ ERC
- **施工过程中会不会把东西烧坏**（制造期风险）→ Antenna

四张单子没有一张能省。区别在于：前两张不过，房子直接不能交付；后两张不过，可能住进去三个月才出问题。

:::term DRC | Design Rule Check，设计规则检查
用工厂给的规则文件（rule deck）逐条检查版图的几何图形：线宽够不够、间距够不够、通孔包边够不够、密度均不均匀。它回答的是"这个图形工厂的机器做得出来吗"。
:::

:::term LVS | Layout vs Schematic，版图与原理图一致性
从版图里**反推**出器件和连接关系（这一步叫提取），再和网表（schematic）比对。器件多了少了、线连错了、尺寸不对，都会报出来。它回答的是"造出来的电路是不是我设计的那个电路"。
:::

:::term ERC | Electrical Rule Check，电气规则检查
查那些"几何上合法、电气上危险"的结构：栅极悬空、well 没接电源、衬底接触太远（闩锁风险）、电源和地短路。
:::

:::term Antenna | 天线效应
制造过程中，长金属线像天线一样收集等离子体电荷。如果这条线连着晶体管栅极，电荷无处泄放，会把极薄的栅氧化层击穿。它只在**制造过程中**发生，芯片做完就没事了。
:::

| 检查 | 查什么 | 不过的后果 | 谁修 |
|---|---|---|---|
| DRC | 几何规则（宽/距/包边/密度） | 工厂拒收，或良率崩 | PR / 版图工程师 |
| LVS | 版图与网表的连接一致性 | 芯片功能全错，直接报废 | PR / 版图工程师 |
| ERC | 电气结构（浮空、well 接触、闩锁） | 漏电、闩锁、可靠性差 | 版图工程师 |
| Antenna | 制造期电荷积累 | 栅氧击穿，良率下降 | PR（可自动修） |

## PV 在流程里的位置 {#when}

:::scene 流片前 48 小时，DRC 还有 137 条
周五下午四点，tapeout 定在下周一。你跑完最后一版 Calibre，DRC 从早上的一万两千条降到 137 条，然后卡住了。LVS 是干净的，Antenna 有 9 条。

版图负责人问你："这 137 条能不能 waive？" 你打开报告，第一屏全是 `M2.SPACE.1`，坐标集中在芯片右下角一小片。你不知道该回答"能"还是"不能"——因为你还没看清这 137 条是同一类还是十几类。

这就是 PV 的现实：**大部分时间不是在修，而是在分类和判断。**
:::

PV 不是流程末尾才做的一次性动作。它在每个阶段都要跑：

| 阶段 | 跑什么 | 目的 |
|---|---|---|
| 布局后（有电源网络） | 早期 DRC（只查 metal/via 基本规则） | 及早发现电源网格的间距问题 |
| CTS 后 | 局部 DRC | 时钟网络 NDR 有没有违规 |
| 布线后 | 全量 DRC + Antenna | 第一次接近签核的检查 |
| 修补（ECO）后 | 增量 DRC + LVS | 确认改动没有引入新问题 |
| 流片前 | 全量 DRC + LVS + ERC + Antenna，官方 deck | 签核 |

关键认知：**越早跑越便宜**。布线后一万条 DRC，可能是某个布线参数错了，改一次消掉九千条；等到流片前才发现，改动空间已经很小了。

流片前那次"全量检查"，最后要对着一张清单逐项画勾：

:::fig finish-checklist | 送厂前的 10 项检查：左边是每一条的判据，右边是出报告的工具。重点看底部那三条"最常见的形式主义错误"——报告在，但报告是旧的：检查跑了、报告也交了，交的却是上一版的输出。
:::

从图里要看出什么：**每一项都要"判据 + 工具 + 报告日期"对得上**。PV 的纪律"宁可多跑一遍，不可少看一眼"，最后就落在这张清单的每一行上。

## DRC 违例怎么读 {#drc}

Calibre 的 DRC 报告（摘要格式，工具版本不同格式略有差异）：

```text
RULECHECK M2.SPACE.1 :  12 Results
  --------------------------------------------------
  M2.SPACE.1 @ (1200, 3400) : 0.08um < 0.10um
  M2.SPACE.1 @ (1250, 3400) : 0.09um < 0.10um
```

一行里有四个信息，缺一不可：

| 字段 | 例子 | 含义 |
|---|---|---|
| 规则名 | `M2.SPACE.1` | 层 + 规则类型 + 序号。`M2` = 第二层金属，`SPACE` = 间距，`.1` = 该规则的第一条变体 |
| 坐标 | `@ (1200, 3400)` | 违例位置，单位是数据库单位（database unit，通常 0.001µm 或 0.005µm） |
| 实测值 | `0.08um` | 版图里实际的尺寸 |
| 要求值 | `0.10um` | 规则要求的最小值 |

**坐标要会换算。** 如果 database unit 是 0.001µm，那么 `(1200, 3400)` 就是 `(1.2µm, 3.4µm)`。这个换算决定了你能否在版图编辑器里跳过去看——打错一个零，就跳到芯片另一头去了。

报告里的规则名和坐标，落到 Calibre 的结果查看窗口（RVE）里是这样对应的：

:::fig calibre-rve | Calibre RVE 结果窗口：左边按规则名分组列出各类违例条数，右边上半是版图（红框标出问题位置），下半是明细表（规则名、实测值、限制值、坐标）。重点练左边——先按规则分类看条数，再点进坐标看版图，这正是"分类 + 聚类"两个动作的工具入口。
:::

从图里要看出什么：**学会在这张窗口里"先分类、再跳坐标"，等于学会了改 DRC**。后面 pitfall 里"卡在几百条就乱调参数"的错误，用这张图的工作流就能避开。

:::term Rule Deck | 规则文件
工厂提供的 DRC 规则集合，通常是一个几百 MB 的文本/SVRF 文件，里面用 Calibre 的语法把每条规则写成几何运算："M2 层任意两个图形的间距不得小于 0.10µm" → `M2.space(0.10)`。

**规则文件由工厂维护，禁止自己改。** 你能改的只有"跑哪些规则"，不能改"规则是多少"。
:::

### 常见的规则类型

| 规则名模式 | 查什么 | 典型原因 |
|---|---|---|
| `M*.WIDTH` | 线宽下限 | 布线用了窄线，或 NDR 没生效 |
| `M*.SPACE` | 同层间距 | 两条线太近（最常见） |
| `M*.ENCLOSURE` | 上层对下层的包边 | via 周围的金属不够宽 |
| `VIA*.CUT` | 通孔尺寸/数量 | 单孔不够，需要双孔 |
| `M*.DENSITY` | 金属密度（窗口内占比） | 大空白区，CMP 会凹陷 |
| `PO.SPACE` / `PO.WIDTH` | 多晶硅（栅极）规则 | 标准单元内部问题，通常不该出现 |

`M*.DENSITY` 这类"密度规则"新手最容易懵：它不是"某两个图形太近"，而是"某个 100µm × 100µm 的窗口里金属占比必须在 30%~70% 之间"。修法是**填冗余金属（dummy metal）**，不是挪线。

### 修法：按代价从小到大

1. **挪线**：把其中一根移开一两个轨道（track）。代价最小，但可能引发新的违例。
2. **缩短/改道**：把这段线绕开，或改走别的位置。
3. **换层**：这段改到 M3。注意 M3 也有自己的间距规则。
4. **加宽**：某些规则下宽一点反而满足（比如宽线有豁免）。
5. **局部重布（rip-up & reroute）**：让工具重布这一小片。
6. **改单元位置**：如果违例来自两个单元挨太近。

:::pitfall DRC 从 8000 降到 300 就卡住
现象：前几千条改一次参数就消掉一大片，剩下几百条怎么调参数都不动。

原因：前几千条是**系统性**的（布线参数、NDR 没生效、单元摆放太密），一次改一片；剩下的是**孤例**，每条成因都不同。

正确做法不是继续调参数，而是三步分类：

1. 按规则类型统计：`M2.SPACE` 多少条、`VIA.ENCLOSURE` 多少条。
2. 按坐标聚类：是不是集中在某几个区域（可能是一个 macro 周围）。
3. 一类一类修，每修完一类重跑一次，别攒着。

```bash
# 作用：按规则类型统计 DRC 违例条数，找出"大头"
# 用法：在跑完 Calibre 的目录下执行，drc.rpt 是结果报告
grep -o "^RULECHECK [A-Z0-9._]*" drc.rpt | sort | uniq -c | sort -rn | head
# grep -o 只输出匹配部分（RULECHECK + 规则名），去掉后面的条数
# sort | uniq -c  统计每条规则出现几次
# sort -rn        按条数从多到少排，第一行就是最大的问题
```
:::

:::pitfall 只看总数不看层，修错方向
现象：DRC 总数一直降不下去，每天修几十条，第二天又冒出几十条。

原因：修 A 类违例时挪了线，在 B 层制造了新违例。总数看起来没变，其实是"此消彼长"。

处理：每次修完记录**分类快照**（每类多少条），而不是只记总数。看的是"这一类是否归零"，不是"总数是否下降"。
:::

## LVS 怎么对 {#lvs}

LVS 的前提是**提取（extraction）**：从版图的几何图形反推"这里有一个 NMOS，宽 0.12µm、长 0.03µm，源接 net A，漏接 net B，栅接 net C"。

:::term Extraction | 提取
把版图图形翻译成器件和连线。规则来自工厂的提取 deck（与 DRC deck 配套）。提取出来的东西叫"extracted netlist"，和原始网表（source netlist）比对，就是 LVS。
:::

```bash
# 作用：跑一次层次化 LVS
# 用法：在 lvs/ 目录下执行，lvs.runset 里指定 layout 和 source
calibre -lvs -hier -turbo lvs.runset
# -lvs     进入 LVS 模式
# -hier    层次化比对（大设计必须开，否则内存吃不消）
# -turbo   多线程加速
```

结论通常先给一句大字：

```text
CELL COMPARISON RESULTS
#     ################################################
#     #                    CORRECT                   #
#     ################################################
```

不对的时候，报告会给出三类差异。这三类的定位方法完全不同：

| 类型 | 报告长什么样 | 本质 | 怎么查 |
|---|---|---|---|
| **Short（短路）** | `Net VDD_NET has 2 connections` / `Short between net A and net B` | 版图里两条本该分开的线连在一起了 | 看坐标，多半是金属重叠或 via 打错位置 |
| **Open（开路）** | `Net A is split into 2 subnets` / `Open on net A` | 一条线中间断了 | 看是不是少打了一个 via，或线被裁断 |
| **Device mismatch（器件不符）** | `Instance mismatch: M1 (layout) has no counterpart in source` / `Property error on M1: W 0.12 vs 0.10` | 器件多了、少了、或尺寸/并联数不对 | 对照原理图，检查单元里的器件定义 |

### 三类差异的读法

**Short**：报告会说哪两条 net 被连在一起。常见于电源/地（`VDD` 和 `VSS` 短在一起是最恐怖的，直接烧片），也常见于两条信号线因为一个多余的 via 连上。

处理：按坐标跳过去，用层次浏览器看这一片是哪两个单元的交界。**short 是最容易修的**（删掉多余图形），但也是最容易漏的（DRC 可能完全看不出来）。

**Open**：报告会说某条 net 被切成几段。最常见的原因是**少打 via**（版图上两条线在同一个坐标交叉，但没有 via 连接），或者某段线被 DRC 修的时候裁掉了。

处理：LVS 报告通常给出每段的坐标范围，把两段之间那一小片放大看。

**Device mismatch**：最容易被误判成"LVS 工具错了"的一类。常见原因：

- 版图里把两个并联的管子画成了一个（或反过来），总数对但 instance 数不对。
- 器件尺寸提取值和网表值差一点（比如 `W 0.12 vs 0.10`），是提取 deck 的精度或网表参数写法问题。
- 电源 via 被提取成一个器件（少见，但发生过）。

:::pitfall LVS 报 net 名字不一样，就当错误修
现象：`Net mismatch: VDD vs VDD_CORE`，你花半天改版图的命名。

原因：LVS 比对的是**连接关系**，不是名字。名字不同但连接等价，通常是"电源网络在不同层次用了不同名字"（顶层叫 `VDD`，单元里叫 `VDD_CORE`），或者是文本标签（label）没打。

处理：先看是不是 `LVS POWER NAME` / `LVS GROUND NAME` 的配置问题，或者是 label 缺失导致的"未命名 net"。**改配置比改版图便宜得多，顺序别搞反。**
:::

## ERC：几何合法但电气危险 {#erc}

DRC 保证"画得出来"，ERC 保证"画出来不会出电气问题"。它查的是几何合法、但物理上危险的结构。

一个类比：楼梯每一级高度都符合规范（DRC 过），但扶手没装（ERC 不过）。验收时看图纸挑不出毛病，住进去才知道危险。

| 检查项 | 现象 | 后果 |
|---|---|---|
| 浮空栅（floating gate） | 栅极没有连接到任何 net | 电位不定，可能常开，漏电 |
| Well/Tap 接触不足 | 衬底接触离器件太远，或密度不够 | 闩锁（latch-up），芯片直接锁死 |
| 电源/地短路 | VDD 和 VSS 之间有低阻通路 | 上电即烧 |
| 天线比例 | 见下一节 | 栅氧击穿 |

:::term Latch-up | 闩锁
CMOS 结构里天然存在寄生的 PNPN 可控硅。当衬底注入电流足够大时，这个寄生结构被触发导通，形成 VDD 到 VSS 的低阻通路，电流暴涨，芯片锁死甚至烧毁。Well/Tap 接触足够密，就是为了把寄生电流引走。
:::

### 为什么 tap 不能离器件太远

衬底是有电阻的。距离注入点越远，寄生电阻越大，同样的衬底电流产生的压降越大。压降超过约 0.6~0.7V（PN 结开启电压），寄生三极管就导通了。

手算一次：衬底薄层电阻按 1000 Ω/□ 估算，一个 tap 覆盖半径 20µm 时，从最远点到 tap 的方块数约 `20/2 = 10 □`（粗略按半宽算），电阻 `10 × 1000 = 10 kΩ`。如果这一片有 100µA 的衬底电流，压降就是 `100µA × 10kΩ = 1V`——已经超过 0.7V，闩锁风险成立。

所以规则不是"随便放几个 tap"，而是给出**最大间距**（比如每 30~50µm 必须有一个 tap）。这个数字由工艺决定，写在 deck 里。

ERC 的违例数量通常远小于 DRC（几十条量级），但**每一条都不能 waive**——它们全都指向真实的可靠性风险。

## Antenna：为什么它是"制造期"问题 {#antenna}

这是四种检查里最反直觉的一个。芯片做完了，天线效应就不存在了——它只在**制造过程中**发生。

### 物理过程

等离子体刻蚀（plasma etching）时，腔体里有大量带电粒子。一条长金属线像天线一样把这些电荷收集起来。如果这条线只连到晶体管栅极（没有别的泄放通路），电荷就堆积在栅氧化层上。

栅氧化层有多薄？28nm 工艺大概 1~2nm，相当于十几个原子层。 accumulated 电荷产生的电压足以把它击穿。击穿之后，这个管子就废了——可能表现为漏电变大，也可能直接短路。

**这就是为什么它不能靠测试筛出来**：损坏发生在制造时，芯片出厂时可能已经带伤，测试不一定能覆盖到。

### 判据与手算

判据是一个比值：

```
antenna_ratio = 连接到栅极的金属面积 / 栅氧化层面积
```

超过工艺给的阈值（典型 300:1 到 500:1，不同层不同）就违例。

手算一次：一条 M1 线宽 0.5µm、长 100µm，连到一个栅极，栅宽 1µm、栅长 0.1µm。

- 金属面积 `= 0.5 × 100 = 50 µm²`
- 栅面积 `= 1 × 0.1 = 0.1 µm²`
- `ratio = 50 / 0.1 = 500 : 1`

如果该层的限制是 300:1，这条就违例了，超出 67%。

### 两种修法

1. **跳层（layer hopping）**：把长线在中途换到更高层。因为天线比例是**按层分别累计**的，换层后原来那层的累积被打断。做法是在靠近栅极的地方先走一小段 M1，然后马上 via 上 M2 走长距离，再下来。这样 M1 那段很短，比例就过了。
2. **加天线二极管（antenna diode）**：在栅极附近加一个反向偏置的二极管，制造时把电荷泄放到衬底。代价是增加面积和一点点漏电/电容。

```tcl
# 作用：让布线器在布线时自动修天线违例
# 用法：Innovus 里在 route 之前设置；ICC2 对应 set_app_options
setNanoRouteMode -routeAntennaFixMode true
# true = 布线时插入跳层或二极管（具体用哪种由工具选）
setNanoRouteMode -routeAntennaFixModeWithDiode true
# 允许用二极管修（更可靠，但面积大）
```

:::note 天线违例经常"修完又回来"
跳层会把长线推到更高层，而更高层自己的天线比例限制可能更严（因为高层线更宽、面积更大）。所以修完必须重跑一遍 Antenna 检查，不能假设一次就干净。
:::

## 课程环境：KLayout 能做什么，不能做什么 {#klayout}

Calibre 是商业工具，课程环境没有 license。替代方案是 **KLayout**（开源版图工具，支持 Ruby/Python 脚本做几何运算）。

但必须把边界说清楚，否则你会以为"KLayout 过了就能交付"。

| 能力 | KLayout | 说明 |
|---|---|---|
| 读 GDS/OASIS | ✅ | 完整支持 |
| 几何运算（间距/面积/包边/密度） | ✅ | 用 `Region` 的 API 自己写 |
| 目视检查、层次浏览、坐标跳转 | ✅ | 比 Calibre 的 RVE 还好用 |
| 跑工厂的完整 DRC deck | ❌ | deck 是 Calibre 语法（SVRF），KLayout 不认；加密 deck 更不行 |
| 完整 LVS（器件识别 + 比对） | ⚠️ 部分 | KLayout 有 LVS 功能，但需要自己写器件提取规则，和工厂 deck 不等价 |
| ERC / Antenna | ❌ | 没有现成实现 |

所以课程里用 KLayout 的目标是：**理解 DRC 的本质是几何运算**，而不是"用 KLayout 交付"。

```python
# 作用：用 KLayout 的 API 做一个最小 DRC——检查 M2 间距
# 用法：klayout -b -r m2_space.py（-b 批处理模式），或在 KLayout 里 Run Script
import pya

layout = pya.Layout()                      # 建一个空 Layout 对象
layout.read("final.gds")                   # 读入版图（GDS 或 OASIS）
dbu = layout.dbu                           # 数据库单位，通常 0.001（即 1nm）
print("DBU =", dbu, "um")                  # 打印出来，后面坐标换算要用

m2 = layout.layer(2, 0)                    # 按 (layer, datatype) 取 M2 层
m2_region = pya.Region(layout.top_cell().begin_shapes_rec(m2))
# begin_shapes_rec 做层次化遍历，比 flat 遍历省内存

space_viol = m2_region.space_check(0.10, False)
# 0.10 = 规则值（µm）；False = 不检查"同一图形内部"的间距
# 返回值是一个 Region，里面每个多边形就是一个违例标记

print("M2 spacing violations:", space_viol.count())
for poly in space_viol.each():
    box = poly.bbox()                      # 违例的包围盒
    print("  at (%.3f, %.3f) um" % (box.left * dbu, box.bottom * dbu))
    # 乘 dbu 把数据库单位换算成 µm，方便和 Calibre 报告对照
```

这段脚本只做了 `M2.SPACE` 一条规则。真正的 deck 有几百上千条，还要处理"宽金属豁免""角到角""同网豁免"等各种变体——这就是为什么工厂要提供 deck，而不是让你自己写。

:::pitfall 拿 KLayout 的结果去回答"DRC 干净吗"
现象：你在课程环境用 KLayout 跑了几条规则，0 违例，于是在报告里写"DRC clean"。

问题：你只查了 3 条规则，真实 deck 有 800 条。这个结论是错的，而且是危险的错——它会让人以为可以交付。

正确表述：**"用 KLayout 自查了 M2 间距和 M1 包边，无违例；完整 deck 需在 Calibre 环境跑，课程环境不具备。"** 写清范围和边界，是工程文档的基本要求。
:::

## 工作中怎么用 {#in-work}

**谁做**：物理验证工程师（PV 工程师），或由版图/PR 工程师兼。大公司有专门的 PV 团队，负责跑 deck、分类违例、出 waiver 建议。

**输入**：最终 GDS（或 OASIS）、网表（用于 LVS）、工厂 deck、waiver 清单（上一版遗留的）。

**输出**：四份报告 + 一份分类统计表 + waiver 清单。分类统计表要写给版图负责人看："137 条 = 98 条 M2 间距（集中在右下 macro 区）+ 30 条 via 包边 + 9 条天线"。

**评审会看什么**：不是"还剩几条"，而是"剩下的每一条，是修、是 waive、还是挡住 tapeout"。这个判断需要工程依据：

- 能修的（局部挪线、加 via）→ 修。
- 工厂明确允许的（某些密度规则在指定区域可豁免）→ 申请 waive，留书面记录。
- 说不清的 → **不许 waive**。说不清就是没搞懂，没搞懂就不能签字。

**做错了会怎样**：DRC 不过，工厂直接拒收（GDS 打回），耽误的是整个项目节点；LVS 不过而没人发现，流片回来是死片，损失是全掩膜的钱。所以 PV 的纪律是：**宁可多跑一遍，不可少看一眼。**

:::lab 动手：把一份 DRC 报告拆成可执行的清单
**任务**：课程环境提供 `~/backend_lab/pv/drc_sample.rpt`（一份 Calibre 格式的 DRC 摘要，约 300 行）。你要产出三样东西：分类统计、最密集区域的坐标范围、以及一份"先修哪类"的建议。

**步骤**：

1. 统计每类规则的条数：

```bash
# 作用：按规则名统计违例条数，从多到少排序
# 用法：在 pv/ 目录下执行，报告文件是 drc_sample.rpt
grep -oE "^RULECHECK [A-Za-z0-9._]+" drc_sample.rpt | awk '{print $2}' | sort | uniq -c | sort -rn
# grep -oE   只取出"RULECHECK 规则名"这一段
# awk '{print $2}'  取第二列，即规则名本身
# uniq -c    统计次数；sort -rn 按次数倒序
```

2. 看坐标分布（假设 database unit = 0.001µm）：

```bash
# 作用：把违例坐标的 X 值分段统计，看是否集中在某一片
# 用法：只取 M2.SPACE.1 这一类，按 X 坐标每 100µm 一档
grep "M2.SPACE.1 @" drc_sample.rpt | \
  sed -E 's/.*@ \(([0-9]+),.*/\1/' | \
  awk '{printf "%d00-%d99um: %d\n", int($1/100000), int($1/100000), 1}' | \
  sort | uniq -c | sort -rn | head -5
# sed 取出括号里第一个数（X 坐标，单位 DBU）
# awk 把 X 除以 100000（=100µm/0.001µm）得到"第几个 100µm 区间"
# 最后按区间计数，看违例是不是扎堆
```

3. 抽一条违例，手算它在版图里的真实坐标和差值。

**过关标准**：能回答三个问题——① 最大的一类占多少条、是什么规则；② 违例是否集中在某个区域（给出坐标范围）；③ 如果只有两小时，先修哪一类、为什么。第三问没有标准答案，但必须给出理由（比如"这类是系统性的，改一个布线参数能消掉一半"）。
:::

:::quiz
DRC 和 LVS 分别保证什么？|DRC 保证工厂能按几何规则造出来；LVS 保证造出来的连接关系和网表一致（功能正确）。
`M2.SPACE.1 @ (1200, 3400) : 0.08um < 0.10um` 这四个字段各是什么？|规则名（M2 层间距第 1 条变体）、坐标（数据库单位）、实测值 0.08µm、要求值 0.10µm。
database unit 是 0.001µm 时，坐标 (1200, 3400) 对应版图哪里？|(1.2µm, 3.4µm)。换算错一个零就会跳到芯片另一头。
LVS 的 short 和 open 分别是什么现象？|short 是两条本该分开的 net 被连在一起（多余图形或 via 位置错）；open 是一条 net 被切断（少打 via 或线被裁断）。
LVS 报 "Net mismatch: VDD vs VDD_CORE" 通常怎么处理？|先查电源/地名字配置和 label 是否缺失，而不是直接改版图；连接等价时改配置即可。
Antenna 为什么只在制造期发生？|等离子刻蚀时电荷积累在长金属上，击穿栅氧化层；芯片制造完成后电荷不再积累，所以只能靠版图设计避免。
一条 M1 线 0.5µm × 100µm 接栅极（1µm × 0.1µm），天线比是多少？|50µm² / 0.1µm² = 500:1；若该层限制 300:1，则违例。
课程环境用 KLayout 的边界是什么？|能做几何运算和目视检查（自写规则子集），不能跑工厂完整 deck，也没有等价的 LVS/ERC/Antenna；结论必须写清"只覆盖了哪几条规则"。
DRC 剩几百条时为什么不该继续调参数？|剩下的是孤例而非系统性问题，调参数无效；应按规则类型和区域聚类，逐类修。
:::
