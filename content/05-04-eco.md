## ECO 是什么，什么时候用它 {#what}

ECO（Engineering Change Order）是"**只改必须改的地方**"的一套流程。它不改 RTL、不重跑综合、不重做布局，直接在已有版图上动几十个单元。

| 情况 | 全流程重跑 | ECO |
|---|---|---|
| 时序差几条 | 几小时到两天 | 十几分钟到两小时 |
| 版图基本定型 | 全部重来 | 只动局部 |
| 风险 | 新版本可能引入新问题 | 改动面小，可控 |
| 前提 | 无 | **必须能精确定位到具体单元** |

:::scene 送厂前三天，PT 报 3 条 hold 违例
你签核完，PT 出报告：3 条 hold，最差 -0.07ns。全流程重跑要两天，时间不够。

正确动作：写一个 ECO，在 3 条路径的终点插入 3 个 delay cell，局部重布，回签。两小时。

这三个 cell 的面积代价是 3 × 0.76um² ≈ 2.3um²，占芯片 49440um² 的 0.005%。**这就是 ECO 的价值：用最小改动换签核通过。**
:::

:::term ECO | Engineering Change Order，工程变更单
原意是芯片设计流程里的"变更申请"。在后端语境下，特指**在已有版图上做局部修改**：换单元尺寸、插缓冲器、改连线，然后局部重布、重新签核。

三类 ECO：**RTL ECO**（改代码，要重跑综合）、**门级 ECO**（改网表，不动 RTL）、**metal-only ECO**（只改金属层，连硅片掩膜都不用重做，最贵也最快）。
:::

## 完整链路：五个环节，一个都不能省 {#flow}

```text
① PT 出违例报告（带具体 pin 名）
      ↓
② 生成 ECO 改动清单（哪个单元、换成什么、插在哪）
      ↓
③ 在 ICC2 里应用改动（改网表 + 改布局）
      ↓
④ 局部重布 + 局部时序优化（不是全芯片）
      ↓
⑤ 回签：PT 重新计时序、FM 验证等价性、DRC 复查
```

| 环节 | 工具 | 关键点 |
|---|---|---|
| ① 找违例 | PrimeTime | 必须 `-significant_digits 4`，否则 -0.07 会显示成 -0.1 |
| ② 生成清单 | 脚本 / PT 的 `fix_eco_timing` | 清单必须是"人可读 + 机器可执行" |
| ③ 应用 | ICC2 | 改完先 `check_lvs` 再布线 |
| ④ 局部重布 | ICC2 / Innovus | 只布改动的网，别全芯片重布 |
| ⑤ 回签 | PT + Formality | **改了网表必须重跑 FM**，否则等于没验证 |

## 改动清单长什么样 {#changelist}

一份好的 ECO 清单是纯文本，一行一个动作，人能看懂、脚本能解析：

```text
# eco.txt —— 每个字段：动作 目标 参数 原因
size_cell   u_core/u_alu/U2317   BUF_X4      # 驱动不足，负载 12 个
insert_buf  u_core/u_ctrl/reg_state[2]/D  DELAY_X1   # hold -0.07ns，需 +70ps
remove_buf  u_core/u_mul/U882    -           # 冗余缓冲，占了布线资源
```

为什么要用文本清单而不是直接写 Tcl：

1. **可评审**：发给同事看一眼就知道你要改什么；
2. **可回退**：清单留着，出问题按反向操作撤销；
3. **可统计**：`grep -c insert_buf eco.txt` 就知道插了多少个。

## 应用脚本：可执行的骨架 {#script}

下面这段是能直接改成项目用的 ICC2 ECO 脚本。逐行看注释。

```tcl
# ============================================================
# apply_eco.tcl —— 读取 eco.txt，在已有版图上应用改动
# 用法：icc2_shell -f apply_eco.tcl
# 前提：block 已经 open，且已 save 过一个"ECO 前"的快照
# ============================================================

set ECO_FILE  "./eco.txt"
set SNAP_PRE  "snapshot_pre_eco"     ;# 出问题回退用

# ---- 0. 先存一个快照。这一步永远不要省 ----
save_block -as $SNAP_PRE
puts "@@@ 已保存 ECO 前快照：$SNAP_PRE"

# ---- 1. 读清单 ----
set fh [open $ECO_FILE r]
set lines [split [read $fh] "\n"]
close $fh

set n_size 0
set n_ins  0
set n_rem  0

foreach line $lines {
  # 去掉行尾注释和首尾空格；空行跳过
  set line [string trim [lindex [split $line "#"] 0]]
  if {$line eq ""} { continue }

  set act  [lindex $line 0]
  set tgt  [lindex $line 1]
  set arg  [lindex $line 2]

  # 每个动作单独 catch：一条失败不影响后面的
  switch -- $act {
    size_cell {
      # 把某个实例换成另一个库单元（同功能、不同驱动）
      if {[catch {size_cell $tgt $arg} err]} {
        puts "@@@ FAIL size_cell $tgt -> $arg : $err"
      } else { incr n_size }
    }
    insert_buf {
      # 在目标引脚前插一个缓冲/延迟单元
      # -pin 指定插在哪个引脚之前，工具会自动断开原连线
      if {[catch {
        set buf [insert_buffer [get_pins $tgt] $arg]
        set_attribute [get_cells $buf] is_physical true   ;# 标记为物理单元
      } err]} {
        puts "@@@ FAIL insert_buf $tgt : $err"
      } else { incr n_ins }
    }
    remove_buf {
      # 删掉冗余单元：先把它的输入连到输出，再删
      if {[catch {
        set ipin [get_pins -of_objects [get_cells $tgt] -filter "direction==in"]
        set opin [get_pins -of_objects [get_cells $tgt] -filter "direction==out"]
        set net  [get_nets -of_objects $ipin]
        disconnect_net $net [get_pins -of_objects [get_cells $tgt]]
        connect_net $net [get_pins -of_objects [get_nets -of_objects $opin] -filter "direction==in"]
        remove_cell [get_cells $tgt]
      } err]} {
        puts "@@@ FAIL remove_buf $tgt : $err"
      } else { incr n_rem }
    }
    default { puts "@@@ 未知动作：$act" }
  }
}

puts "@@@ ECO 应用完成：size=$n_size insert=$n_ins remove=$n_rem"

# ---- 2. 合法性检查（必须有）----
legalize_placement
check_lvs
# 如果有错，这里就要停下来，不要继续布线

# ---- 3. 只布改动的网，不要全芯片重布 ----
route_auto -nets [get_nets -of_objects [get_cells -hier -filter "is_physical==true"]]
route_detail -incremental true

# ---- 4. 局部时序优化：只优化受影响区域 ----
set_app_options -name opt.post_route.effort -value medium
route_opt -incremental

# ---- 5. 出报告 + 存盘 ----
redirect eco_drc.rpt { check_routes }
redirect eco_timing.rpt { report_qor }
save_block -as snapshot_post_eco
puts "@@@ ECO 完成，报告：eco_drc.rpt / eco_timing.rpt"
```

:::pitfall `insert_buffer` 之后忘了 `legalize_placement`
插进去的单元坐标是"挨着目标引脚"的浮点位置，可能和别的单元重叠。不 legalize 直接布线，会得到一堆 spacing DRC 和 short。

**规矩：任何改变布局的 ECO，应用完第一件事就是 `legalize_placement`。**
:::

## 让 PT 帮你算：`fix_eco_timing` {#pteco}

手写清单适合少量违例。几百条违例时，让 PT 生成：

```tcl
# ---- 在 PT 里 ----
# 1) 先确认时序真的收敛过，报告可信
report_timing -delay_type min -max_paths 20 -significant_digits 4

# 2) 让 PT 生成 ECO 修复建议（只出方案，不改网表）
fix_eco_timing -type hold \
               -methods {insert_buffer size_cell} \
               -buffer_list {DELAY_X1 BUF_X2} \
               -slack_lesser_than 0

# 3) 把方案写成脚本
write_changes -format icctcl -output eco_hold.tcl
#    icctcl = ICC2 能直接 source 的格式
#    也可以 -format ptsh / dcsh / innovus
```

| 参数 | 作用 | 建议 |
|---|---|---|
| `-type hold` / `setup` | 修哪类违例 | 一次只修一类，先 hold 后 setup |
| `-methods` | 允许哪些手段 | 只给 `size_cell` 更安全；`insert_buffer` 更有效 |
| `-buffer_list` | 允许插哪些单元 | 明确列出，别让工具自由发挥 |
| `-slack_lesser_than 0` | 只修负 slack 的 | 加 `-slack_greater_than -0.1` 可限制"只修严重的" |

:::note PT 生成的 ECO 为什么不建议直接 source
PT 只看时序，不知道物理。它可能建议把一个单元换大两档，但那个位置**放不下**；或者建议插 5 个 buffer，但那片区域**已经拥塞**。

正确做法：PT 出方案 → 人看一遍 → 删掉物理上不合理的 → 再应用。这个"人看一遍"是 ECO 里最值钱的十分钟。
:::

## 实战：修那 3 条 -0.07ns 的 hold {#case}

回放我们实测的场景（12026 单元，ICC2，hold WNS -0.07ns）。

**第一步：确认违例在哪**

```tcl
report_timing -delay_type min -max_paths 5 -significant_digits 4 \
              -path_type full_clock_expanded
```

看到三条，都在 `u_ctrl/state_reg[*]` 的 D 端。原因：这几个触发器离时钟树末端很近，时钟到得早，数据反而"太早稳定"→ hold 违例。

**第二步：判断修法**

| 方案 | 做法 | 代价 | 选不选 |
|---|---|---|---|
| A. 数据路径插 delay cell | 在 D 端前插 `DELAY_X1`（约 60~80ps） | 3 个单元，面积 +2.3um² | ✅ 选这个 |
| B. 调时钟 skew | 让这几个触发器的时钟晚到 | 影响同一支路其他触发器 | ❌ 风险大 |
| C. 换更大驱动的上一级 | `size_cell` 换大 | 可能改善也可能恶化 | ❌ 不针对 hold |

**第三步：写清单**

```text
insert_buf  u_ctrl/state_reg[2]/D  DELAY_X1   # hold -0.0712ns，需 +72ps
insert_buf  u_ctrl/state_reg[5]/D  DELAY_X1   # hold -0.0688ns
insert_buf  u_ctrl/state_reg[7]/D  DELAY_X1   # hold -0.0654ns
```

**第四步：应用 + 回签**

```bash
icc2_shell -f apply_eco.tcl          # 应用改动
pt_shell  -f scripts/pt.tcl          # 重新签核时序
fm_shell  -f scripts/fm.tcl          # 等价性（关键！）
```

**第五步：确认三件事**

```text
1) PT: hold WNS 从 -0.07 变成 +0.02  ✅
2) FM: 2560/2560 等价              ✅
3) DRC: 仍是 0                     ✅
```

:::pitfall 改了网表却没更新 SVF，FM 直接报不等价
Formality 靠 SVF（引导文件）知道"工具做了哪些优化"。ECO 手工改的网表**不在 SVF 里**，FM 会认为你改坏了逻辑。

两种处理：
1. 手工改动**只允许物理类**（插 buffer/delay、换同功能不同驱动），并在 FM 里 `set_dont_verify_points` 排除这些点；
2. 或者用 `eco_netlist` 生成增量 SVF 一并喂给 FM。

**千万不要**因为 FM 报错就把这几条设成 don't care——那是把"验证"变成"假装验证"。
:::

## ECO 的四条纪律 {#discipline}

1. **一次只改一类问题**。先 hold，回签；再 setup，回签。混在一起改，出问题不知道是谁的锅；
2. **每次改动前存快照**（`save_block -as snapshot_pre_xxx`）。ECO 的价值就是可回退，不回退就没价值；
3. **清单进 git**。`eco.txt` 是文本，必须版本管理，写明"为什么改"；
4. **改完必查三样**：时序（PT）、等价（FM）、DRC。少一样都不算完成。

:::term Metal-only ECO | 只改金属层的 ECO
芯片已经流片回来，发现逻辑或时序问题，只能改金属层（因为晶体管层已经做死了）。做法是预先在版图里留一些**备用单元（spare cell）**，需要时只改连线。

这是最贵最快的一种 ECO，通常只在"芯片已经回来但有问题"时用。
:::

:::lab 动手：写一份自己的 ECO 清单并解析它
在模拟终端里做这个练习（这是真实工作里的第一步）：

```bash
cd ~
cat > eco.txt <<'EOF'
# 动作        目标                              参数        原因
insert_buf    u_ctrl/state_reg[2]/D             DELAY_X1    hold -0.0712
insert_buf    u_ctrl/state_reg[5]/D             DELAY_X1    hold -0.0688
size_cell     u_core/u_alu/U2317                BUF_X4      驱动不足
EOF

# 统计每类动作有多少条
awk '!/^#/ && NF>0 {print $1}' eco.txt | sort | uniq -c
```

预期输出：

```text
   2 insert_buf
   1 size_cell
```

再进一步：把"原因含 hold"的行挑出来

```bash
grep hold eco.txt | awk '{print $2}'
```

过关标准：能用 `awk` + `grep` + `sort` + `uniq` 三个命令统计任意一份改动清单。这套动作每天都会用到。
:::
