## 两个真实故障 {#cases}

**故障一：芯片跑低频正常，一上高频就随机死机。**
原因：高频时电流瞬间变大，局部电压跌落超过 10%，触发器抓错数据。

**故障二：芯片用了半年开始出问题，越来越频繁。**
原因：电源线电流密度太大，金属被电迁移"烧"出空洞，电阻逐渐变大。

这两种都不是时序问题，也不是 DRC 问题，而是**功耗完整性问题**。

:::term Power Integrity | 功耗完整性
Power Integrity（PI）。研究"电能能不能干净、稳定地送到每个单元"。包含 IR drop、EM、电源噪声等。
:::

## IR Drop 分两种 {#types}

| 类型 | 什么时候发生 | 典型阈值 | 工具 |
|---|---|---|---|
| 静态 IR drop | 平均电流引起 | < 3%~5% VDD | RedHawk / Voltus |
| 动态 IR drop | 时钟沿同时翻转，瞬间大电流 | < 8%~10% VDD | 需要激励向量（VCD） |

```
静态：所有单元同时耗平均电流 → 电源网格上的平均压降
动态：时钟上升沿，几万个触发器同时翻转 → 瞬时电流尖峰 → 局部电压塌陷
```

:::term Dynamic IR Drop | 动态电压降
芯片里最危险的不是平均功耗，而是**瞬间电流**。时钟沿到来的那一刻，几万个触发器同时动作，电流可以在几十皮秒内冲到峰值。

如果电源网格响应不过来（电感、电阻太大），局部电压会瞬间塌下去，触发器就可能抓错数据。
:::

## RedHawk 需要什么输入 {#inputs}

| 输入 | 内容 | 来源 |
|---|---|---|
| DEF | 布局布线 | PR 工具 |
| LEF | 单元物理 | 库 |
| Liberty（.lib） | 功耗模型 | 库 |
| SPEF | 寄生 RC | PR/RCX |
| Power intent（UPF） | 电源域与开关 | 低功耗设计 |
| 激励（VCD/FSDB） | 实际翻转活动 | 仿真 |

:::pitfall 没有 VCD，做不了动态 IR
静态 IR 只需要平均功耗（`report_power` 就能给）。动态 IR 必须有**真实翻转信息**——哪个信号什么时候翻转。

没有 VCD 时，工具只能用"假设翻转率"（比如 20%），结果只能做趋势参考，不能签核。

**所以动态 IR 分析要和验证团队要仿真波形，这是跨团队协作的典型场景。**
:::

## 报告怎么看 {#report}

RedHawk 输出通常是热图 + 统计表：

```
Voltage Drop Summary (VDD, static)
  Max drop      : 42.3 mV  (4.2% of 1.0V)
  Location      : (1240, 860)  near u_core/u_dsp
  Avg drop      : 18.7 mV
  Violating instances : 37
```

三件事：

1. **最大压降是多少、占标称电压的百分比**。
2. **在哪个位置、哪个模块附近** —— 这决定怎么修。
3. **有多少个单元超过阈值** —— 决定严重程度。

:::scene 定位到具体模块之后怎么修
报告说压降最大在 `u_dsp` 附近，三种修法按代价排：

1. **加电源条密度**：在那个区域多打几条 stripe（最直接）。
2. **加 via**：如果是层间瓶颈，补 via 阵列。
3. **降局部功耗**：让 dsp 模块降低翻转率（改设计）、或分散布局（挪一部分逻辑走）。

**先看是"供电不够"还是"用电太猛"，对策完全不同。**
:::

## EM：电迁移 {#em}

电流密度超过限值，金属原子被电子"推走"，形成空洞或小丘，最终断路或短路。

```
允许电流 ≈ 线宽 × 工艺给的电流密度上限（mA/µm）
```

所以电源线宽不是随便定的，是按电流算出来的（03-04 算过）。

| 检查项 | 位置 | 修法 |
|---|---|---|
| 电源线 EM | stripe / ring | 加宽、加并联条 |
| 信号线 EM | 大驱动输出 | 加宽、降低驱动 |
| via EM | 过孔 | 加 via 数量 |

## 一节可以背下来的结论 {#summary}

| 现象 | 病因 | 查什么 |
|---|---|---|
| 低频正常、高频死机 | 动态 IR drop | 时钟沿附近的电压波形 |
| 用久了出问题 | EM | 电流密度报告 |
| 局部区域功能异常 | 静态 IR drop | 压降热图 + 该区域电源密度 |
| 上电时序异常 | power gating 时序 | UPF + switch 控制信号 |

:::check
- 能区分静态/动态 IR drop，知道各自阈值量级
- 知道 RedHawk 需要哪六类输入，尤其是 VCD 的作用
- 会读压降报告的三要素（最大值、位置、违例单元数）
- 知道 EM 的成因和三种修法
- 能根据"什么时候出问题"反推病因
:::
