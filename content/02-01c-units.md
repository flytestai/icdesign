## 为什么单位要先讲 {#why}

:::goal 能说出电压/电流/电阻/电容/功耗各自的物理含义与单位；能秒换 ps↔ns、um↔nm（都是 1000 倍）；能说出为什么"工艺说 nm、工具用 um"；看到 lef 里的 `0.06`、`0.2`、`0.02` 能立刻判断它是什么量、多少 nm。
:::

时序报告里一个数字 `0.052`，是 52ps 还是 52ns？差 1000 倍。lef 里 `WIDTH 0.06`，是 0.06um 还是 60um？也差 1000 倍。

**这类错误不会报错，只会让你得出完全相反的结论**：以为时序余量很足，实际已经崩了。所以这一课必须先过关。

## 五个基本量：物理含义比公式重要 {#basics}

### 电压 V：推动电子的"水位差" {#voltage}

:::term 电压 | voltage
两点之间的电势差，为电荷（电子）流动提供**驱动力**，单位**伏特（V）**。水位差越大，水流越急；电压越高，电流越大。
:::

芯片里只有两个电压名字要记：

| 名称 | 含义 | 逻辑电平 |
|---|---|---|
| **VDD** | 供电电压 | **高电平 = 逻辑 1** |
| **VSS** | 接地（0V） | **低电平 = 逻辑 0** |

所以"信号是 1"的物理含义就是"这根线被拉到 VDD"。而 PR 里 **power plan** 要做的，就是把 VDD/VSS 送到每一个单元的电源脚上。

电压和延迟的关系（后面 lib 课要反复用）：**电压越高，驱动力越强，延迟越小**。

### 电流 I：单位时间流过多少电荷 {#current}

:::term 电流 | current
单位时间内流过导体横截面的电荷量，反映"流动的快慢"，常用单位**毫安 mA / 微安 μA**。
:::

芯片里电流的两个关注点：

- **峰值电流**：太多会把电压拉低（IR drop），单元供电不足就变慢甚至失效；
- **平均电流**：决定功耗和散热。

### 电阻 R：走线越细越长，越难走 {#resistance}

:::term 电阻 | resistance
导体对电流的阻碍，单位**欧姆（Ω）**。**走线越细越长，电阻越大**；温度越高，金属电阻也越大。
:::

这条规律有一串直接后果：

- 长线电阻大 → 延迟大 → setup 变差（后面 rc tech / net delay 课的主线）；
- 细线（低层金属 M1）电阻大 → 关键信号优先走高层厚金属；
- via 也有电阻 → 换层越多，串联电阻越大。

### 电容 C：两根导体之间的"存储能力" {#capacitance}

:::term 电容 | capacitance
两个导体之间隔一层绝缘介质，就能存储电荷，这个能力叫电容，单位**法拉（F）**，芯片里常用 pF / fF。
:::

芯片里电容无处不在：**相邻两根线之间**（耦合电容）、**线与地之间**、**晶体管的栅极**。它带来的后果是"要给电容充放电，信号才能翻转"——**电容越大，延迟越大**。

:::term RC 提取 | RC extraction
把版图上的几何形状换算成真实的寄生电阻 R 与寄生电容 C 的过程。**Place 阶段只是估算（trial/estimate），CTS 之后跑 PT 时才会提取真实的线上 R、C。**
:::

### 功耗 P：动态 + 漏电 {#power}

:::term 功耗 | power
电路消耗的功率，芯片里分两块：
- **动态功耗**：电容充放电 + 信号翻转产生的功耗——**翻转越频繁、电容越大、电压越高，动态功耗越大**；
- **漏功耗（leakage）**：晶体管关断时电子逃逸造成的微弱漏电，**不翻转也在漏**，工艺越先进占比越高。
:::

这就是为什么低功耗设计有三板斧：**降电压、降频率/关时钟（clock gating）、换高阈值电压单元（hvt 漏电小）**。

## 两套必须背下来的换算 {#convert}

### 时间：ps ↔ ns（时序报告） {#time}

```
1 ns = 1000 ps        （10³）
1 ps = 0.001 ns
```

时序工具默认单位通常是 **ps 或 ns**，而 lib 文件里会写 `time_unit : "1ns"`。所以看到报告里的 `52`，先确认这个报告的表头单位——**这是新人第一个"看错十倍"重灾区**。

常用对照，建议直接记住：

| ns | ps |
|---|---|
| 0.001 | 1 |
| 0.01 | 10 |
| 0.05 | 50 |
| 0.1 | 100 |
| 1 | 1000 |

顺带记住频率与周期的关系：**频率 = 1 / 周期**。1GHz ↔ 1ns；500MHz ↔ 2ns；800MHz ↔ 1.25ns。

### 长度：um ↔ nm（lef 与工艺） {#length}

```
1 um = 1000 nm        （10³）
0.06 um = 60 nm
```

:::tip 为什么"工艺说 nm、工具用 um"
- **工艺节点**用人熟悉的 nm 说：28nm、16nm、7nm；
- **工具与库文件**内部一律用 **um**：lef 里 `WIDTH 0.06` 意思是 0.06um = 60nm，`SIZE 10.792 BY 1.672` 是 10.792um × 1.672um。

**所以看到一个裸数字，先问它是哪个文件里的、那个文件的单位是什么。**
:::

### 一组真实数字，对号入座 {#real}

文档里给的 28nm 级例子（tech lef 里能直接找到）：

| 参数 | 数值 | 换算 | 含义 |
|---|---|---|---|
| **pitch** | 0.2 um（或 0.19） | 200 nm | 同层相邻两条线的**中心距**，布线器的最小步进 |
| **线宽 WIDTH** | 0.06 um | 60 nm | 这一层最细能画多细 |
| **面积 area** | 0.02 um² | — | 单元面积量级（不同单元差很多） |

:::pitfall 单位混用：把 ns 当 ps、把 nm 当 um
**现象 A**：时序报告 WNS = `-52`，你以为是 -52ns（灾难），实际是 -52ps（0.052ns，很常见的小违例）。
**现象 B**：lef 里看到 `0.06`，算面积时当成 0.06um 但按 60um 量级去估，结果差 1000 倍。
**现象 C**：SDC 里 `-period 2` 写了 2ns，但你以为是 2ps，于是以为频率只有 500MHz，实际是 500MHz…… 反之亦然。

**防错三条**：
1. 看报告先找**表头单位**（`Units: 1ps` 这类）；
2. 看 lef 先看 **UNITS 段**（`DATABASE MICRONS 1000`）；
3. **写完约束自己反算一遍频率与周期**，对不上就是单位错了。
:::

## 动手：把换算练成条件反射 {#lab}

下面这台 Tcl 练习台，改数字就能算——建议把 0.06、0.19 都换成你自己的项目数字试一遍：

:::tclrun
# 时间：ns → ps（乘 1000）
set ns 0.052                                  ;# 报告里的一个延迟值（ns）
puts "$ns ns = [expr {$ns * 1000}] ps"        ;# 52 ps

# 时间：ps → ns（除 1000）
set ps 52                                     ;# 同一个值，用 ps 表示
puts "$ps ps = [expr {$ps / 1000.0}] ns"      ;# 0.052 ns

# 频率与周期：1 / 周期
puts "周期 1.25ns → 频率 [expr {1000.0 / 1.25}] MHz"   ;# 800 MHz
puts "周期 2.5ns  → 频率 [expr {1000.0 / 2.5}] MHz"    ;# 400 MHz

# 长度：um → nm
set w 0.06                                    ;# lef 里的线宽（um）
puts "线宽 $w um = [expr {$w * 1000}] nm"      ;# 60 nm

# 长度：pitch 0.19um，一层 100um 宽能排多少条线？
set pitch 0.19                                ;# 栅格间距（um）
puts "100um 能排 [expr {int(100 / $pitch)}] 条线"

# 面积：0.06um × 0.33um 的引脚矩形
puts "引脚面积 [expr {0.06 * 0.33}] um2"
:::

:::lab 三个反算题
不看答案，先自己算，再用练习台验：

1. 时序报告写 `slack = -0.032`，表头是 ns，换成 ps 是多少？
2. lef 里 `SIZE 2.4 BY 0.4`，单位 um，这个单元宽多少 nm、高多少 nm？
3. 目标频率 1.2GHz，周期该在 SDC 里写多少 ns？换算成 ps 是多少？

验收标准：三题全对，且能说出"为什么要先看文件单位再读数字"。
:::

:::quiz
VDD 与 VSS 分别对应逻辑电平的什么？| VDD 是供电电压、对应高电平（逻辑 1）；VSS 接地、对应低电平（逻辑 0）。
电阻与走线的粗细长短是什么关系？这条规律带来什么后果？| 越细越长电阻越大；导致长线/细线延迟大、setup 变差，所以关键信号走高层厚金属、少换层（via 也有电阻）。
电容在芯片里出现在哪些地方？对延迟什么影响？| 相邻线之间、线与地之间、晶体管栅极；要给电容充放电信号才能翻转，电容越大延迟越大。
动态功耗和漏功耗的来源分别是什么？| 动态功耗来自电容充放电与信号翻转（翻转越频繁、电容越大、电压越高越大）；漏功耗来自关断时电子逃逸，不翻转也在漏，先进工艺占比更高。
RC 提取在什么时候做？为什么 Place 阶段只是估算？| 在 CTS 之后跑 PT 时提取真实 R、C；Place 阶段还没有真实绕线，只能用简化模型估算。
1ns 等于多少 ps？0.06um 等于多少 nm？| 1ns = 1000ps；0.06um = 60nm。
为什么工艺说 nm、而工具和 lef 用 um？| 节点名是给人看的代际称呼（28nm/16nm/7nm），工具与库内部统一用 um 表达几何尺寸；所以读数字前必须先确认文件单位。
时序报告 WNS 显示 -52，怎么判断它是 ps 还是 ns？| 看报告表头单位（如 Units: 1ps），或结合周期量级反推；0.052ns 常见，-52ns 在正常周期下几乎不可能。
:::
