## 终端是什么，为什么后端离不开它 {#why}

:::goal 学完这一课，你能在任意一台 Linux 服务器上回答"我是谁、我在哪、这儿有什么"，并用绝对路径和相对路径各走一遍到目标目录。
:::

终端（Terminal）是一个**用打字代替点击**的窗口。你在里面输入一行命令，回车，机器执行，把结果打回给你。

它不是"黑底白字的老古董"，而是一个**接口**：你打的字交给一个叫 shell 的程序，shell 把它翻译成系统调用，再把结果排版好还给你。图形界面（GUI）只是在这个接口外面又包了一层按钮。

芯片行业为什么离不开它，有三个很硬的原因：

1. **服务器没有显示器**。你用的不是自己电脑，而是一台放在机房的机器，几十个人共用。你只能远程打字进去。
2. **流程要跑几个小时甚至几天**。图形界面一断线就全没了，命令行可以挂在后台、写到日志、第二天来看。
3. **一条命令胜过一百次点击**。批量改 500 个文件、循环跑 20 组参数，只有脚本能做到。

第三条最容易被低估。举个真实规模：一个 40nm SoC 的布线后报告有 30 万行（典型值），你要找出所有负 slack 的路径起点。用眼睛找是不可能的；用一条管道命令，0.3 秒。

:::term Terminal（终端） | 终端
你看到的那个窗口本身。它负责显示字符、接收键盘输入，本身不理解命令。真正干活的是窗口里跑的 shell。
:::

:::term Shell | 壳
终端里真正理解你命令的那个程序。它把 `ls` 翻译成系统调用，再把结果排版好给你看。Linux 上最常见的是 bash，芯片公司大量用 tcsh（第 5 课讲）。

"壳"这个名字很准确：它是包在操作系统内核外面的一层壳，你和内核之间的所有对话都经过它。
:::

:::term SSH (Secure Shell) | 安全外壳协议
从自己电脑远程登录服务器的方式，命令形式是 `ssh 用户名@服务器地址`。你以后每天上班的第一件事就是它——登录成功，提示符出现，一天的工作才开始。
:::

:::scene 入职第一天的操作
组长给你一个账号和一句话："工程在 `/home/proj/28nm/backend`，你先看看目录结构。"

你打开终端，`ssh` 登进去，然后：

```bash
# 作用：登录后确认自己在哪、工程在哪；在刚连上的服务器上执行
pwd                            # 先看自己站在哪，通常是 /home/你的工号
cd /home/proj/28nm/backend     # 用绝对路径进工程（不知道自己在哪时，绝对路径最稳）
ls                             # 看看这一层有什么
```

就这三个动作，决定了你接下来三个月能不能找到东西。

找不到目录的人，后面所有工具都跑不起来——因为 EDA 工具的脚本里全是相对路径，你站错一层，`source ./setup.tcl` 就报 `No such file or directory`，而报错不会告诉你"你站错地方了"。
:::

## 文件系统是一棵树 {#tree}

Linux 里所有东西都挂在一棵树上，树根叫 `/`（读作"根目录"）。用户的家目录、硬盘、U 盘、甚至设备，全都是这棵树上的一个节点。

注意这里的思维转换：Windows 有 C 盘、D 盘，是**多棵树**；Linux 只有**一棵树**，所谓"另一个盘"是挂到某个目录下面的（叫 mount，挂载）。所以 Linux 里没有"盘符"这个概念。

```
/                          ← 根，所有东西的起点
├── home/                  ← 所有用户的家
│   ├── weizhen/           ← 你的家目录，登录后就站在这
│   │   ├── proj/          ← 你自己建的工程
│   │   └── .bashrc        ← 隐藏文件（点开头就是隐藏）
│   └── lisi/
├── usr/                   ← 装软件的地方
│   ├── bin/               ← 大部分命令在这
│   └── synopsys/          ← EDA 工具安装目录
├── etc/                   ← 系统配置文件
├── tmp/                   ← 临时文件，重启可能被清空
└── proj/                  ← 有些公司把项目挂在这里
```

**树上的每个位置都有一条唯一的"路径"**，就像你家的地址。

:::term Path | 路径
从某个起点走到目标文件所经过的一串目录名。用 `/` 分隔。

- **绝对路径（absolute path）**：从根开始写，`/home/weizhen/proj`。无论你当前在哪，它都指向同一个地方——像"上海市浦东新区XX路1号"。
- **相对路径（relative path）**：从当前位置开始写，`proj/rtl`。你在不同目录下执行，指向的地方不一样——像"出门左转第二家"。
:::

四个必须背下来的符号：

| 符号 | 含义 | 例子 |
|---|---|---|
| `/` | 根目录，或者路径分隔符 | `cd /` 回到根 |
| `~` | 当前用户的家目录 | `cd ~` 等于 `cd /home/weizhen` |
| `.` | 当前目录 | `./run.sh` 运行当前目录下的脚本 |
| `..` | 上一级目录 | `cd ..` 退一层 |

还有一个容易混的点：`~` 只在**路径开头**才有特殊含义。`/home/~weizhen` 是错的，`/home/weizhen/~` 也是一个真名叫 `~` 的目录。`~weizhen`（不带斜杠）表示"用户 weizhen 的家目录"，等价于 `/home/weizhen`。

:::pitfall 路径写错，是新手第一个 90% 会犯的错
现象：

```
$ cd proj
-bash: cd: proj: No such file or directory
```

三种原因，按概率排：

1. 你不在自己以为的目录里。先 `pwd` 确认。
2. 目录名拼错，或者大小写不对（Linux 区分大小写，`Proj` ≠ `proj`，`RTL` ≠ `rtl`）。
3. 你用了相对路径，但起点不对。不确定就用**绝对路径**，从 `/` 开始写，最不容易错。

怎么查：`ls -d */` 列出当前层所有目录，看你要进的那个到底叫什么。**报错信息里的路径是"你以为的路径"，不是真实路径**——它只回显你输的东西。
:::

## 三件套：pwd、ls、cd {#three}

这三个命令你一天要敲几百遍。先把每个参数过一遍，再上手。

### pwd：我在哪

```bash
# 作用：打印当前工作目录；在任意目录下执行，不依赖任何文件
pwd                  # print working directory，输出形如 /home/weizhen/proj/pnr
pwd -P               # 显示"物理路径"：如果当前目录是符号链接，-P 解开它显示真实位置（真机才有区别）
```

`pwd` 是唯一"永远安全"的命令：它不改任何东西，只告诉你事实。**迷路时第一个敲它。**

### ls：这儿有什么

```bash
# 作用：列出目录内容；在任意目录下执行
ls                   # 只列名字，最常用
ls -l                # long format，长格式：权限、属主、大小、时间、名字
ls -a                # all，连隐藏文件（点开头）一起显示
ls -lh               # -h = human readable，把 4096 变成 4.0K、把 1820000 变成 1.8M
ls -lht              # -t = 按修改时间排序，最新在最上面（找"刚生成的文件"必用）
ls -lhtr             # -r = reverse，倒序：最旧的在最上面
ls -d */             # -d 只列目录本身，配 */ 就是"只看这一层有哪些子目录"
ls -R                # 递归列出所有层（目录深时会刷屏，先配合 head 用）
ls -F                # 给目录加 /、给可执行文件加 *，一眼分清类型
```

`ls -l` 的输出有七列，必须会读：

```
-rw-r--r--  1 weizhen pdteam   1820 Nov 22 10:12 run.tcl
│└┬┘└┬┘└┬┘  │   │       │      │        │         └── 文件名
│ │  │  │   │   │       │      │        └── 修改时间
│ │  │  │   │   │       │      └── 大小（字节）
│ │  │  │   │   │       └── 属组（group）
│ │  │  │   │   └── 属主（owner）
│ │  │  │   └── 硬链接数（目录一般是 2 起）
│ │  │  └── 其他人权限      ┐
│ │  └── 同组权限           ├ 第 3 课详细讲
│ └── 属主权限              ┘
└── 文件类型：- 普通文件、d 目录、l 符号链接
```

### cd：我要去哪

```bash
# 作用：切换当前目录；不产生输出，用 pwd 验证
cd /home/weizhen/proj    # 绝对路径：从根开始，任何时候都对
cd proj                  # 相对路径：进当前目录下的 proj
cd ..                    # 退一层
cd ../..                 # 退两层
cd ~                     # 回家目录（cd 后面什么都不加也一样）
cd -                     # 回到"上一次所在的目录"，两个目录来回切时特别好用（真机支持）
cd                       # 不带参数 = 回家
```

`cd -` 值得单独说：它会打印出你跳到了哪，比如 `~/backend_lab/soc/pnr`。你在 `pnr/` 和 `reports/` 之间反复横跳时，`cd -` 比敲两次完整路径快得多。**注意：本站的模拟终端不支持 `cd -`（会报 `cd: -: No such file or directory`），这条留到真机练。**

:::term Flag / Option（选项） | 选项
命令后面 `-l`、`-a` 这种带减号的叫选项，用来改变命令的行为。可以连写：`ls -lh` = `ls -l -h`。

短选项用单个减号、单个字母；长选项用两个减号、完整单词（`ls --all`）。**记不住就查 `--help`**。
:::

:::sandbox basic | 试：pwd、ls -l、cd backend_lab/soc/pnr、cd ..
:::

## 真实芯片工程的目录长什么样 {#real}

你可能以为工程目录是随便建的。事实上，**目录结构本身就是流程的一部分**——工具的输出放错地方，下一环就找不到输入。

一个典型的数字后端工程（各公司名字略有差异，骨架高度一致）：

```
proj/                          ← 项目根
├── rtl/                       ← 前端交付的 RTL（只读）
│   └── soc_top.v
├── dc/                        ← 综合：Design Compiler / Genus 的地盘
│   ├── scripts/               ← .tcl 脚本与 sdc 约束
│   ├── netlist/               ← 综合出来的门级网表 .v
│   └── reports/               ← 面积、时序、功耗报告
├── pnr/                       ← 布局布线（Place & Route）
│   ├── scripts/               ← floorplan / place / cts / route 各自的 tcl
│   ├── db/                    ← 工具数据库（Innovus 的 .enc、ICC2 的 .ndm）
│   ├── def/                   ← 版图交换格式，跨工具传数据用
│   └── reports/               ← 每一步的时序、DRC、拥塞报告
├── signoff/                   ← 签核：交付前的最后一道关
│   ├── sta/                   ← PrimeTime 的时序签核
│   └── pv/                    ← Calibre 的 DRC / LVS
├── pdk/                       ← 工艺库（Process Design Kit），公司统一发，只读
│   ├── lib/                   ← 时序库 .lib/.db
│   ├── lef/                   ← 物理抽象：每个单元多大、引脚在哪
│   └── tech/                  ← 工艺文件：层定义、DRC 规则
└── run/                       ← 跑批日志，按日期分目录
    └── 20261122_0930/
```

| 目录 | 全称 | 放什么 | 谁写 | 能改吗 |
|---|---|---|---|---|
| `rtl/` | Register Transfer Level | 人写的 Verilog | 前端 | **不能**，改了就和前端对不上账 |
| `dc/` | Design Compiler | 综合脚本、约束、网表 | 综合工程师 | 能，但改动要通知下游 |
| `pnr/` | Place and Route | 布局布线全过程的数据库和报告 | 后端 | 能，你主要在这里干活 |
| `signoff/` | Signoff | PT 时序签核、Calibre 物理验证 | STA / PV 工程师 | 只写结果，不改上游 |
| `pdk/` | Process Design Kit | 库文件、LEF、工艺规则 | 工艺厂 / CAD | **绝对不能**，全公司共用 |

三条纪律：

1. **每一层都分 `scripts / 输出 / reports`**。脚本和数据不混在一起，否则改脚本时容易误删结果。
2. **`rtl/` 和 `pdk/` 是只读的**。一个是和前端对账的基准，一个是全公司共用的库，改坏了整条产线都停。
3. **`run/` 按日期分**。`run/20261122_0930/` 这种命名让你三天后还能找回"当时到底跑了哪一版"。

:::term PDK (Process Design Kit) | 工艺设计套件
晶圆厂随工艺一起交付的一整套文件：器件模型、标准单元的时序库（.lib）、物理抽象（LEF）、DRC/LVS 规则。**没有 PDK 什么工具都跑不起来**，而且它按工艺节点和版本严格对应，用错版本的结果全部作废。
:::

:::term Netlist | 网表
综合之后得到的"门级连接表"：里面不再是你写的 `always` 块，而是一堆标准单元（与门、或门、触发器）以及它们之间的连线。文件名通常是 `.v`。

后端所有工作的起点就是这个网表——它已经确定了"用哪些门、怎么连"，后端只决定"放在哪"。
:::

这里有一次必须会算的账：**为什么 run/ 要定期清**。

假设一版 `pnr/` 数据库 6.5 GB（40nm SoC 的典型值），你每天存一版，30 天就是

`6.5 GB × 30 = 195 GB`

而公司给的个人配额通常是 200 GB。也就是说，**一个月的版本就能把你的空间吃满**，然后所有工具开始报 `No space left on device`。

所以真实做法是：只保留每天一版 + 关键节点（place 后、cts 后、route 后）各一版，其余压缩或删除。算一下：`6.5 × (30 + 3) = 214 GB` 还是超，于是要么压成 tar.gz（文本类数据库能压到 20%~30%），要么把 30 天缩到 14 天。

**"空间不够"不是运维问题，是你自己的工作习惯问题**，而它表现出来的样子往往是"工具莫名报错"。

:::lab 动手：搭一个属于你的工程骨架
**任务**：在真机（或 WSL）上建出上面这套目录，并用 `find` 确认层数。

```bash
# 作用：一次建出完整工程骨架；在自己的家目录下执行，不要在 pdk/ 或别人的目录里跑
cd ~                                       # 先回家，避免在别人的目录里建东西
mkdir -p myproj/{rtl,dc/{scripts,netlist,reports},pnr/{scripts,db,def,reports},signoff/{sta,pv},pdk,run}
# -p = parents：父目录不存在就自动建；{} 是 bash 的花括号展开，一条命令等于建 16 个目录
cd myproj                                  # 进入工程根
find . -type d | sort                      # 递归列出所有目录并排序，检查结构
find . -type d | wc -l                     # 数一共有多少个目录
```

预期输出（`find` 的顺序可能不同，`wc -l` 必须是 16）：

```
.
./dc
./dc/netlist
./dc/reports
./dc/scripts
./pdk
./pnr
./pnr/db
./pnr/def
./pnr/reports
./pnr/scripts
./rtl
./run
./signoff
./signoff/pv
./signoff/sta
16
```

**过关标准**：`wc -l` 输出 16；能指着其中任意三个目录说出"这里放什么、谁写、能不能改"。
:::

## 命令的通用规律 {#pattern}

Linux 命令基本都是一个模子：

```
命令名  [选项]  [参数]
ls      -lh      /home/weizhen
```

- **选项**以 `-` 开头，控制"怎么干"。
- **参数**是"对谁干"，通常是文件或目录。
- 选项在前、参数在后是惯例。`ls /home -lh` 大部分情况也能跑，但会让人困惑，别这么写。

**如何自己查用法**（比背参数重要得多）：

```bash
# 作用：查命令用法；任意目录可执行，不需要联网
ls --help            # 大部分 GNU 命令支持：打印简短用法，几十行，够用
ls --help | head -20 # 只看开头 20 行，先看它接什么参数
man ls               # 打开完整手册（真机才有；模拟终端不支持 man）
man ls | col -b      # 手册里有退格符，col -b 去掉控制字符再输出，方便重定向到文件
```

`man` 的用法：`空格` 翻页、`/关键字` 搜索、`q` 退出。**看 man 只看三处：SYNOPSIS（语法）、DESCRIPTION 前几段、EXAMPLES。**

五个救命键，比任何命令都值得先练熟：

| 按键 | 作用 | 什么时候用 |
|---|---|---|
| `Tab` | 自动补全命令名和文件名 | 每次敲路径都按，补不出来就是路径错了 |
| `↑` / `↓` | 翻历史命令 | 重复跑同一条长命令 |
| `Ctrl + C` | 强制中断当前命令 | 命令卡住、刷屏停不下来 |
| `Ctrl + L` | 清屏（等于 `clear`） | 屏幕太乱，但不想丢历史 |
| `Ctrl + A` / `Ctrl + E` | 光标跳到行首 / 行尾 | 长命令改开头或结尾的参数 |

:::tip 用 Tab 补全代替打字
`cd /home/wei<Tab>` 会自动补成 `cd /home/weizhen/`。补不出来，说明你记的路径是错的。

**养成每敲两三个字符就按一次 Tab 的习惯**，能消灭一大半路径错误。它的价值不在省打字，而在**它是一个实时校验器**：补全成功 = 路径存在，补全失败 = 现在就停下，而不是等回车后看报错。

`↑` 的进阶用法：`history | grep cts` 找出你三天前跑过的那条 CTS 命令，再用 `!编号` 重跑（真机支持）。
:::

:::term Environment Variable（环境变量） | 环境变量
shell 里存着的一组"键=值"，所有命令都能读到。最重要的两个是 `PATH`（去哪些目录找命令）和 `HOME`（家目录在哪）。`echo $PATH` 能看到一串用冒号分隔的目录——**你敲的命令就是在这串目录里挨个找的，找不到就报 `command not found`**。
:::

## 在终端里"找到自己"：三个问题的定位法 {#locate}

新手在终端里迷路，本质是三个问题没答案，而它们恰好对应三条命令：

| 问题 | 命令 | 输出怎么读 |
|---|---|---|
| 我是谁 | `whoami` | 输出用户名，决定你有没有权限改某个文件 |
| 我在哪 | `pwd` | 输出绝对路径，决定你的相对路径从哪算 |
| 这儿有什么 | `ls -l` | 输出七列，第一列决定你能不能进、能不能改 |

把这三个连起来用，就是一次完整的"定位"：

```bash
# 作用：迷路时的标准三步；在任意目录下执行
whoami                          # 我是 weizhen
pwd                             # 我在 /home/weizhen/proj/pnr/reports
ls -l ..                        # 上一层有什么？看到 db/ def/ scripts/ reports/ pnr.tcl
ls -l ../../rtl 2>/dev/null     # 再上两层的 rtl 在不在（2>/dev/null 是"错误的别看"，真机支持）
```

**手算一次路径换算**，这是最实用的一项技能。

当前在 `/home/wei/proj/pnr/reports`，要去 `/home/wei/proj/rtl`：

- 绝对路径：`/home/wei/proj/rtl`，18 个字符，任何时候都对。
- 相对路径：先退两级（`reports` → `pnr` → `proj`），再进 `rtl`，写成 `../../rtl`，10 个字符。

验算方法：`cd ../../rtl && pwd`，输出必须是 `/home/wei/proj/rtl`。**如果你算错了，`pwd` 会立刻告诉你错在哪**——这就是为什么每个 `cd` 后面都该跟一个 `pwd`。

什么时候用哪个？给三条判据：

1. **脚本里一律用绝对路径**。脚本可能被任何人从任何目录执行，相对路径必翻车。
2. **手动操作、且在工程内部移动，用相对路径**。短、快，而且换台机器（家目录名不同）也不用改。
3. **不确定时用绝对路径**。多打十几个字符，换零风险。

## 路径的六种写法与三个高频错误 {#path-forms}

同一个目标，至少有六种写法。以"从 `/home/wei/proj/pnr` 进入 `proj/rtl`"为例：

| 写法 | 命令 | 说明 |
|---|---|---|
| 绝对 | `cd /home/wei/proj/rtl` | 最稳，任何时候都对 |
| 家目录缩写 | `cd ~/proj/rtl` | 只在家目录下等价于绝对路径 |
| 同级跳转 | `cd ../rtl` | 先退到 `proj`，再进 `rtl` |
| 当前目录显式 | `cd ./../rtl` | `./` 就是当前目录，`./../rtl` 等价于 `../rtl`，写出来更明确 |
| 多级相对 | `cd ../../wei/proj/rtl` | 能跑但没必要，只用于演示"相对路径可以绕路" |
| 变量 | `cd $PROJ/rtl` | 工程里常见，`$PROJ` 由 setup 脚本 export |

三个高频错误，每个都对应一个具体现象：

**错误一：路径里有空格，没加引号。**

```bash
# 作用：演示空格路径的正确与错误写法；任意目录
cd /home/wei/my proj        # 错：shell 把它当成两个参数，报 "too many arguments"
cd "/home/wei/my proj"      # 对：引号把空格包住
cd /home/wei/my\ proj       # 也对：反斜杠转义空格
```

**错误二：把 Windows 路径直接搬过来。** `cd D:\proj\rtl` 在 Linux 里会变成 `cd D:projrtl`（反斜杠被当转义符吃掉），报 `No such file or directory`。Linux 只用 `/`。

**错误三：大小写。** `cd RTL` 报错而 `cd rtl` 正常，是因为 Linux 文件系统区分大小写。Windows 上不区分，所以这个习惯很难改——**看到"明明有这个目录"却进不去，先检查大小写**。

:::pitfall 到处相对路径，脚本换个人跑就崩
现象：你写的 `run.sh` 里是 `cd pnr && source ./scripts/cts.tcl`，你自己跑没问题，同事一跑报：

```
./scripts/cts.tcl: No such file or directory
```

原因：他是在 `~/` 下执行 `bash /home/wei/proj/run.sh` 的。**脚本的工作目录是"执行者当前所在目录"，不是你写脚本时所在的目录**，所以 `cd pnr` 失败（或进错了 pnr）。

解法：脚本开头先钉死自己的位置，再全部用绝对路径：

```bash
#!/bin/bash
# ↑ shebang 必须在第一行
# 作用：让脚本不依赖"从哪执行"；放在脚本最前面
set -e                                   # 任何一步失败立刻退出，别带着错往下跑
PROJ=/home/wei/proj                      # 工程根写成变量，换机器只改这一行
cd "$PROJ/pnr" || exit 1                 # 进不去就退出，并给出非零返回码
source "$PROJ/pnr/scripts/cts.tcl"       # 全部用绝对路径
```

判断依据：只要脚本里出现 `cd 相对路径` 或 `./xxx`，就要问自己"如果别人在别处执行会怎样"。
:::
