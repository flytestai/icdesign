这门课教什么，以及怎么学才不白学

Orientation

先花 30 分钟把地图看清楚：后端工程师一天在干什么、这门课 9 个阶段各自解决什么问题、网站上的每一课怎么用。

约 30 分钟 课表学时 2 导学学习路径环境
01

先说清楚：数字后端到底是干什么的

你写的 Verilog 代码，本质是一段逻辑描述——"如果 A 和 B 同时为 1，输出就是 1"。这段描述再正确，也只是一段文本，芯片工厂看不懂，也没法生产。

数字后端（Digital Backend，也叫物理设计 Physical Design）要做的，是把这段文本变成一张可以送到工厂去生产的版图：每个晶体管放在哪、哪根线走哪一层、多宽、多长。这张版图的文件格式叫 GDSII，工厂拿到它就能开模生产。

Physical Design物理设计点击看解释

把"逻辑上应该怎么连"变成"物理上真的放在哪、怎么连"。它不改变电路功能，只决定这块芯片跑多快、多大、多耗电、能不能造出来。行业里简称 PD。

打个比方：

阶段类比产出
前端设计写菜谱：先放油、再放盐RTL 代码
逻辑综合把菜谱翻译成"需要哪些食材、多少克"门级网表
数字后端决定厨房怎么摆、锅放哪、人走哪条道不撞GDSII 版图
制造照图纸施工晶圆

所以后端工程师不是"画图的"，而是在速度、面积、功耗、可制造性之间做取舍的人。这四个指标合称 PPA（Performance / Power / Area）。

工作场景 · 一天的真实工作

早上 9 点，打开终端，连上公司服务器。昨天跑完的布线报告出来了：有 37 个 DRC 违例（设计规则违例，意思是"这个形状工厂造不出来"）。

你先看违例分布——集中在某个宏单元周围，说明是布局时没给够通道。改布局参数，重跑局部布线，两小时后降到 3 个。剩下 3 个是电源线太窄，得回去改电源规划。

下午开会，前端问你："这条路径为什么差 0.2ns？"你打开时序报告，指出是时钟树偏斜（skew）太大。会后你调 CTS 参数。

这一整天你没有写一行 RTL，但芯片能不能按时流片，取决于你。

02

这门课的 9 个阶段，各自解决什么问题

课表一共 113 学时，分 9 个阶段。不要跳阶段，因为后一个阶段默认你会前一个阶段的东西。

小技巧

因为后端工具没有图形界面也能干活，而且服务器上根本没有鼠标给你用。你以后每天要做的事是：登录服务器 → 进入工程目录 → 改一个配置文件 → 敲一条命令 → 等 3 小时 → 看报告 → 再改。这一整套动作全部在终端里完成。

Linux 不熟的人，卡住的往往不是"不懂后端"，而是"文件找不到、路径写错了、权限不够"。这门课把这块单独抽出来讲透。

03

这个网站怎么用

每一课的结构是固定的，你按顺序走就行：

  1. 本章目标（蓝色框）：一句话告诉你这一章学完能得到什么。
  2. 工作场景（绿色框）：这件事在真实项目里什么时候用、谁在催你。先建立"为什么要学"的直觉。
  3. 概念讲解：尽量用生活里的类比，配图和表。
  4. 术语卡（灰边框，点一下展开）：英文原名 + 中文 + 白话解释。行业里就是用英文，改不了，但你可以记住它。
  5. 代码块：每一行都有注释。# 开头的灰色行就是注释，告诉你这行在干嘛、为什么要这么写。
  6. 动手（蓝色框）：照着敲一遍。一定要自己敲，不要复制粘贴，手指的记忆比眼睛可靠。
  7. 常见坑（橙色框）：别人踩过的错，连报错原文都给你，遇到了直接对。
  8. 自测：先自己想，再点开答案。答不上来就回去重读那一节。

页面左边是目录，右边滚动时左边会高亮当前章节。每章底部有"这一章我学完了"的勾选框，勾上会同步到服务器——换台电脑用同一个浏览器还能接着看。

常见坑 · 把"看过"当成"学过"

这是 0 基础学员最大的坑：视频看完了、文章读完了，一上手发现什么都不会。

判断标准很简单：能不能不看资料，从空目录开始把这件事做出来。 所以每一课的"动手"部分都有明确的过关标准，做到才算学完，做不到就再做一遍。

04

英文术语怎么记

后端领域的术语基本全是英文缩写，原因很现实：工具是英文的，报告是英文的，跟海外团队对接也是英文。你不需要"英语好"，你需要把 200 个高频词变成条件反射。

三个方法，按顺序用：

  1. 先记中文意思，再记英文缩写。比如先知道"时钟树偏斜"是什么，再记它叫 skew。
  2. 拆词。setup = 建立（数据要在时钟来之前站稳）；hold = 保持（时钟来了数据不能马上跑）。拆开就懂了。
  3. 在场景里记。术语卡都配了"什么时候会用到"，别孤立背单词。
Skew时钟偏斜点击看解释

同一个时钟信号，到达两个触发器的时间不一样，差值就叫 skew。就像广播体操的喇叭，操场这头听到"一二三四"比那头早 0.1 秒。
skew 太大会让某些路径的时序变差，但故意做出一点 skew 反而能救命（叫 useful skew）。第五阶段会详细讲。

05

你需要准备什么

  • 一台能上网的电脑（Windows / Mac 都行）。
  • 一个 SSH 客户端。Windows 用 MobaXterm 或 PowerShell 自带的 ssh，Mac 直接用终端。
  • 课程服务器账号（老师会发）。没有服务器也能学：阶段一、二的概念部分在任意 Linux 上都能练，装个虚拟机或用 WSL 都行。
动手动手：确认你的终端能用

打开终端（Windows 按 Win+R 输入 powershell 回车），敲：

bash
# 问系统：现在是谁在操作whoami # 问系统：当前在哪个目录pwd # 问系统：这个目录里有什么ls

预期输出类似：

shell
weizhen/home/weizhenDesktop  Documents  Downloads

三条命令分别回答三个最基础的问题：我是谁、我在哪、这儿有什么。后面所有操作都建立在这三个问题上。

如果 whoami 都报"命令不存在"，说明你打开的不是终端而是别的东西（比如记事本），回去重新开。

过关标准（都能做到才算学完）
  • 能说出"数字后端"和"前端设计"的分工差别
  • 知道 9 个阶段里哪三个阶段是工具实操、哪三个阶段是理论与签核
  • 在自己电脑上成功敲出 whoami、pwd、ls
  • 理解为什么这门课要先学 18 学时 Linux
自测：先自己想，再点开答案
数字后端交付给工厂的最终文件叫什么？
GDSII（版图文件）。工厂拿到它才能开模生产。
PPA 分别指什么？
Performance（性能/速度）、Power（功耗）、Area（面积）。后端工作的核心就是在三者之间取舍。
为什么"看过课程"不等于"学会"？
因为后端的技能是操作性的。判断标准是：不看资料，能不能从空目录把流程跑出来。
"skew" 中文是什么？为什么它不总是坏事？
时钟偏斜。同一时钟到达不同触发器的时间差。故意制造偏斜（useful skew）可以把紧张路径的时间"借"给别的路径，反而帮助收敛。
