ChipFinish 桌面实训：从最终流出到签核放行

ChipFinish and Signoff Handoff

用一套模拟交付包练习核对网表、流出版图与寄生，识别错版报告，处理豁免并决定能否放行。

预计学习 ≈19 分钟 课表学时 0 ChipFinish签核交付Metal Fill
01

领取任务：先冻结候选包，再看通过数

本章目标一句话目标
工作场景 · 交付前的收包复核

你接手教学顶层 desk_top。实现同事已经送来 R2 版候选包，物理验证和时序同事各发来一组报告。大家口头都说过了，但其中混有旧流出版图的报告和填充前的寄生。你的任务是把每份证据绑定到它真正检查过的输入，再决定能否交付。

本课是原创模拟桌面实训。文件名、指纹、工艺选项、坐标、规则和报告行均为纸面数据，不是任何商用工具的实测或真实工艺规格，也不提供实际流片文件。把交付包想成一张装箱单：箱子上都写着 R2，不代表箱内文件从同一个候选版本导出。表中 N8、O2 等是短教学指纹；实际交接应记录文件的完整 SHA-256 校验和以及生成来源。

交付物桌面数据接手人要核对什么
冻结实现数据库desk_r2.db，指纹 D2顶层 desk_top，父版本 R1，本轮仅调整局部走线并重生成填充
最终网表（final netlist）desk_final.v，指纹 N8单元、引脚、连接和导出选项；本例三个版本的逻辑网表字节相同
最终流出版图（stream-out）desk_r2.oas，指纹 O2顶层、层次、单位、填充状态、导出日志；本例只交 OASIS，若项目指定 GDSII 则绑定实际交付的 GDSII
流出层映射（layer map）map_v3，指纹 M3实现层及用途如何变为文件中的层号、数据类型；同时核对验证端读取配置
SPEF（标准寄生交换格式）r2_rcmax.spef / r2_rcmin.spef，指纹 P2H / P2L电阻电容来自什么几何，提取角、单位和网名是否与时序分析一致

工作中怎么用：实现负责人登记 D2 → O2 的流出链和 D2 → P2H/P2L 的提取链。本例寄生从与最终流出一致的含填充实现几何提取，不假设所有项目都直接从 OASIS 提取。移交前还要核对宏库、约束和提取配置等依赖的版本；报告归档员只收能追到实际输入的记录。

Final Netlist最终网表

记录交付设计的实例和连接。它回答「元件怎么接」，不是版图图形或时序报告。

SPEF标准寄生交换格式

记录由互连几何提取的寄生电阻、电容和网络名等数据。时序分析用它计算线的延迟和负载，不用它代替网表。

02

对齐层映射：形状导出了，不等于检查读到了

把流出层映射当成货架编号：同一金属上的信号图形和填充图形可以放在不同编号的格子里。版图查看器能显示某种颜色，只说明某处有图形，不说明规则读取了该数据类型。下表是 M3 的三条模拟映射，不是工艺厂规则；R2 的顶层、层次范围和统计口径固定，期望与实收都按顶层展开后的同一窗口计数。

实现用途OASIS 层号／数据类型预期轮廓数验证导入日志的实收轮廓数
M4 信号图形40/01212
M4 金属填充40/3055
V4 过孔切孔41/033

纸面抽验：三类合计应为 12 + 5 + 3 = 20；但总数相同仍不足够。如果实收变为 17/0/3，合计依然是 20，却有 5 个填充轮廓未出现在预期用途。先比较流出日志和实际版图里的层号／数据类型，再比较验证端导入统计，区分「导出放错编号」与「导入读错编号」。不靠调整规则阈值解决映射错误。

工作中怎么用：流出负责人交映射版本、顶层和层级范围；物理验证同事核对读入配置、单位、缺层告警和关键层计数，再查看规则是否执行。若窗口需坐标抽检，本例 1 DBU = 0.001 µm，顶层坐标 x=12400 DBU 应读成 12.400 µm；若在子单元核对，还要先做实例旋转、镜像和平移变换。对不上的统计先标记为输入无效，不能以「零标记」关闭问题。

Layer Map层映射

规定实现工具里的层及用途如何对应流出版图中的层号和数据类型。读入端也必须按批准的约定解释这些编号。

03

做填充前后对比：先配对条件，再算裕量

金属填充（metal fill）是在版图里加入用于满足密度等工艺要求的金属图形，不等于向标准单元行里补空白的 filler 单元。信号线即使没挪，邻近填充也可能改变耦合电容；影响取决于提取模型和填充几何，不能用一个固定增量外推全芯片。把 R0 → R1 当作对照实验：只加填充；R1 → R2 同时调了局部走线、重生成填充，因此不能把后者的全部变化归因于填充。

同一路径 u_launch/Q → u_capture/DR0 无填充R1 有填充R2 局部修线并重填充
RCmax 中示例互连段电阻（Ω）747469
同一受害网的对地电容（fF）202121
同一受害网的耦合电容总计（fF）698
FUNC/SS/RCmax setup 到达时间（ps）9781006991
同一 setup 要求时间（ps）100010001000
FUNC/FF/RCmin 同一端点的 hold 裕量（ps）+12+10+8

setup（建立时间）裕量等于要求时间减到达时间，三版分别为 +22、−6、+9 ps；R0 → R1 损失 28 ps，耦合电容增加 3 fF，即 50%。延迟取自本题给定数据，不是用电容比例推算的。hold（保持时间）需用快速角的最小延迟分析独立核对，不能拿 setup 公式或 RCmax 报告代替。表里只是一条路径，不代表全场景最差裕量。

工作中怎么用：寄生提取同事交付注明填充状态的两套角文件；时序同事先对齐模式、工艺角、约束、库、提取和串扰设置，再核查 SPEF 单位、网名映射与回注覆盖。最后比较相同路径诊断原因，并扫描所有约定场景和端点确认有没有其他路径变差。只做局部抽样不能代替最终时序回归。

04

填签核矩阵：分清哪一行能证明什么

DRC（设计规则检查）、LVS（版图与源网表一致性检查）和 LEC（逻辑等价检查）像三种不同的验收：图纸有没有违反尺寸，实物有没有按连接表接线，两个逻辑版本是否实现同一个功能。三者的输入和判据各不同，一个通过不能替另一个补证据。先建矩阵，再把文件实际输入写到每行，不要只有一列「PASS」。

检查／负责人此题要求绑定的输入合格条件与证据
LEC／逻辑验证批准功能参考 REF17、最终网表 N8、批准的 EQ2 比较配置等价；未匹配或未比较点处理闭合，并保留比较范围和配置记录
LVS／物理验证O2、认可的源网表 N8（按本题供电表示和宏模型）、M3、LVS4全量器件与连接匹配，无未处理短路和开路；保留运行日志与汇总
DRC／物理验证完整 O2、M3、规则版本 DRC6、选项 OPT2必做规则实际执行；原始标记全部清零或逐条匹配有效豁免；保留原始结果和处置清单
STA／时序N8、同候选的 P2H/P2L、约束 SDC5、库组 LIB2静态时序分析（STA）覆盖约定场景，回注范围匹配；本题两个视图 setup／hold 分别至少 +5 ps，无未约束目标端点

手算一个反例：如果功能网表对 REF17 等价，但版图中 u_capture/D 有 1 处断点，LEC 仍可能通过，LVS 必须报告不匹配；如果两根线未接触但间距小于规则，LVS 可以匹配而 DRC 失败。反过来，合法几何不保证连接正确。意图改变功能的 ECO 则应以获准的新功能参考做比较，不能为了让 LEC 变绿而随意更换参考。

工作中怎么用：各签核负责人填入实际校验值、运行标识、检查范围和结论，由放行负责人逐行核对。本例只指定四行，实际项目另有供电完整性或可靠性等要求时，应按批准范围加入矩阵；没有列出的项目不等于已经通过。

05

报告错版演练：先做输入验真，再读 PASS

报告标题相当于文件夹标签；日志中的实际输入指纹才是收据。R0 是填充前版本，R1 是上一轮含填充候选，其版图指纹为 O1。你收到下面四份摘要；其中的状态是教学记录，不是工具原生输出。各报告中未展开的配置，假定与上一节对应行一致。

收到的报告报告页显示从运行记录查到的实际输入你应填的状态
lec_okR1 / PASSREF17 + N8 + EQ2，比较覆盖完整可复用：本题 LEC 输入及配置完全相同，仍须登记原运行标识与复用依据
lvs_R2R2 / MATCHO1 + N8 + M3 + LVS4错版，不能用于 R2；用 O2 重跑全量 LVS
drc_R2R2 / 0O2 + M3 + DRC6 + OPT2，但该次只启用间距类规则覆盖不足；全量 DRC 配置需启用所有必做规则
sta_R2R2 / PASSN8 + R0 的 RCmax 寄生指纹 P0H；未查到 hold 视图错版且缺项；用 P2H/P2L 补齐两个视图
常见坑 · 新报告名盖住旧输入

现象：文件名写着 R2，LVS 也显示匹配。原因：运行请求取的是旧的 O1，输出文件名却由当前发布目录生成。查法：把实际读取的流出版图指纹同清单 O2 比对，查清调度输入后重跑，不重命名旧报告冒充新证据。

纸面计数：收到四份正向摘要，但当前只有 1 份可列作有效证据、3 行未闭合。旧版本字样不是自动判废条件：lec_ok 不读取版图，且其全部证明输入和比较范围在本题未变；相反，文件名更新也不能证明报告新版。凡无法还原输入的报告标「证据不足」，不要填通过。

工作中怎么用：接包人先看运行解析出的路径与工件校验值，再核对规则集、模式角和范围，最后才读结果。一旦发现输入混绑，保留错版报告及其运行号以便追查，单独开新运行号提交回归，不覆盖已有证据。

06

豁免与回归：原始标记保留，剩余阻断要归零

豁免不是删除报错，而是获授权后接受一个精确限定的标记。R1 的全量复核曾有两条原始标记：FILL.KEEP/宏边界/指纹 K9（12400,8000 DBU）和 M4.SPACE/信号线/指纹 S1。本例只有第一条允许申请；R2 调整信号走线并重新填充，必须比较新标记所对应的几何，不能把旧版坐标附近的形状全部排除。

全量回归阶段原始标记对本行版图有效的豁免待处理数
R1，版图 O1K9、S11：旧审批 W17 只匹配 O1 的 K92 − 1 = 1
R2，版图 O2，换版审批前K90：W17 不覆盖 O21 − 0 = 1
R2，版图 O2，换版审批后K91：新审批 W18 只匹配 O2 的 K91 − 1 = 0

W18 在本题由物理验证负责人复核、放行负责人批准，适用 desk_top / O2 / M3 / DRC6 / OPT2，并记录规则、位置、几何指纹、复核依据（同一宏边界、未改变的 K9 几何，有项目批准的宏边界例外）、审批人和仅限本候选的有效期。若出现第二条同规则标记，或 K9 附近几何变为另一指纹，均不能自动匹配。原始计数仍是 1，只能说「未处置标记 0」，不能写成「DRC 原始零标记」。

工作中怎么用：物理验证同事在 O2 上交全量 DRC/LVS 运行记录：必做规则均执行、S1 已消失、未新增其他标记、LVS 无短路或开路。时序同事用 P2H/P2L 完成回注，本题两视图的全量最差 setup 为 +9 ps、hold 为 +8 ps，无未约束目标端点，分别高于门槛 4 ps、3 ps。放行人另核准 LEC 复用和 W18，四行齐全才放行；缺任一项就冻结包、登记责任人和下次核验所需证据。

07

交卷：写出别人能复核的放行决定

用一张纸或一个文本编辑器完成，不需要商用工具。交卷时分「初收包」和「回归完成」两个时间点：同一个 O2 可以先被阻断，等配套的报告和审批都到齐后再获准。复核人应能从你的记录追到运行标识、实际工件、覆盖范围和审批，不必猜「修好了」究竟指哪一项；若之后产生 O3，不能把 O2 的整包结论直接复制过去。

可抄入放行单的教学运行标识：原逻辑比较 EQ-101（登记复用），重跑的 PV-204（全量 LVS）、PV-205（全量 DRC）、TM-212（两视图 STA）。时序证据须同时写 P2H/P2L 和 +9/+8 ps；只填 TM-212，审阅人无法从放行单判断是否确实用了最终寄生。

动手从四份摘要写一张放行单
  1. 抄写候选包五项交付物的指纹和两个寄生角；将第 5 节四份摘要逐行挂到签核矩阵，写出有效证据数和缺项。
  2. 计算填充前后及最终的 setup 裕量。将全量 DRC、LVS 和两视图 STA 的补齐结果登记到对应行；写明 W18 的约束与标记对账。
  3. 先写 HOLD（阻断），再填写条件满足后的 RELEASE（放行）和候选标识。过关线：得到 1/4 → 4/4 有效证据，写明 1 条原始标记、1 条获准、0 条待处理，并能指出一次再次阻断的触发条件。
自测
为什么两个报告都写 desk_top 和 R2，仍要查实际版图指纹？
顶层和标题不能识别旧几何；本题 LVS 实际用的是 O1，不能证明 O2 的连接正确。
窗口实收为 17/0/3，和预期同样共 20 个轮廓，能否通过映射核对？
不能。信号类多 5、填充类少 5，先分辨流出映射错还是验证端读入错。
R0、R1、R2 的 setup 裕量是多少？R0 → R1 耦合电容增幅是多少？
+22/−6/+9 ps；(9−6)÷6=50%，裕量损失 28 ps。
为什么旧标题的 LEC 可以继续用，而标为 R2 的 DRC 不能算通过？
LEC 的参考、网表、配置和比较范围都没变；DRC 虽读取 O2，却没有覆盖全部必做规则。
一条 K9 原始标记在 W18 批准前后分别留下几条待处理？
批准前 1、批准后 0；两次的原始标记数都是 1。若另有新标记，须单独处置。
若时序补跑的 hold 最差是 +4 ps，其他证据都合格，能否放行？
不能。它比本例 +5 ps 门槛少 1 ps，应保持阻断并开时序回归事项。
过关标准（都能做到才算学完）
  • 能从报告的实际输入而不是标题判断它对应哪个候选包。
  • 能在填充前后算出裕量变化，并区分单路径诊断与全场景签核。
  • 能用「输入、检查范围、结论、例外」四项说明为什么 O2 最终可以放行，或指出哪项会重新阻断。
