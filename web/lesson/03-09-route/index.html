Route：三种引擎、短路开路与串扰

Routing

全局布线、特殊布线、详细布线各自解决什么；短路与开路怎么从报告读到版图；天线效应与串扰的成因和修法。附原始资料对照。

预计学习 ≈17 分钟 课表学时 4 Innovus40nm项目实操Route
01

一句话先记住：布线不是"把线连上"

前面几步，单元的位置是摆出来的；到这一步，单元之间的线是画出来的。画线听起来比摆东西简单，实际上是整条流程里约束最多的一步：

  • 线要连对（连错就是短路，没连上就是开路）；
  • 线要走得下（轨道不够就会溢出，绕远路就会时序变差）；
  • 线要守制造规则（太细、太近、太薄都会做不出来）；
  • 线不能互相干扰（平行太长的两根线会串扰）；
  • 线还要经得起制造过程（长线会积累电荷，打坏栅极）。

一样没做到，后面签核就过不去。所以这门课不讲"怎么点那个按钮"，讲每一步在防什么。

Route布线

把网表里"谁连谁"的逻辑关系，变成版图里"走上哪一层、走哪条轨道、在哪里打过孔"的物理连线。资料里「走线」「绕线」都是指这件事。
同义词提醒：DRC（设计规则检查）有时被口语说成「规则检查」；DRV（设计规则违例）有时被笼统说成「违例」。两者不同——DRC 是检查动作，DRV 是检查出来的问题项。

02

三种布线引擎：先分清谁干什么

原始资料列了三个名字：global route、sroute、nanoroute。很多人记成"三个都能布线，随便用一个"，这是最常见的误解——它们根本不是同一件事的三个选项，而是流水线上的三个工位。

引擎干什么输出什么什么时候跑
Global Route（全局布线）只做规划：估算每条网大致走哪个区域、需要几条轨道一张"需求 vs 容量"的分配图，不产生真实几何Floorplan / Place 之后，先看拥塞
sroute（special route）布特殊网：电源、地、时钟主干电源网格、ring、stripe、followpinPowerPlan 之后，Place 前后都可跑
NanoRoute（详细布线）真正画几何：具体到哪一层、哪条 track、哪个 via可提取寄生的实际版图Place 和 CTS 之后

为什么必须分三步？ 想象在一座城市里送快递：

  • 全局布线 = 规划"每个片区的货从哪条主干道走"，只算流量，不画具体车道；
  • 详细布线 = 真正把车开上路，遇到单行道、限高、堵点要绕；
  • 特殊布线 = 修的是水电管网，跟快递车道是两套系统，但会抢地下空间。

如果直接跳到详细布线，工具没有全局的流量估计，就会一头扎进局部最优，最后到处绕不出去——这就是"必须先跑 global route 看拥塞"的原因。

常见坑 · 把 sroute 当成信号布线

sroute 只处理特殊网（电源/地/时钟主干），它按"宽线 + 规则阵列"的方式布，追求的是载流能力和连通，不管时序。信号网必须交给 NanoRoute。混用会导致电源网时序被当成信号网优化，或者信号网被按电源规则布成一大片金属，直接短路。

03

全局布线：在动手之前先看"路够不够"

全局布线阶段最该看的是拥塞图（congestion map），不是"跑完了没有"。

拥塞图的读法只有一句：红色 = 这个区域需要的轨道数超过可用轨道数。

但要注意三个容易看错的地方：

  1. 分母是轨道，不是面积。同一个区域，密度 70% 不一定拥塞，密度 50% 也可能拥塞——取决于这个方向上有几条可用 track。
  2. 要分方向看。横向拥塞和纵向拥塞是两回事，只压一个方向解决不了问题。
  3. 要看层。M2 拥塞但 M5 有余量，说明问题不在总量，在"没往上层引"。
小技巧

调整 floorplan 或 place 之前，先把当前拥塞图的层、方向、图例阈值记下来。改完之后用同样的层、同样的图例再比一次。换了图例阈值的两张图，颜色没法直接对比。

04

详细布线的两个硬指标：短路与开路

原始资料里有一句话很实在："一般 short 的数量在 2 位数算是比较好的结果"。

这句话没有解释为什么。道理是这样：

一块中等规模的芯片，网的数量是十万到百万级，走线数以百万计。工具在几百万次决策里出现几十次失误，是正常工程现实；上千个 short 才是异常，说明不是"个别决策错了"，而是系统性问题——通常是 floorplan 留的通道不够，或者 place 把单元堆在了错误的位置。

短路（short）：两根不该连的线连上了

排查顺序按"聚集程度"走，不要一个一个看：

现象常见根因修法
short 集中在 top 边宏的出 pin 和 port 抢同一片区域；或 stdcell 走线和 port 打架在边界打 partial blockage（局部禁布区），大小和深度看 short 的深度；如果是宏，加宽 channel
short 集中在 宏与宏之间通道太窄，两侧 pin 的出线在中间撞上拉开宏间距，或在 channel 中间打 blockage
short 出现在 宏的拐角拐角处可用轨道被切成碎片打 blockage、加 keepout margin，或直接调 floorplan
常见坑 · blockage 忘了删

blockage 是临时脚手架：它帮你把单元推开、把通道让出来，但它本身也占地方。必须在 route 之前删掉，否则工具会把那里当成永久禁布区，布线时绕不过去，反而产生新的开路。这是新手最常犯的错之一。

开路（open）：该连的没连上

开路比 short 更隐蔽，因为版图上"看起来是连着的"。

典型原因是两层金属在屏幕上重叠，但没有合法过孔。投影重叠不等于电气连接——必须有满足包围（enclosure）和间距（spacing）规则的 via，才算真的连上。

所以查开路的方法不是放大看图，而是：

  1. 从报告拿到断点的坐标和层；
  2. 在版图里定位到那个坐标，确认两层图形是否真的重叠；
  3. 检查那里有没有 via，via 是否满足 DRC；
  4. 如果没 via，看是工具没打，还是打了但被 DRC 删了。
一个反直觉的事实

连通性检查和 DRC 检查是两套独立判据。DRC 全绿不代表连对了（可能少打了一个 via 但没违反规则）；连通性全通也不代表能制造（可能 via 间距不够）。两个都要过。

05

天线效应：制造过程留下的伤

原始资料只有一句："Antenna 天线效应，也可以插 buf 修复，还有增加 shape 面积。"

这句话省略了最重要的部分：为什么会发生。

芯片制造是一层一层往上长金属的。每长完一层，要对整片 wafer 做一次等离子刻蚀。刻蚀时，已经成形但还没接到任何扩散区的长金属线，会像天线一样收集电荷。电荷越积越多，电压越来越高，最后击穿它所连接的栅极氧化层——栅极就打坏了。

关键点在"还没接到扩散区"：如果这条线上连着一个晶体管的源/漏（扩散区），电荷有地方泄放；只连到栅极（纯绝缘）就会积累。

所以修法的逻辑都是"给它一条泄放路径"：

修法原理代价
插天线二极管反向二极管在正常电压下不导通，电荷积累到一定电压时击穿泄放增加面积、增加结电容（可能影响时序）
跳层（跳线）在某一层断开，改走更高层，缩短单层累积长度可能增加 via、影响布线资源
加大 shape 面积增大金属面积降低电荷密度占面积，可能加剧拥塞
插 buffer把长线切成几段，每段累积量降低增加延迟和功耗，慎用

原始资料给的两条命令对应自动修复：

tcl
setNanoRouteMode -drouteFixAntenna true      ;# 详细布线时自动修天线setNanoRouteMode -routeInsertAntennaDiode true ;# 允许插入天线二极管
常见坑 · 看到长线就加二极管

天线违规有具体的比率判据（金属面积 / 栅面积），不是"线长就违规"。盲目加二极管会引入额外电容，把本来通过的时序搞崩。正确顺序是：先看报告里哪条网、哪个栅、比率多少，再决定用哪种修法。

06

串扰：工作时两根线的互相干扰

原始资料的描述是："两根走线较长，且并行时，容易引起串扰。"

这句话是对的，但只说了一半。串扰有两个必要条件，缺一不可：

  1. 两根线在物理上靠得近（耦合电容大）；
  2. 其中一根在翻转（有电压变化 dv/dt）。

只有耦合没有翻转，不会有干扰；只有翻转没有耦合，也不会。所以修串扰有两个方向——减小耦合，或者错开翻转时间。

手段做法适用
加间距（spacing）把两根线拉开，耦合电容随距离下降局部、少量网
加屏蔽（shielding）在受害网两侧沿 track 打 VSS 线关键时钟、敏感信号
降低驱动/加 buffer改变边沿斜率，减小 dv/dt施扰网驱动过强时
时序错开调整路径延迟，避免同时翻转有用但难控
换层让两根线不在相邻层重叠布线资源允许时

串扰的两个后果要分清：

  • 毛刺（glitch）：受害线上出现一个不该有的电压跳变，可能让下游触发器误触发。这个是功能问题。
  • 延迟变化（delay shift）：受害线变慢或变快，影响时序。这个是时序问题。

两者要用不同报告查，修法也不同。毛刺看噪声分析（noise），延迟看带 SI 的时序分析。

07

布线之后还没完：OptRoute 在做什么

Route 跑完，线是连上了，但通常不是最优的：

  • 为了让所有线都连上，工具可能绕了远路 → 时序变差；
  • 有些线为了避让走了很窄的间距 → SI 风险；
  • 局部 DRC 违例可能只是勉强通过。

OptRoute 就是在已经连通的版图上做二次优化，不改变连接关系，只改走线路径和单元位置。

细节见下一课 OptRoute，以及参考专题 Route 诊断实训。

动手：不用工具也能练的三件事

动手纸面排查：一条"看起来连上了"的网

场景：报告说 u_ctrl/busy_q/D 这条网开路。你把版图放大到该坐标，看到 M3（驱动侧）和 M2（负载侧）两块金属在屏幕上明显重叠。实例端点和网络归属都与网表一致。

请回答：

  1. 屏幕上重叠，为什么还会报开路？
  2. 你要去查什么，才能确认是"没打 via"还是"via 打了但不合法"？
  3. 如果你补了一个 via，接下来必须再查哪两项？（提示：不止连通性）
自测
global route、sroute、nanoroute 三者的分工分别是什么？
global route 只做流量规划不画几何；sroute 布电源地等特殊网；nanoroute 画信号线的真实几何。
为什么 short 数量上千就说明是系统性问题？
少量 short 属于百万级决策中的正常失误；上千个说明 floorplan 通道或 place 位置存在结构性缺陷，不是个别决策错误。
两层金属投影重叠，为什么仍可能报 open？
投影重叠只是视觉重叠，必须有满足包围和间距规则的合法 via 才算电气连接。
天线效应为什么只发生在连到栅极的长线上？
连到扩散区的线有电荷泄放路径；只连栅极时电荷无处泄放，会积累到击穿栅氧化层。
串扰发生的两个必要条件是什么？
两根线物理耦合足够大，且其中至少一根正在翻转（有 dv/dt）。
blockage 为什么必须在 route 之前删除？
它只是临时推开单元的手段，留着会被当成永久禁布区，导致布线绕不出去产生开路。
