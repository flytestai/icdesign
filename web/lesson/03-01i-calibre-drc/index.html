Calibre DRC：手修与复查

Calibre DRC Debugging

从签核标记追到版图几何，排查间距、filler 短路和 ECO 后成批短路，并验证修复。

预计学习 ≈14 分钟 课表学时 0 CalibreInnovusDRCLVSECO
01

从 Marker 定位到可编辑对象

这一讲在流程里的位置

Calibre DRC · 承接布线与填充。布线完成、Filler 加完之后才做全量 DRC。本讲从 marker 定位到可编辑对象，并区分"局部复核"和"全量签核"。

课程来源

本讲是网站原创专题；钉钉目录第 13 项仅用于确定主题与顺序，不转载原文、项目参数或图片。相关基础可另看上传 Word 整理的 ECO 短路、开路和 DRC。

Calibre DRC 用规则集检查版图几何；LVS 把从版图提取出的器件与连接同源网表比较。DRC 无标记并不能证明接线正确。本讲的输入包括冻结的 Innovus 实现数据库、从该版本流出的 GDS 或 OASIS、规则适用的工艺选项、流出层映射、签核 DRC/LVS 规则集和同版本源网表。标记摘录、坐标、名称和尺寸都是原创合成示例，不是工艺规则或 Calibre 实测。

记录规则、坐标、层、实例层次和次数。查看结果时核对顶层和版图版本；坐标先确认单位和原点，再考虑实例的旋转、镜像及层映射。Marker 指示违规，不一定正好盖在可编辑对象上。确认图形来自本设计顶层走线、邻接实例还是库／宏内部，只有第一种可用本次局部连线调整解决；另外两种先核对实例布置和库版本，不直接改库版图。

02

区分 VIA 和 M1 的间距规则

同时出现过孔切孔间距和 M1 金属间距时，分别找到各自两处被测几何；过孔被金属覆盖不足是包围规则，不是间距。比如挪动过孔可增加切孔距离，却可能使 M1 出现不够包围或更短的金属边。先按规则识别测的是平行边、角或线端，再选改动对象、方向与增量。几何正面看上去更宽，不代表规则关心的方向一定改善。

本例 M1 有两块属于不同网络的顶层图形，标记范围内还包含 VIA1；报告规则却是 M1 对 M1，所以不按“标记里有过孔就挪过孔”处理。确认信号线的固定过孔与引脚不在要移动的一小段上，才能只调整平行段和必要的接入折线。若位于中间层，还要检查移动后邻线以及新折角、过孔和边界有没有引入其他规则问题。

03

排查 Filler 与 ecoRoute 后的短路

Filler 填补标准单元行空隙，某些类型还延续电源轨。短路靠近 filler 不等于 filler 是根因：先核对供电域、物理邻接、相邻单元朝向、电源网绑定和 filler 类型，用提取路径确认真正的误连点。若 ecoRoute 后突然新增一批短路，先保留修前后快照，按网对、位置或重复实例归并；选一个代表点在副本追踪新增形状、过孔、供电连接或规则变化。确认同源后再做针对性修复或回退，不要批量删除单元或过孔来降低计数。

在本次学习案例里，供电连通和 LVS 的短路计数都是零；这里不顺带改 filler。若额外看见供电短路，应另立问题、单独追踪误连路径。几何间距通过只是一个检查的结果，不能用来注销供电误连。

04

固定签核基线：先确认读的是同一版图

开始前把实现数据库版本、流出文件、层映射与运行配置记录在同一清单；对 LVS 另外绑定当前源网表、顶层和工艺规则中的器件、供电选项。绝不把不同来源或不同版本的 DRC 与 LVS 结果合成一个“全绿”结论。下面的 DEMO 标识和数值都是教学用；实务不能用它们替代工艺方批准的签核规则。

text
合成基线清单与标记（非 runset，非命令）implementation DB=top_r12; stream=top_r12.oas; top=demo_topstream layer map=DEMO_MAP_A; process option=DEMO_6MDRC deck=DEMO_DRC_R4; LVS deck=DEMO_LVS_R7LVS source=top_r12_src.v; baseline LVS=matchDRC M1.SPACE.PAIR count=1; bbox=(78.100,44.300)-(78.390,44.510) ummeasured metal edge gap=0.044 um; required>=0.052 umshapes: top/n_req (editable signal M1), top/VSS (fixed M1 rail)

展开顶层标记后，沿边读取实际最短距离 0.044 µm，低于规则限值 0.052 µm。根因是 n_req 的短平行段离固定 VSS 轨过近，两者没有接触，因此基线 LVS 匹配并不矛盾。先确认相邻区域有空轨，再决定在副本中只移动该小段；不挪供电轨、不改库图形，也不更换规则或网表来得到更少标记。

05

只调信号线，先做局部复核

把 n_req 的平行段调整到合法轨道，保留两端接入。修后实测最短距离为 0.061 µm；走线有一个小折弯，检查其最小面积、线端条件、越过邻网以及信号的逻辑归属。先在实现工具复查受影响区域的几何和连通，再从修后数据库重新流出，使用同版本签核规则在项目支持的局部模式检查违规附近并包含足够的邻域，而非只裁下标记框。需要考虑派生层和相邻实例；对于依赖全局上下文、不能局部复现的规则，不把裁窗零结果当成通过。

06

从局部排错推到全量签核

局部复查证明原坐标的根因处理有效，却验证不了整片密度等依赖全局的规则，也不能替代完整连接对比。最终用 top_r13 对应的完整流出版图，以约定顶层、工艺选项与批准的 DRC/LVS 规则集执行全量签核；本例只是布线几何改动，修前后源逻辑网表内容一致，仍要复核该源是修后版认可的参考。对照每条规则的计数与位置清单，确认没有“旧标记消失、别处出现同类标记”。

text
合成全量验收摘要（非命令）DRC full deck:  M1.SPACE.PAIR 1 -> 0; other new violations=0LVS full run:  device/net counts match source; shorts=0; opens=0export top=demo_top; final source logical content unchanged

在真实项目中还须检查运行日志、批准的豁免范围与其他交付检查；若移动线路可能影响时序，另按项目约定重提寄生，并复查受影响的时序或噪声。不应把“局部清零”或“某个版本 LVS 通过”写成当前交付包的签核结论。

运行结束后先看进程与汇总日志，确认目标层都读入且对应检查没有被跳过。整个版图从多处报错突然变为零时，先查顶层名、版图范围、版图单位和检查筛选条件，而不是把异常结果算作修复收益。对于经过批准的豁免，保留规则、标记、版本和审批依据，不能把坐标附近的新几何自动归入修前的豁免。

07

DRC 修复的复查与回退清单

  • 修前后分别留存实现数据库、流出文件、层映射、顶层与运行配置，连同日志、标记位置和 LVS 结果做版本配对。
  • 遇到新短路、新开路、原标记不消失、全量规则失败或版本配对不明，撤销本次局部改动，恢复同套基线输入并复现原报告，再判断该试另一个位置还是先修验证环境。
  • 只保存了局部签核的结果时标记为待验，不要放行；全量验证完成后再关闭问题并记录修复涉及的形状及网络。

09

报告清零，但填充层根本没被规则读到

本案的编号、几何和规则都是原创模拟数据。收尾工程师没有动版图，前后均读取同一个 OAS-17，却看到某个边界邻域的间距标记由 2 变成 0。该规则核对 M5 信号与填充之间的间距。版图独立读回显示，12 个填充轮廓都在批准的 50/32；对比两次运行发现，最后一次验证导入配置却把填充输入指到了没有图形的 50/31。查看器仍能显示 50/32，不能证明它参与了检查。

名单中两个填充图形到最近信号边的距离分别是 0.041 µm、0.046 µm，本题规则要求 ≥0.050 µm。写出各差多少，并判断该改流出层映射、验证端读入配置，还是直接改信号线。然后列出从找回标记到关闭问题的证据。

核对：两处分别差 0.009 µm 和 0.004 µm。只恢复批准的验证端读入配置，用不变的 OAS-17 重现两条旧标记，证明不是新几何造成的变化。逐条定位受影响的填充、信号和边界上下文，再按项目允许方式修复并重流出；局部窗口复查只能证明那两点。最终还要在修后版图使用批准配置做全量回归，特别是填充重生成可能影响的密度规则，并补齐项目要求的 LVS 等检查。不能把缺层导致的 0 当作修复或豁免。
