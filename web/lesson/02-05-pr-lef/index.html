LEF 详解：tech lef 与 cell lef 里到底写了什么

Inside LEF: Technology and Cell Libraries

打开 lef 文件看真东西：tech lef 里的版本、单位、金属层定义、最小宽度与间距、pitch、走线方向、via 定义与电阻、obs 遮挡块；cell lef 里的单元尺寸与引脚。最后讲清 lef 与 def 的分工，以及工艺从 40nm 走到 3nm 时规则为什么越来越难。

约 30 分钟 课表学时 2 LEF工艺库金属层viapitchDRC单元库
01

为什么必须读懂 lef

本章目标能在 lef 里找到 MACRO / PIN / LAYER / VIA / SITE 这几类关键段，能说出 tech lef 与 cell lef 各管什么，能解释 pitch、最小间距、preferred direction 是什么意思。

工具摆放和绕线时做的每个决定，背后都是 lef 里的规则在约束它。你看到的这些现象，原因都在 lef：

  • 为什么这条线要绕这么远？——因为那一层禁止走线，或者间距不够；
  • 为什么这个单元只能朝某个方向摆？——因为它的 pin 在某一边，反过来接不上；
  • 为什么 DRC 报"间距违规"？——因为间距规则就写在 tech lef 里。

所以 lef 不是"配好了就不用管"的文件，它是你判断"能不能这么干"的依据。

02

tech lef：工艺的规则书

tech lef工艺 LEF

只描述工艺、不含具体设计的 lef：能用哪些金属层、每层的宽度/间距/pitch 规则、via 的定义与电阻、走线方向。一个工艺一份，所有用这个工艺的项目共用。

文档列了 tech lef 里必须看懂的五块内容，我们一块一块看：

1. 版本与单位

文件开头两行最容易被跳过，但它决定了后面所有数字的含义：

text
VERSION 5.8 ;                      # lef 语法版本，工具会校验UNITS  DATABASE MICRONS 1000 ;          # 数据库单位：1 微米 = 1000 个内部单位（即 1nm）END UNITS

DATABASE MICRONS 1000 意味着文件里写的长度都是"整数个内部单位"，1000 个单位 = 1μm。所以看到 WIDTH 0.14 ; 和看到 WIDTH 140 ; 可能是同一件事，取决于单位——读 lef 前先确认单位，否则会把 0.14μm 当成 140μm。

2. 金属层定义：层数、宽度、间距

metal layer金属层

芯片里的走线层，从下到上编号（M0、M1、M2…）。总层数取决于工艺：40nm 常见 1P9M 左右（9 层金属），先进工艺能到 15 层以上。每一层都是独立的，宽度、间距、方向各不相同。

这张剖面图值得多看几眼，它解释了三件事：

  1. 为什么下层细、上层粗：M1/M2 线宽 0.024~0.032μm 量级，到 M8/M9 变成 0.36μm——粗线电阻小，适合走长线和电源；
  2. via 是一层"竖井"：V1 连 M1 与 M2，V2 连 M2 与 M3……图中每层都标了 via 的尺寸与间距规则；
  3. 1P9M 的含义：1 层 poly（多晶硅）+ 9 层金属。你在 lef 里数 LAYER 段就能对上。

一层金属在 lef 里长这样：

text
LAYER M2  TYPE ROUTING ;                   # 这一层用来走线（不是 cut/via 层）  DIRECTION HORIZONTAL ;           # 首选走线方向：水平（M1 常为垂直，奇偶层交替）  WIDTH 0.07 ;                     # 默认线宽 0.07μm  PITCH 0.14 ;                     # 线间距栅格：相邻两条线的中心距  SPACING 0.07 ;                   # 最小间距：两条线边缘至少隔 0.07μm  SPACING 0.6 RANGE 10 100000 ;    # 特殊规则：长度在 10~100000 之间时，间距要 0.6END M2

重点看三个词：

  • WIDTH（宽度）：这条线最细能画多细。越细电阻越大、越慢；
  • SPACING（间距）：两条线之间至少要留多少空隙，留不够就是 DRC 违规；
  • 特殊区间规则（RANGE 10 100000）：长线更容易受干扰/更容易短路，所以长度达到一定值后间距要求会更严。这一类"分段规则"是先进工艺里最坑人的地方——你按默认间距绕的线，一旦长度超过阈值就变成违规。
pitch栅格间距

同层相邻两条线的中心到中心距离（文档的说法：从 M1 最左侧到另一条 M1 最左侧的距离）。它是布线器的最小步进单位——所有线的位置都落在 pitch 的整数倍上，所以 pitch 越小，能塞的线越多。

DRC设计规则检查

Design Rule Check。检查设计里有没有违反工艺规则的地方（间距不够、宽度不足、via 缺失、密度不够等）。DRC 不通过就不能流片，所以它贯穿 PR 全程，route 之后最集中。

3. 走线方向：横纵交替

DIRECTION HORIZONTAL / VERTICAL 规定了这一层的首选走线方向。工艺厂通常让相邻层交替，原因很实际：同方向的线在同一层可以平行排布，密度最高；换方向时用 via 下到另一层。这就像立交桥——同一层只能一个方向，两个方向要靠上下层。

小技巧
  • horizontal = 横向（左右）；
  • vertical = 纵向（上下）。

28nm 课上给的例子是 M1 horizontal（横向）、M2 vertical（纵向），两者交错成网格。但要注意：第一层到底是横还是竖，不同工艺不一样（有的从竖开起），从 M1 之后才严格交替，不会出现连续两层同向。所以判断方向只能看 lef 里的 DIRECTION，不能凭记忆。

常见坑 · 把"memory 的实例名 M1"当成"金属层 M1"

现象：查看某个 memory 的信息时看到"M1"，以为在说金属层。

真相：在 floorplan 语境里，M1、M2 常常是 memory 的实例名（memory 1、memory 2），和金属层 M1/M2 完全是两回事。文档里那段"Memory 名称通常标记为 M1、要关注它的宽和高、多少比特"说的就是这个。

分清的办法：看上下文——带"层/走线/via"的是金属层，带"宽高/比特/摆放"的是 memory 实例。

4. via：连接不同金属层

via通孔

连接相邻两层金属的"竖井"。M1 通过 via1 连到 M2，M2 通过 via2 连到 M3。它有自己的尺寸、包围（enclosure）规则和电阻。

text
VIA VIA12 DEFAULT  LAYER M1 ;    RECT -0.03 -0.03 0.03 0.03 ;   # 下层金属上的接触矩形  LAYER VIA1 ;    RECT -0.02 -0.02 0.02 0.02 ;   # 孔本身的尺寸  LAYER M2 ;    RECT -0.03 -0.03 0.03 0.03 ;   # 上层金属上的接触矩形END VIA12

via 有两个关键点新人常忽略：

  1. via 有电阻：一个 via 的电阻可能几十欧。一段长线要换层几次，串联起来的 via 电阻会实实在在拖慢信号——所以"能少换层就少换层"。
  2. via 要成组打：单个 via 电流能力有限（电迁移），电源线上通常打 via 阵列。

5. obs：遮挡块

OBS（obstruction）是禁止布线区域。有的公司把 macro 上方/周围的禁布规则直接写在 lef 的 obs 里，工具读进来就自动避开；有的写在 tech lef 的全局规则里。

text
MACRO SRAM_1024X32  CLASS BLOCK ;                    # 这是个 macro（block 类）  SIZE 120.0 BY 80.0 ;             # 尺寸 120μm × 80μm  OBS    LAYER M1 RECT 0 0 120 80 ;     # M1 整块禁止走线（macro 内部不许穿线）    LAYER M2 RECT 0 0 120 80 ;  ENDEND SRAM_1024X32

这条规则解释了上一课的一个问题：为什么 mem 摆错会毁掉布线——它的 obs 占掉了两层金属的整片区域，你把它摆在通道中间，等于把通道堵死。

03

cell lef：每个单元长什么样

cell lef单元 LEF

描述每个标准单元/宏单元：宽高（SIZE）、有几个 pin、pin 的名字与方向（input/output/inout）、pin 的形状与位置、单元类别（CORE / BLOCK）。

图里这几行值得逐条对号：

行含义
MACRO RSDFFARX1_LVT单元名：带复位（R）的扫描 DFF，LVT = 低阈值电压（快，但漏电大）
CLASS CORE这是个标准单元（不是 block）
SOURCE USER单元来源标记（用户自定义/库生成），工具不在意，人看的
SIZE 10.792 BY 1.672宽 10.792μm、高 1.672μm（前面是宽/X，后面是高/Y）
SYMMETRY X Y允许沿 X 轴、Y 轴镜像——这就是"单元可以翻转摆放"的合法依据
SITE unit它占一个 site（行内最小栅格倍数），工具按 site 对齐摆放
PIN D / DIRECTION INPUT / PORT LAYER M1 RECT ...引脚 D 在 M1 上的一块矩形（后面是坐标范围）
ANTENNAGATEAREA 0.021天线规则参数：栅面积，用于天线检查（route 阶段会用到）

下面这份示意是同一个结构的"教科书版"，编号更整齐：

标准单元在 lef 里长这样：

text
MACRO NAND2_X1  CLASS CORE ;                     # 标准单元（core cell）  ORIGIN 0 0 ;  SIZE 1.4 BY 2.4 ;                # 宽 1.4μm、高 2.4μm（同库单元等高）  PIN A    DIRECTION INPUT ;              # 输入引脚    PORT      LAYER M1 ;        RECT 0.2 0.6 0.5 1.8 ;     # 引脚在 M1 上的形状    END  END A  PIN B    DIRECTION INPUT ;    PORT      LAYER M1 ;        RECT 0.9 0.6 1.2 1.8 ;    END  END B  PIN ZN    DIRECTION OUTPUT ;             # 输出引脚    PORT      LAYER M1 ;        RECT 0.55 2.0 0.85 2.4 ;   # 引脚朝上（靠近行边界，方便与相邻行连线）    END  END ZNEND NAND2_X1

看这段能读出三件对工作有用的事：

  1. 所有 core cell 高度相同（这里 2.4μm）。这是标准单元的核心约定——等高才能按行排列、共享电源轨，工具才能自动摆放。
  2. pin 的方向与位置是固定的。DIRECTION INPUT/OUTPUT 决定"谁驱动谁"，位置决定"线从哪接进去"。文档里说 cell lef 要描述"输入 pin 名字、输入 pin 数量、输出 pin 数量"，就是这个意思。
  3. pin 常被放在靠近行边界的位置（如 ZN 在 y=2.0~2.4），这样上下相邻两行的单元可以直接连线，不用绕远。
常见坑 · 单元方向摆反了

现象：place 之后某些单元周围拥塞异常，或时序比预期差很多。 原因：单元被翻转（flip）后 pin 换到了另一侧，线要从远处绕过来；有些单元（如带埋孔结构的）甚至不允许某些朝向。 怎么查：在版图上按 pin 方向筛一遍，或看 place 阶段的拥塞图是否集中在这些单元附近。

小技巧

行业里描述单元/模块尺寸，习惯说 width（宽，X 方向） 和 height（高，Y 方向），不说"长宽"。

lef 的 SIZE A BY B 就是 宽 BY 高（A=宽、B=高）。为什么强调这个：跨部门沟通时"长"到底指哪边经常吵起来，统一说 X/Y 或 width/height 就没人会误。面积一律按 宽×高 算。

04

看 Memory 时看什么

宏单元（mem/SRAM）在 lef 里和标准单元同构（MACRO ... SIZE ... PIN ...），但你的关注点完全不同——因为它内部不能碰：

你要看为什么
实例名（常叫 M1、M2…）指代清楚是哪块 mem，别和金属层 M1 混
width × height决定 floorplan 能不能放下、通道还剩多少
bit 数/规格判断它是什么用途（数据缓存？指令缓存？）
pin 分布（在哪几条边）决定朝向怎么摆才能让线短
OBS内部禁布范围，摆错就把通道堵死
memory 从哪来

第三方 IP，不是你设计的。文档的说法很直接：memory 内部逻辑不用管，你只处理它的输入输出。所以别花时间研究它的功能，把 尺寸、pin、朝向 搞对就够了。

05

lef 与 def 的分工：一个是字典，一个是答卷

lefdef
内容库信息：形状、规则、pin 位置设计信息：这一版每个单元/端口的具体坐标
变化频率一个工艺/库一份，基本不变每跑一版都变
谁给工艺厂、库组上一道工序、顶层、或你自己导出
类比字典（字长什么样、笔顺规则）答卷（这一版你把字写在哪）

文档的说法很准：lef 是工具用来解析数据的（形状、线宽），def 存储单元的位置，可以还原我们的单元设置。 所以缺 lef 工具什么都干不了，缺 def 只是"从零开始摆"。

06

工艺越先进，lef 越难缠

制程演进路线：40nm → 32nm → 28nm → 12nm → 7nm → 3nm。每往前进一代，lef 里的规则复杂度和条数都是跳着涨的：

  • 层数变多（可选层、双倍/四倍曝光层），可用的走线资源不再"均匀"；
  • 间距规则从"一个数"变成"分段规则 + 与宽度相关 + 与相邻线状态相关"；
  • 出现大量"不许打 via 的区域""颜色（color）必须交替"之类的新约束（多重曝光带来的）。

这就是为什么老工艺用 Encounter/ICC 就够，先进工艺必须上 Innovus/ICC2——不是界面好看，是老引擎处理不了这些规则组合。

动手打开一份 lef，把这五样找出来

用课程页的练习终端（或真机）执行下面几条，边看边记：

bash
# 找工艺层定义：能看到每层的 DIRECTION / WIDTH / PITCH / SPACINGgrep -n "^LAYER" tech.lef | head -20 # 找 via 定义与它的电阻grep -n -A6 "^VIA " tech.lef | head -40 # 找一个单元，看它的尺寸和引脚方向grep -n -A20 "MACRO NAND2_X1" cells.lef # 数一数有多少个单元grep -c "^MACRO" cells.lef

验收标准：能指出该工艺有几层可用金属层、M1 与 M2 的 preferred direction 分别是什么、NAND2_X1 有几个输入 pin、它的输出 pin 在哪一侧。

自测
tech lef 与 cell lef 分别描述什么？
tech lef 描述工艺规则（金属层、宽度、间距、via、走线方向），与具体设计无关；cell lef 描述每个单元的形状、尺寸与引脚。
pitch 是什么？为什么它决定能塞多少条线？
同层相邻两条线的中心距，是布线器的最小步进单位；pitch 越小，同样宽度里能排下的线越多。
文档里"长度 10~100000 时间隔要达到 0.6"说的是什么规则？
分段间距规则：线长超过阈值后，为避免干扰/短路，最小间距要求变严。长线按默认间距绕就会报 DRC。
为什么 macro 的 OBS 会让布线绕不通？
OBS 是禁布区，macro 常把整片金属层标成 obs；把它摆在通道中间等于把通道堵死。
lef 和 def 的区别，用一句话说。
lef 是库信息（形状与规则，基本不变），def 是这一版设计的实际坐标（每版都变）。
为什么先进工艺必须换 Innovus/ICC2？
规则复杂度和数量大幅上升（多重曝光、颜色、分段间距等），老引擎处理不了这些约束组合，运行时间也撑不住。
过关标准（都能做到才算学完）
  • 能在 lef 里定位 VERSION/UNITS、LAYER、VIA、MACRO、PIN、OBS 六类关键段
  • 能解释 WIDTH / SPACING / PITCH / DIRECTION 各自约束什么
  • 能说出 via 电阻为什么要少换层
  • 能说清 lef 与 def 的分工（字典 vs 答卷）
  • 能说出标准单元"等高"这个约定为什么是自动布局的前提
