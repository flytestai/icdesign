Pin 与 Port：单元接口和模块接口

Pin vs Port: Cell Interface and Block Interface

版图界面上那些黄色的小点和小片，含义完全不同：单元上的叫 pin，模块边缘的叫 port。这一课把两者的层级、方向、物理形态讲清，再讲清 Input/Output 的相对性、模块 90 度翻转与镜像、以及"顶层给你的 port 位置与顺序必须一模一样"这条硬规定——它决定两个模块能不能拼上。

预计学习 ≈13 分钟 课表学时 2 pinportblockIO方向翻转floorplanmacro
01

两个词，两个层级

本章目标能一句话说清 pin 与 port 的层级差别（Cell 层 vs Block 层）；能说出 Input/Output 方向的相对性；能解释模块翻转/镜像后端口怎么办；能说出顶层给的 port 位置与顺序为什么"必须一模一样"。

新人在版图上最容易混的两个东西：

  • 单元（NAND、DFF）身上那些引脚——叫 pin；
  • 模块（你做的整个 block）边缘那些接口片——叫 port。

它们长得像（都是一小块金属 + 一个方向），但层级完全不同，改错一个的后果也不同。

PinPort
层级Cell 层：标准单元/宏单元自己的引脚Block 层：整个模块对外的接口
作用Cell 与 Cell 之间连接模块与模块之间、模块与顶层之间交互
谁定库（lef）里写死，你改不了floorplan 时由你摆（或由顶层指定）
版图外观单元内部的小黄点/小矩形模块边缘的黄色区域/箭头
例子DFF 的 CK、D、Q、S 脚你这一块对外的 data_in[7:0]、clk、rst_n
02

Pin：单元的接口，库说了算

pin引脚

标准单元或宏单元自己的输入/输出端点。名字、方向、形状都写在 cell lef 里（PIN A { DIRECTION INPUT ; PORT LAYER M1 ; RECT ... }）。

一个 DFF 的典型引脚（文档举的例子）：

Pin方向作用
CK输入时钟，沿到来时采样
D输入数据输入
Q输出数据输出
S（或 SE/SI）输入测试扫描相关（scan enable / scan in）

这些 pin 你一个都不能动。你能做的只有：把它摆在哪、朝哪个方向（翻转/镜像）、用什么线连它。这也是为什么 place 阶段"某类单元摆反了"会出问题——pin 的方向决定线从哪一侧接进来（LEF 那课讲过）。

03

Port：模块的接口，你说了算

port端口

一个 block 对外的接口，位于模块边缘。它决定这个 block 怎么和外面（相邻模块、顶层）连起来。

IO输入输出

Input/Output 的合称。说"这个模块的 IO 在哪边"，意思就是"它的 port 集中分布在哪个方向"。IO 是个统称，port 是具体的那个接口。

port 的三个关键属性：

  1. 位置：在模块边缘的哪一段（左边？上边？第几微米处）；
  2. 顺序：一组总线里 data[0] 到 data[7] 是从下往上排还是从上往下排；
  3. 方向：Input 还是 Output。
小技巧

分两种情况（后面会反复遇到）：

  • 自己做主：独立模块（顶层没给你约束），floorplan 时你按数据流决定 port 摆哪边；
  • 顶层指定：顶层（top）已经和别的模块拼好了版图，它会给你一个 def 文件，里面写死了你这一块的面积和 port 位置——这时候位置不是你选的，是必须遵守的。
04

方向是相对的：别人 Output 就是你的 Input

这一点在文档里被专门强调，因为拼接时最容易搞反：

text
   模块 A                              模块 B  ┌──────────┐   A 的 Output  ───→   B 的 Input   ┌──────────┐  │          ├───────────────────────────────────┤          │  └──────────┘                                    └──────────┘
  • 同一个信号，在 A 那边是 Output，在 B 那边就是 Input；
  • 界面上箭头朝内 = Input，朝外 = Output；
  • 所以"这根线是输入还是输出"这个问题，必须先问"站在谁的角度"。
常见坑 · 把 Port 方向配反

现象：模块单独跑没问题，一拼到顶层就报"驱动冲突"或"某根线没有驱动"。

原因：你按自己的理解把某个 port 定义成了 Output，但对接模块也把它定义成 Output（或者两个都当 Input），两边顶上了。

怎么查：拿顶层的连接关系（或对方给的 def/接口文档）逐个 port 对方向；一个信号只能有一个驱动源。

05

翻转与镜像：模块能转，port 顺序会变

模块在版图上可以摆放成 8 种朝向（N/S/E/W 四个方向 × 是否镜像），文档说的"支持 XY 翻转、允许 90 度旋转"就是这个意思。

orientation朝向

单元或模块在版图上的摆法，由"方向（N/S/E/W）+ 是否镜像（MX/MY）"组合而成。lef 里用 SYMMETRY X Y 声明这个单元允许沿哪个轴镜像；不允许的朝向工具不会去用。

text
   原方向          旋转 90°         镜像（X 轴翻转）  ┌────┬──┐      ┌────────┐       ┌────────┐  │ P1 │P2│      │P3      │       │P2    P1│  │    │  │      │        │       │        │  └────┴──┘      │P1    P2│       └────────┘                 └────────┘

关键后果：模块一翻转，port 的物理顺序就变了。如果顶层按"没翻转"的顺序连你，拼上去就是全错位——所以 floorplan 定完 port 之后，朝向也必须锁定并告知顶层。

为什么标准单元可以随便翻

标准单元是"等高"的（同一行内高度一致），翻转不会破坏行结构，而且 pin 一般在靠近行边界的位置，翻过来照样能接。但宏单元和 block 的 port 位置是语义相关的，翻转前必须确认对接方能不能接受。

06

宽高、长宽：说法习惯要对齐

文档顺带纠了一个用词习惯：

  • 描述芯片/模块尺寸时，行业里习惯说宽（width）和高（height），不是"长和宽"；
  • lef 里写的是 SIZE 10.792 BY 1.672，前面是宽（X 方向），后面是高（Y 方向）；
  • 面积利用率 = 单元总面积 / 可用面积，用的是同一个"宽×高"口径。

为什么提这个：跨部门沟通时"长"到底指哪一边，经常吵起来。统一用 width/height（X/Y）就没人会误。

07

Memory：只有 port，没有你关心的引脚

文档对 Memory 的描述很到位：第三方封装好的模块，内部逻辑连接不用管，你只需要处理它的输入输出。

对 PR 来说，macro 就是"一个很大的、内部不能摆东西的盒子"：

  • 它的 pin 在 lef 里定义（通常分布在边缘若干位置）；
  • 它的内部对布线是禁布区（OBS）；
  • 你在 floorplan 里要做的只有：摆在哪、朝哪边、周围留多少通道。

所以看到 memory 时，你关注的是它的 size + pin 分布 + 通道，不是它的功能。

动手在 lef 里数 pin，在 def 里找 port
bash
# 1. 找一个标准单元，看它有几个 pin、方向分别是什么grep -n -A3 "^  PIN " cells.lef | head -30 # 2. 统计某个单元里 input / output 各有几个grep -c "DIRECTION INPUT" cells.lefgrep -c "DIRECTION OUTPUT" cells.lef # 3. 在 def 里找模块的 port（PINS 段），看位置与方向grep -n -A6 "^PINS" design.def | head -30 # 4. 看 port 的方向与层grep -n "DIRECTION" design.def | head -10

验收标准：能报出某个单元有几个 input pin、几个 output pin，并从 def 里读出至少两个 port 的名字、方向与所在层。

自测
Pin 与 Port 的层级差别是什么？
Pin 属于 Cell 层（标准单元/宏单元自己的引脚，写在 cell lef 里，改不了）；Port 属于 Block 层（整个模块对外的接口，floorplan 时摆放或被顶层指定）。
DFF 的 CK / D / Q / S 分别是什么？
CK 时钟输入、D 数据输入、Q 数据输出、S 测试扫描相关输入。
Input / Output 为什么说是相对的？
同一个信号在驱动方是 Output、在接收方是 Input；箭头朝内是 Input、朝外是 Output，必须先确定站在谁的角度。
Port 的三个关键属性是什么？
位置（在边缘哪一段）、顺序（总线内如何排列）、方向（Input/Output）。
模块翻转或旋转 90 度后，port 会有什么问题？
port 的物理顺序/位置随之改变；若顶层按原朝向连接，拼上去会错位，所以朝向要和顶层锁定一致。
顶层给 def 文件的场景下，port 位置能自己改吗？
不能。def 里写死了面积与 port 位置，必须遵守，否则拼不上顶层。
为什么说 Memory 只需要关心 port？
它是第三方封装好的宏单元，内部逻辑无需处理，PR 只关心尺寸、pin 分布、朝向和周围通道（内部是禁布区）。
描述尺寸时应该用哪两个词？lef 的 SIZE 先后顺序是什么？
用 width（宽）和 height（高）；SIZE 前面是宽（X），后面是高（Y）。
过关标准（都能做到才算学完）
  • 能一句话区分 pin（Cell 层）与 port（Block 层）
  • 能说出 DFF 四个常见 pin 的作用
  • 能解释 Input/Output 的相对性，并说出箭头方向的约定
  • 能说出 port 的三个属性，以及"顶层指定"时不能自改
  • 能解释翻转/镜像为什么会让 port 顺序变化，为什么必须与顶层锁定
  • 知道 lef 的 SIZE 是"宽 BY 高"，面积按宽×高算
