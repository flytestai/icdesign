物理验证：DRC / LVS / ERC / Antenna

Physical Verification

版图交出去之前，必须证明"工厂造得出来"（DRC）和"和网表一致"（LVS）。这一课讲四种检查各自查什么、违例怎么读、怎么修。

约 35 分钟 课表学时 2 PVDRCLVSCalibre
01

四种检查

检查全称查什么不过的后果
DRCDesign Rule Check工厂的几何规则造不出来 / 良率崩
LVSLayout vs Schematic版图和网表是否一致连接错了，功能全错
ERCElectrical Rule Check电气规则（如 well 接触、浮空栅）闩锁、漏电、可靠性问题
Antenna天线效应检查长金属在制造中积累电荷栅氧化层被击穿
LVS版图与原理图一致性点击看解释

从版图里提取出实际的器件和连接关系，再和网表对比。多了、少了、连错了，都会报出来。
这是最"致命"的一项：DRC 不过工厂拒收，LVS 不过芯片直接不工作。

02

DRC 违例怎么读

Calibre 报告片段：

shell
RULECHECK M2.SPACE.1 :  12 Results  --------------------------------------------------  M2.SPACE.1 @ (1200, 3400) : 0.08um < 0.10um  M2.SPACE.1 @ (1250, 3400) : 0.09um < 0.10um

读法：

  • M2.SPACE.1：M2 层的最小间距规则。
  • @ (1200, 3400)：违例坐标。
  • 0.08um < 0.10um：实际 0.08，要求 0.10。

修法（按代价从小到大）：

  1. 挪线：把其中一根线移开几个轨道。
  2. 换层：把这段线改到 M3 走。
  3. 改宽度：如果规则允许（有时宽一点反而满足）。
  4. 重布：局部 rip-up & reroute。
常见坑 · DRC 数量从 8000 降到 300 就卡住

前面几千条是系统性的（布局/布线参数问题），改一次参数能消掉一大批。剩下几百条是"孤例"，每条都要单独看。

这时候不要再批量改参数，要：

  1. 按规则类型分类统计（M2.SPACE 多少条、VIA.ENCLOSURE 多少条）。
  2. 按区域聚类（是不是集中在某几个地方）。
  3. 分类修，一类一类清。

用命令统计：

bash
grep -o "^RULECHECK [A-Z0-9._]*" drc.rpt | sort | uniq -c | sort -rn | head

LVS 怎么对

bash
# Calibre 典型调用calibre -lvs -hier -turbo lvs.runset

LVS 报告通常先给一句结论：

shell
===================================================              LVS REPORT===================================================CELL COMPARISON RESULTS#     #################################################     #                    CORRECT                   ##     ################################################

如果不对，会列出：

shell
Net mismatch:  net VDD  vs  net VDD_COREInstance mismatch:  M1 (layout) has no counterpart in source

三类常见错：

现象原因
少了器件版图里漏画/漏提取（比如 well tap 没画）
多了器件电源 via 被当成器件、filler 处理不当
网络名不同电源网络命名不一致（VDD vs VDD_CORE）
Extraction提取点击看解释

从版图的几何图形反推出"这里有一个 NMOS、栅宽多少、源漏接哪"。LVS 的第一步就是提取。
提取规则（rule deck）由 foundry 提供，和后端用的 DRC deck 是配套的。

04

Antenna：一个容易被忽略的检查

制造过程中，长金属线像天线一样收集等离子体电荷。如果这条线连着晶体管的栅极，电荷会击穿很薄的栅氧化层。

判据：金属面积 / 栅面积 不能超过一个比值（由工艺给）。

修法：

  1. 跳层：把长线在中途换到更高层（break 掉累积）。
  2. 加二极管：在栅极附近加 antena diode 泄放电荷。

# 后端工具里通常有自动修setNanoRouteMode -routeAntennaFixMode true

Calibre 是商业工具。如果没有，可以用 KLayout 跑 DRC（开源，能读 GDS + 跑 Ruby/Python 规则脚本）。

# KLayout DRC 脚本骨架（示意）import pya layout = pya.Layout()layout.read("final.gds")m2 = layout.layer(2, 0)          # M2 层 # 检查 M2 间距 < 0.10um 的地方space_check = m2.space(0.10, False, False)# 结果写到报告
工作场景 · 为什么课上要练 KLayout

不是让你以后用 KLayout 交付（工业界用 Calibre），而是：

  1. 理解 DRC 的本质是"几何运算"（间距、包围、面积）。
  2. 没有商业工具时，你依然能验证自己的版图。

方法论比工具重要，这条在 PV 上体现得最明显。

过关标准（都能做到才算学完）

  • 知道 DRC 清到卡住时应该"分类 + 聚类"而不是乱调参数

自测：先自己想，再点开答案
DRC 和 LVS 分别保证什么？
DRC 保证工厂能造出来（几何规则）；LVS 保证版图和网表连接一致（功能正确）。
DRC 报告里 M2.SPACE.1 @ (1200,3400) : 0.08um < 0.10um 是什么意思？
M2 层间距规则违例，位置在 (1200,3400)，实际间距 0.08µm，要求 0.10µm。
DRC 剩几百条时应该怎么做？
按规则类型统计 + 按区域聚类，分类逐类修；不要再批量调参数。
LVS 报 "Net mismatch: VDD vs VDD_CORE" 通常是什么原因？
电源网络命名不一致（版图和网表用了不同名字），或电源连接关系画错。
Antenna 违例的两种修法？
跳层（中途换到更高层打断累积）或加天线二极管泄放电荷。
