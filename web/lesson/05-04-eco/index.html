ECO 实战：从 PT 的违例到版图上的一次改动

Engineering Change Order in Practice

版图都快送厂了，PT 报出 3 条 hold 违例。全流程重跑要两天，ECO 只要两小时。这一课给一套能直接用的 ECO 脚本骨架：读违例、生成改动、应用、局部重布、回签。

约 50 分钟 课表学时 4 ECOPTICC2时序修复等价性
01

ECO 是什么，什么时候用它

ECO（Engineering Change Order）是"只改必须改的地方"的一套流程。它不改 RTL、不重跑综合、不重做布局，直接在已有版图上动几十个单元。

情况全流程重跑ECO
时序差几条几小时到两天十几分钟到两小时
版图基本定型全部重来只动局部
风险新版本可能引入新问题改动面小，可控
前提无必须能精确定位到具体单元
工作场景 · 送厂前三天，PT 报 3 条 hold 违例

你签核完，PT 出报告：3 条 hold，最差 -0.07ns。全流程重跑要两天，时间不够。

正确动作：写一个 ECO，在 3 条路径的终点插入 3 个 delay cell，局部重布，回签。两小时。

这三个 cell 的面积代价是 3 × 0.76um² ≈ 2.3um²，占芯片 49440um² 的 0.005%。这就是 ECO 的价值：用最小改动换签核通过。

ECOEngineering Change Order，工程变更单点击看解释

原意是芯片设计流程里的"变更申请"。在后端语境下，特指在已有版图上做局部修改：换单元尺寸、插缓冲器、改连线，然后局部重布、重新签核。
三类 ECO：RTL ECO（改代码，要重跑综合）、门级 ECO（改网表，不动 RTL）、metal-only ECO（只改金属层，连硅片掩膜都不用重做，最贵也最快）。

02

完整链路：五个环节，一个都不能省

text
① PT 出违例报告（带具体 pin 名）      ↓② 生成 ECO 改动清单（哪个单元、换成什么、插在哪）      ↓③ 在 ICC2 里应用改动（改网表 + 改布局）      ↓④ 局部重布 + 局部时序优化（不是全芯片）      ↓⑤ 回签：PT 重新计时序、FM 验证等价性、DRC 复查
环节工具关键点
① 找违例PrimeTime必须 -significant_digits 4，否则 -0.07 会显示成 -0.1
② 生成清单脚本 / PT 的 fix_eco_timing清单必须是"人可读 + 机器可执行"
③ 应用ICC2改完先 check_lvs 再布线
④ 局部重布ICC2 / Innovus只布改动的网，别全芯片重布
⑤ 回签PT + Formality改了网表必须重跑 FM，否则等于没验证
03

改动清单长什么样

一份好的 ECO 清单是纯文本，一行一个动作，人能看懂、脚本能解析：

text
# eco.txt —— 每个字段：动作 目标 参数 原因size_cell   u_core/u_alu/U2317   BUF_X4      # 驱动不足，负载 12 个insert_buf  u_core/u_ctrl/reg_state[2]/D  DELAY_X1   # hold -0.07ns，需 +70psremove_buf  u_core/u_mul/U882    -           # 冗余缓冲，占了布线资源

为什么要用文本清单而不是直接写 Tcl：

  1. 可评审：发给同事看一眼就知道你要改什么；
  2. 可回退：清单留着，出问题按反向操作撤销；
  3. 可统计：grep -c insert_buf eco.txt 就知道插了多少个。
04

应用脚本：可执行的骨架

下面这段是能直接改成项目用的 ICC2 ECO 脚本。逐行看注释。

tcl
# ============================================================# apply_eco.tcl —— 读取 eco.txt，在已有版图上应用改动# 用法：icc2_shell -f apply_eco.tcl# 前提：block 已经 open，且已 save 过一个"ECO 前"的快照# ============================================================ set ECO_FILE  "./eco.txt"set SNAP_PRE  "snapshot_pre_eco"     ;# 出问题回退用 # ---- 0. 先存一个快照。这一步永远不要省 ----save_block -as $SNAP_PREputs "@@@ 已保存 ECO 前快照：$SNAP_PRE" # ---- 1. 读清单 ----set fh [open $ECO_FILE r]set lines [split [read $fh] "\n"]close $fh set n_size 0set n_ins  0set n_rem  0 foreach line $lines {  # 去掉行尾注释和首尾空格；空行跳过  set line [string trim [lindex [split $line "#"] 0]]  if {$line eq ""} { continue }   set act  [lindex $line 0]  set tgt  [lindex $line 1]  set arg  [lindex $line 2]   # 每个动作单独 catch：一条失败不影响后面的  switch -- $act {    size_cell {      # 把某个实例换成另一个库单元（同功能、不同驱动）      if {[catch {size_cell $tgt $arg} err]} {        puts "@@@ FAIL size_cell $tgt -> $arg : $err"      } else { incr n_size }    }    insert_buf {      # 在目标引脚前插一个缓冲/延迟单元      # -pin 指定插在哪个引脚之前，工具会自动断开原连线      if {[catch {        set buf [insert_buffer [get_pins $tgt] $arg]        set_attribute [get_cells $buf] is_physical true   ;# 标记为物理单元      } err]} {        puts "@@@ FAIL insert_buf $tgt : $err"      } else { incr n_ins }    }    remove_buf {      # 删掉冗余单元：先把它的输入连到输出，再删      if {[catch {        set ipin [get_pins -of_objects [get_cells $tgt] -filter "direction==in"]        set opin [get_pins -of_objects [get_cells $tgt] -filter "direction==out"]        set net  [get_nets -of_objects $ipin]        disconnect_net $net [get_pins -of_objects [get_cells $tgt]]        connect_net $net [get_pins -of_objects [get_nets -of_objects $opin] -filter "direction==in"]        remove_cell [get_cells $tgt]      } err]} {        puts "@@@ FAIL remove_buf $tgt : $err"      } else { incr n_rem }    }    default { puts "@@@ 未知动作：$act" }  }} puts "@@@ ECO 应用完成：size=$n_size insert=$n_ins remove=$n_rem" # ---- 2. 合法性检查（必须有）----legalize_placementcheck_lvs# 如果有错，这里就要停下来，不要继续布线 # ---- 3. 只布改动的网，不要全芯片重布 ----route_auto -nets [get_nets -of_objects [get_cells -hier -filter "is_physical==true"]]route_detail -incremental true # ---- 4. 局部时序优化：只优化受影响区域 ----set_app_options -name opt.post_route.effort -value mediumroute_opt -incremental # ---- 5. 出报告 + 存盘 ----redirect eco_drc.rpt { check_routes }redirect eco_timing.rpt { report_qor }save_block -as snapshot_post_ecoputs "@@@ ECO 完成，报告：eco_drc.rpt / eco_timing.rpt"
常见坑 · insert_buffer 之后忘了 legalize_placement

插进去的单元坐标是"挨着目标引脚"的浮点位置，可能和别的单元重叠。不 legalize 直接布线，会得到一堆 spacing DRC 和 short。

规矩：任何改变布局的 ECO，应用完第一件事就是 legalize_placement。

05

让 PT 帮你算：`fix_eco_timing`

手写清单适合少量违例。几百条违例时，让 PT 生成：

tcl
# ---- 在 PT 里 ----# 1) 先确认时序真的收敛过，报告可信report_timing -delay_type min -max_paths 20 -significant_digits 4 # 2) 让 PT 生成 ECO 修复建议（只出方案，不改网表）fix_eco_timing -type hold \               -methods {insert_buffer size_cell} \               -buffer_list {DELAY_X1 BUF_X2} \               -slack_lesser_than 0 # 3) 把方案写成脚本write_changes -format icctcl -output eco_hold.tcl#    icctcl = ICC2 能直接 source 的格式#    也可以 -format ptsh / dcsh / innovus
参数作用建议
-type hold / setup修哪类违例一次只修一类，先 hold 后 setup
-methods允许哪些手段只给 size_cell 更安全；insert_buffer 更有效
-buffer_list允许插哪些单元明确列出，别让工具自由发挥
-slack_lesser_than 0只修负 slack 的加 -slack_greater_than -0.1 可限制"只修严重的"
PT 生成的 ECO 为什么不建议直接 source

PT 只看时序，不知道物理。它可能建议把一个单元换大两档，但那个位置放不下；或者建议插 5 个 buffer，但那片区域已经拥塞。

正确做法：PT 出方案 → 人看一遍 → 删掉物理上不合理的 → 再应用。这个"人看一遍"是 ECO 里最值钱的十分钟。

06

实战：修那 3 条 -0.07ns 的 hold

回放我们实测的场景（12026 单元，ICC2，hold WNS -0.07ns）。

第一步：确认违例在哪

tcl
report_timing -delay_type min -max_paths 5 -significant_digits 4 \              -path_type full_clock_expanded

看到三条，都在 u_ctrl/state_reg[*] 的 D 端。原因：这几个触发器离时钟树末端很近，时钟到得早，数据反而"太早稳定"→ hold 违例。

第二步：判断修法

方案做法代价选不选
A. 数据路径插 delay cell在 D 端前插 DELAY_X1（约 60~80ps）3 个单元，面积 +2.3um²✅ 选这个
B. 调时钟 skew让这几个触发器的时钟晚到影响同一支路其他触发器❌ 风险大
C. 换更大驱动的上一级size_cell 换大可能改善也可能恶化❌ 不针对 hold

第三步：写清单

text
insert_buf  u_ctrl/state_reg[2]/D  DELAY_X1   # hold -0.0712ns，需 +72psinsert_buf  u_ctrl/state_reg[5]/D  DELAY_X1   # hold -0.0688nsinsert_buf  u_ctrl/state_reg[7]/D  DELAY_X1   # hold -0.0654ns

第四步：应用 + 回签

bash
icc2_shell -f apply_eco.tcl          # 应用改动pt_shell  -f scripts/pt.tcl          # 重新签核时序fm_shell  -f scripts/fm.tcl          # 等价性（关键！）

第五步：确认三件事

text
1) PT: hold WNS 从 -0.07 变成 +0.02  ✅2) FM: 2560/2560 等价              ✅3) DRC: 仍是 0                     ✅
常见坑 · 改了网表却没更新 SVF，FM 直接报不等价

Formality 靠 SVF（引导文件）知道"工具做了哪些优化"。ECO 手工改的网表不在 SVF 里，FM 会认为你改坏了逻辑。

两种处理：

  1. 手工改动只允许物理类（插 buffer/delay、换同功能不同驱动），并在 FM 里 set_dont_verify_points 排除这些点；
  2. 或者用 eco_netlist 生成增量 SVF 一并喂给 FM。

千万不要因为 FM 报错就把这几条设成 don't care——那是把"验证"变成"假装验证"。

07

ECO 的四条纪律

  1. 一次只改一类问题。先 hold，回签；再 setup，回签。混在一起改，出问题不知道是谁的锅；
  2. 每次改动前存快照（save_block -as snapshot_pre_xxx）。ECO 的价值就是可回退，不回退就没价值；
  3. 清单进 git。eco.txt 是文本，必须版本管理，写明"为什么改"；
  4. 改完必查三样：时序（PT）、等价（FM）、DRC。少一样都不算完成。
Metal-only ECO只改金属层的 ECO点击看解释

芯片已经流片回来，发现逻辑或时序问题，只能改金属层（因为晶体管层已经做死了）。做法是预先在版图里留一些备用单元（spare cell），需要时只改连线。
这是最贵最快的一种 ECO，通常只在"芯片已经回来但有问题"时用。

动手动手：写一份自己的 ECO 清单并解析它

在模拟终端里做这个练习（这是真实工作里的第一步）：

bash
cd ~cat > eco.txt <<'EOF'# 动作        目标                              参数        原因insert_buf    u_ctrl/state_reg[2]/D             DELAY_X1    hold -0.0712insert_buf    u_ctrl/state_reg[5]/D             DELAY_X1    hold -0.0688size_cell     u_core/u_alu/U2317                BUF_X4      驱动不足EOF # 统计每类动作有多少条awk '!/^#/ && NF>0 {print $1}' eco.txt | sort | uniq -c

预期输出：

text
   2 insert_buf   1 size_cell

再进一步：把"原因含 hold"的行挑出来

bash
grep hold eco.txt | awk '{print $2}'

过关标准：能用 awk + grep + sort + uniq 三个命令统计任意一份改动清单。这套动作每天都会用到。

过关标准（都能做到才算学完）
  • 能说出三类 ECO（RTL / 门级 / metal-only）的区别
  • 能画出 ECO 五环节链路，知道每环节用什么工具
  • 能写出 size_cell / insert_buffer / remove_buf 三条应用命令
  • 知道应用后必须 legalize_placement，再局部布线，再回签
  • 知道 ECO 后必须重跑 FM，且手工改动要用 SVF/dont_verify 正确处​理
自测：先自己想，再点开答案
ECO 相比全流程重跑，核心优势是什么？
改动面小、时间短、风险可控：只动必须动的单元，不重跑综合与全局布局。
为什么 PT 生成的 ECO 建议不能直接 source？
PT 只看时序不看物理，可能建议换大单元但位置放不下，或插 buffer 但区域已拥塞，需要人工筛一遍。
改了网表之后为什么必须重跑 Formality？
手工 ECO 不在 SVF 引导文件里，等价性没有被验证过；不重跑就等于没验证，芯片可能逻辑错误。
insert_buffer 之后为什么必须 legalize_placement？
新插单元的坐标可能与其他单元重叠，不合法化会产生 spacing DRC 和短路。
ECO 的四条纪律是什么？
一次只改一类、改前存快照、清单进 git、改完查时序/等价/DRC 三样。
