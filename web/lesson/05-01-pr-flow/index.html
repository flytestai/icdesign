28nm 全流程（一）：把 PR 串成项目

28nm PR Flow

前面学的是"每个阶段怎么做"，这一课讲"怎么把它们串成一条不会断的流水线"：目录怎么分、每步产物叫什么、怎么交接给 PT。

约 40 分钟 课表学时 4 流程28nm交接
01

PR 阶段的项目视角

单机跑一个流程，和项目里跑一个流程，差别在这几点：

单机练习真实项目
一个目录随便放按阶段/日期分目录，可回溯
脚本改完就覆盖脚本进版本管理，每次跑记录版本号
跑完看报告每步产出固定格式报告，自动汇总成一张表
一个人跑交接给别人能复现
Run Directory运行目录点击看解释

每次跑流程新建一个带时间戳的目录（如 run/20261122_1400/），里面放本次的脚本副本、日志、报告、结果。
好处：任何时候都能回答"三天前那版是怎么跑的、结果是什么"。

02

推荐目录结构

shell
proj/28nm/├── rtl/                    # 只读├── syn/│   ├── scripts/            # 综合脚本│   ├── netlist/ipa_top.v   # ← PR 的输入│   └── reports/├── pnr/│   ├── scripts/│   │   ├── 01_init.tcl│   │   ├── 02_floorplan.tcl│   │   ├── 03_power.tcl│   │   ├── 04_place.tcl│   │   ├── 05_cts.tcl│   │   ├── 06_route.tcl│   │   └── 07_finish.tcl│   ├── db/                 # 每阶段存盘│   ├── out/                # def / gds / spef / v│   └── reports/├── sta/│   ├── scripts/│   └── reports/├── pv/└── run/    └── 20261122_1400/      # 每次跑的完整现场

要点：脚本按阶段编号。 想重跑"从 CTS 开始"，只要 restoreDesign db/04_place.enc 再跑 05、06、07，不用从头来。

03

每步的产物与检查

步骤产物关键检查
01 初始化db/01_init.enc单元数、时钟、checkDesign
02 floorplandb/02_fp.enc利用率、宏位置、无重叠
03 powerdb/03_power.enc连通性、via 覆盖
04 placedb/04_place.enc密度、拥塞、setup WNS
05 ctsdb/05_cts.encskew、insertion delay、hold WNS
06 routedb/06_route.encDRC、open net
07 finishout/*.def/.gds/.spef最终 DRC、时序、面积
小技巧

不是怕崩，是怕改错。

比如 CTS 之后发现 floorplan 有问题，你可以 restoreDesign db/02_fp.enc 改完重跑 03~07；如果没有存盘，只能从 01 开始。

存盘的时间成本是 1 分钟，不存盘的代价是 4 小时。

04

交接给 PT：要交什么

PR 做完，STA 工程师（或者你自己）要用 PrimeTime 复签。需要三样东西：

文件内容为什么需要
final.v布线后的网表PT 要读设计
final.spef寄生参数（R/C）让 PT 用真实线延迟
ipa.sdc约束和 PR 用同一份，保证口径一致
bash
# PR 侧导出write_verilog out/final.vwrite_parasitics -format SPEF -output out/final.spef
常见坑 · 网表和 SPEF 不匹配

现象：PT 读入后报大量 cannot find pin 或时序完全对不上。

原因：网表是布线前导出的，SPEF 是布线后生成的（或者反过来）。两者单元名、连线名对不上。

规矩：网表和 SPEF 必须同一次运行、同一时刻导出。 导出后立刻用 grep 核对几个关键单元名是否都在。

工作场景 · 一次典型的交接事故

PR 工程师交了网表和 SPEF，STA 一跑，WNS −2.3ns，完全不可能。

排查发现：SPEF 是三天前那版（改过布局），网表是新的。延迟数据对不上，时序当然离谱。

从此这个团队的规定：导出脚本必须在同一条命令里同时产生 .v 和 .spef，并在文件名里带同一个时间戳。

过关标准（都能做到才算学完）
  • 能画出 28nm 项目的目录结构，并说明为什么脚本按阶段编号
  • 知道每步该存什么盘、检查什么
  • 能说出交接给 PT 的三件套
  • 明白网表和 SPEF 必须同时导出
自测：先自己想，再点开答案
为什么按阶段编号写脚本、每步存盘？
可以从任意阶段重跑，不必从头；改错时能快速回到上一个可用状态。
交接给 PT 需要哪三个文件？
布线后网表 .v、寄生参数 .spef、约束 .sdc。
网表和 SPEF 不匹配会有什么现象？
PT 报找不到引脚，或时序结果完全不合理（因为延迟数据对应的是另一个版本）。
为什么要建带时间戳的 run 目录？
留存每次运行的完整现场（脚本、日志、报告），可以回溯和复现。
