终端与文件系统：我是谁、我在哪、这儿有什么

Terminal & Filesystem

从零开始认识终端：文件系统为什么是一棵树、绝对路径和相对路径的区别、cd/pwd/ls 三件套，以及在真实芯片工程里目录为什么长成那样。

约 40 分钟 课表学时 3 Linux终端路径
01

终端是什么，为什么后端离不开它

终端（Terminal）是一个用打字代替点击的窗口。你在里面输入一行命令，回车，机器执行，把结果打回给你。

图形界面（GUI）不是更友好吗？在芯片行业有三个现实原因让终端成为主流：

  1. 服务器没有显示器。你用的不是自己电脑，而是一台放在机房的机器，几十个人共用。你只能远程打字进去。
  2. 流程要跑几个小时甚至几天。图形界面一断线就全没了，命令行可以挂在后台、写到日志、第二天来看。
  3. 一条命令胜过一百次点击。批量改 500 个文件、循环跑 20 组参数，只有脚本能做到。
Shell壳点击看解释

终端里真正理解你命令的那个程序。它把 ls 翻译成系统调用，再把结果排版好给你看。Linux 上最常见的是 bash，芯片公司大量用 tcsh（第六课讲）。

工作场景 · 你入职第一天的操作

组长给你一个账号和一句话："工程在 /home/proj/28nm/backend，你先看看目录结构。"

你打开终端，ssh 登进去，然后：

bash
cd /home/proj/28nm/backend     # 进入工程目录ls                             # 看看有什么

就这两个动作，决定了你接下来三个月能不能找到东西。找不到目录的人，后面所有工具都跑不起来。

02

文件系统是一棵树

Linux 里所有东西都挂在一棵树上，树根叫 /（读作"根目录"）。用户的家目录、硬盘、U 盘、甚至设备，全都是这棵树上的一个节点。

shell
/                          ← 根，所有东西的起点├── home/                  ← 所有用户的家│   ├── weizhen/           ← 你的家目录，登录后就站在这│   │   ├── proj/          ← 你自己建的工程│   │   └── .bashrc        ← 隐藏文件（点开头就是隐藏）│   └── lisi/├── usr/                   ← 装软件的地方│   ├── bin/               ← 大部分命令在这│   └── Synopsys/          ← EDA 工具安装目录├── etc/                   ← 系统配置文件└── tmp/                   ← 临时文件，重启可能被清空

树上的每个位置都有一条唯一的"路径"，就像你家的地址。

Path路径点击看解释

从某个起点走到目标文件所经过的一串目录名。用 / 分隔。
- 绝对路径：从根开始写，/home/weizhen/proj。无论你当前在哪，它都指向同一个地方——像"上海市浦东新区XX路1号"。
- 相对路径：从当前位置开始写，proj/rtl。你在不同目录下执行，指向的地方不一样——像"出门左转第二家"。

四个必须背下来的符号：

符号含义例子
/根目录，或者路径分隔符cd / 回到根
~当前用户的家目录cd ~ 等于 cd /home/weizhen
.当前目录./run.sh 运行当前目录下的脚本
..上一级目录cd .. 退一层
常见坑 · 路径写错，是新手第一个 90% 会犯的错

现象：

shell
$ cd proj-bash: cd: proj: No such file or directory

三种原因，按概率排：

  1. 你不在自己以为的目录里。先 pwd 确认。
  2. 目录名拼错，或者大小写不对（Linux 区分大小写，Proj ≠ proj）。
  3. 你用了相对路径，但起点不对。不确定就用绝对路径，从 / 开始写，最不容易错。
03

三件套：pwd、ls、cd

这三个命令你一天要敲几百遍。

bash
pwd# print working directory：打印"我现在在哪"# 输出：/home/weizhen ls# list：列出当前目录的内容# 输出：proj  Downloads  Documents ls -l# -l = long format，长格式：权限、大小、修改时间都给你# 输出的第一列 drwxr-xr-x 是权限（第三课讲） ls -a# -a = all，连隐藏文件一起显示（点开头的配置文件全在这） ls -lh# -h = human readable，把字节数变成 4.0K / 1.2M 这种人能读的单位# 后端常用组合：ls -lht  按时间倒序，最新的在最上面 cd proj# change directory：进入 proj 目录 cd ..# 回上一级 cd ~# 回家目录 cd -# 回到"上一次所在的目录"，来回切换两个目录时特别好用
Flag / 选项Flag / 选项点击看解释

命令后面 -l、-a 这种带减号的叫选项（flag / option），用来改变命令的行为。可以连写：ls -lh = ls -l -h。
记不住选项不用背，ls --help 或 man ls 会列全。man 是 manual 的缩写，装软件后查用法第一选择。

动手动手：在树上走一遍
bash
cd ~              # 回到家目录pwd               # 确认：/home/weizhenmkdir demo        # make directory，建一个叫 demo 的目录cd demo           # 进去pwd               # 确认：/home/weizhen/democd ..             # 退出来pwd               # 又回到 /home/weizhenls -l             # 看到 demo 目录，第一列是 drwxr-xr-x

过关标准：能不看笔记，连续做出"进目录 → 确认位置 → 退回来"这一套，并且知道每一步 pwd 会输出什么。

模拟终端试：pwd、ls -l、cd backend_lab/soc/pnr、cd ..
[autumn@eda ~]$
这里跑的是浏览器里的模拟环境：命令、输出、报错都按真实 Linux 的行为写，练手够用；真机上的路径与权限另有差异。
04

真实芯片工程的目录长什么样

你可能以为工程目录是随便建的。事实上，目录结构本身就是流程的一部分——工具的输出放错地方，下一环就找不到输入。

一个典型的数字后端工程：

shell
proj/                          ← 项目根├── rtl/                       ← 前端给的 RTL 代码（只读，别改）├── syn/                       ← 综合：脚本、网表、时序库│   ├── scripts/               ← .tcl 脚本│   ├── netlist/               ← 综合出来的 .v 网表│   └── reports/               ← 面积、时序报告├── pnr/                       ← 布局布线（Place & Route）│   ├── scripts/│   ├── db/                    ← 工具的数据库（Innovus 的 .enc、ICC2 的 .ndm）│   ├── def/                   ← 版图交换格式│   └── reports/├── sta/                       ← 静态时序分析（PrimeTime）├── pv/                        ← 物理验证（DRC/LVS）├── lib/                       ← 标准单元库、宏单元库├── lef/                       ← 物理抽象（每个单元多大、引脚在哪）└── run/                       ← 跑批日志，按日期分目录

注意三件事：

  1. 每一层都分 scripts / 输出 / reports。脚本和数据不混在一起，否则改脚本时容易误删结果。
  2. rtl/ 是只读的。前端交付的代码你不能改，改了就和前端对不上账。
  3. run/ 按日期分。run/20261122_0930/ 这种命名让你三天后还能找回"当时到底跑了哪一版"。
Netlist网表点击看解释

综合之后得到的"门级连接表"：里面不再是你写的 always 块，而是一堆标准单元（与门、或门、触发器）以及它们之间的连线。文件名通常是 .v。
后端所有工作的起点就是这个网表——它已经确定了"用哪些门、怎么连"，后端只决定"放在哪"。

动手动手：搭一个属于你的工程骨架
bash
cd ~mkdir -p myproj/{rtl,syn/{scripts,netlist,reports},pnr/{scripts,db,reports},sta,pv,lib,lef,run}# -p = parents，一次建多层目录，父目录不存在就自动建 cd myprojfind . -type d | sort# find 会递归列出所有目录，检查是不是都建对了

预期输出（顺序可能略有不同）：

shell
../lef./lib./pnr./pnr/db./pnr/reports./pnr/scripts./pv./rtl./run./sta./syn./syn/netlist./syn/reports./syn/scripts

过关标准：find . -type d | wc -l 输出 13（含根目录自己）。

05

命令的通用规律

Linux 命令基本都是一个模子：

shell
命令名  [选项]  [参数]ls      -lh      /home/weizhen
  • 选项以 - 开头，控制"怎么干"。
  • 参数是"对谁干"，通常是文件或目录。
  • 顺序不能反：ls -lh /home 对；ls /home -lh 大部分情况也能跑，但会让人困惑。

三个救命键：

按键作用
Tab自动补全。路径敲一半按 Tab，补不出说明路径错了——这是最有效的排错手段
↑ / ↓翻历史命令。别重复敲长命令
Ctrl + C强制中断当前命令。命令卡住、刷屏停不下来时用
小技巧

cd /home/wei<Tab> 会自动补成 cd /home/weizhen/。补不出来，说明你记的路径是错的。养成每敲两三个字符就按一次 Tab 的习惯，能消灭一大半路径错误。

过关标准（都能做到才算学完）
  • 能解释绝对路径和相对路径的区别，并各举一例
  • 能说出 / ~ . .. 四个符号的含义
  • 不看笔记，完成"回家 → 建目录 → 进入 → 退回 → 查权限"一整套
  • 能画出（或说出）后端工程目录的六层结构，并说明为什么 rtl/ 只读
自测：先自己想，再点开答案
cd .. 和 cd - 有什么区别？
cd .. 退到上一级目录；cd - 回到上一次所在目录（在两个目录之间来回切换用）。
ls -lh 里 -h 有什么用？
把文件大小从字节数变成 4.0K / 1.2M 这种人能读的单位。
为什么后端工程的 rtl/ 目录通常是只读的？
因为它由前端交付，是双方对账的基准。后端擅自修改会导致综合结果与前端验证过的版本不一致。
mkdir -p a/b/c 和 mkdir a/b/c 有什么区别？
-p 会把不存在的父目录一起建出来；不加 -p 时如果 a 不存在就会报错。
按下 Tab 补不出路径，通常说明什么？
路径本身写错了（拼错、大小写不对、或当前位置不对）。
