芯片是怎么造出来的：从沙子到 GDSII

How a Chip Is Made

后端工程师如果不懂制造，就会做出"设计上完美、工厂造不出来"的版图。这一课用最直白的方式讲清晶圆、光刻、工艺节点和标准单元库。

约 32 分钟 课表学时 2 基础概念制造工艺
01

先看全景：一颗芯片要过五道关

阶段谁做产出一句话
1. 规格产品/架构Spec 文档这颗芯片要干什么
2. 前端设计设计工程师RTL 代码用 Verilog 描述逻辑
3. 验证验证工程师测试平台 + 覆盖率报告证明逻辑没写错
4. 综合 + 后端综合/PD 工程师门级网表 → GDSII把逻辑变成版图
5. 制造 + 封测晶圆厂 / 封测厂芯片照图施工

后端在第 4 关的末段。你的下游是工厂，所以你必须懂工厂的规矩——这就是为什么后端有那么多"设计规则"。

GDSII版图数据格式点击看解释

一种几十年前定下来的二进制文件格式，描述每一层（金属、多晶硅、扩散区）上的几何图形。工厂的机器读它来制作掩模版。
它是后端的最终交付物。文件通常几百 MB 到几 GB。

02

制造到底在做什么

不用记工艺细节，理解三件事就够：

  1. 晶圆（Wafer）是一片圆形的硅片，直径常见 300mm。一片晶圆上会排几百上千个同样的芯片（die）。
  2. 光刻（Lithography）是用光"印"图形：先把光刻胶涂在晶圆上，用掩模版（mask）挡光曝光，被照到的地方性质改变，洗掉后留下图形。一层图形对应一张掩模版，先进工艺有 60~80 层。
  3. 一层一层叠起来：先做晶体管（底层），再用金属一层层连线（M1、M2、…、M8）。后端做的就是决定每层金属上画什么。
工作场景 · 为什么后端要关心"工厂能不能造"

你画了一根 0.02µm 宽的线，逻辑上完全正确，但工厂的机器最细只能画 0.04µm。这根线造出来会断，或者和旁边的线粘在一起。

所以工厂会给一份设计规则（Design Rule）：最小线宽多少、两根线最小间距多少、一个孔最小多大。后端跑完布线必须做 DRC（Design Rule Check），把所有违规的地方找出来改掉。

DRC 不是"工具挑刺"，是"工厂的验收标准"。

DRC设计规则检查点击看解释

Design Rule Check。检查版图是否满足工厂的几何约束：线宽、间距、包围、密度等。
DRC 不干净 = 工厂拒收 = 不能流片。所以它是后端的硬门槛，通常要清到 0。

03

工艺节点：40nm / 32nm / 28nm 是什么意思

这个数字大致指晶体管"栅极长度"的量级，越小越先进：

节点大致年代特点课程里在哪用
40nm2008 前后成熟、便宜、规则相对宽松阶段三，Innovus 项目
32nm2010 前后开始有明显的光刻效应阶段四，ICC2 项目
28nm2011 前后长期主力，手机芯片大量用阶段五，全流程实战
常见坑 · 节点数字不等于"实际尺寸"

"28nm 工艺"里最小的线不一定是 28nm，金属间距、氧化层厚度都另有数字。节点更像一个"代际名字"，不同厂家的 28nm 规则也不完全一样。

所以换工艺 = 换一整套库和规则，不能拿 40nm 的经验直接套 28nm。

04

标准单元库：后端的乐高积木

后端不画晶体管。你用的是标准单元（Standard Cell）：工厂预先做好、验证过的一批小功能块——与门、或门、触发器、缓冲器，高度统一（比如都是 1.4µm 高），宽度不同。

一排排摆好，就成了版图的主体。

shell
┌──┬────┬──┬──────┬──┬────┐   ← 一行（row），高度固定│INV│ NAND│DFF│  AOI  │BUF│├──┴────┴──┴──────┴──┴────┤│  ...  下一行 ...          │└──────────────────────────┘

一个库通常有几百个单元，同一种功能还分不同"驱动能力"（X1、X2、X4…），驱动强的面积大、延迟小。选哪个，就是后端和综合的日常决策。

Standard Cell标准单元点击看解释

预先设计好、高度统一的基础逻辑单元。后端把它们摆成行、连上线，就构成了芯片。
与它相对的是 Macro（宏单元），比如 SRAM、PLL，面积大、形状不规则，需要单独摆放并预留通道。

后端要用到的库文件有四种，缺一不可：

文件内容给谁用
.lib / .db时序、功耗、面积模型综合、STA
.lef物理抽象：多大、引脚在哪布局布线
.tf / tech lef工艺信息：层、线宽、间距规则布局布线
.gds完整版图最终交付、DRC/LVS
工作场景 · 缺库文件，流程一步都跑不动

真实项目里，"库没齐"是最常见的阻塞。比如综合报 Cannot find cell 'NAND2_X1'——.db 里没有这个单元；或者布线索要 .lef 里的引脚位置，没有就报 no pin location。

老手接手新项目第一件事不是跑流程，而是核对这四类文件是否齐全、版本是否匹配。

05

为什么要有 signoff（签核）

流片一次几百万到几千万。错了就是全废，没有"打个补丁重来"。

所以流片前有一整套签核流程，每一份报告都必须"绿"：

签核项检查什么不过会怎样
时序（STA）每条路径的 setup/hold芯片跑不到目标频率，或直接不工作
DRC工厂能不能造出来工厂拒收，或良率归零
LVS版图和网表是否一致连线错了，功能全错
IR Drop电源网络压降局部电压不够，芯片死机
EM电流密度金属被电迁移"烧断"，用几个月就坏
Signoff签核点击看解释

流片前的最后一道确认：所有检查项都通过，负责人签字放行。
签核用的工具通常比设计时用的更严格（比如设计时用 ICC2 内部 STA，签核必须用 PrimeTime），因为"自己检查自己"不够可信。

过关标准（都能做到才算学完）
  • 能说出芯片从规格到成品的五道关，以及后端在第几关
  • 能解释 GDSII、DRC、标准单元、Macro 四个词
  • 知道 40/32/28nm 各自在课程的哪个阶段用
  • 能列出后端需要的四类库文件及各自用途
自测：先自己想，再点开答案
后端交付给工厂的最终文件格式是什么？
GDSII。
DRC 检查的是什么？不通过会怎样？
检查版图是否满足工厂的几何设计规则（线宽、间距、密度等）。不通过工厂拒收，无法流片。
标准单元和宏单元有什么区别？
标准单元高度统一、成行摆放，是基础逻辑；宏单元（如 SRAM）面积大、形状不规则，需要单独摆放并预留通道。
.db 和 .lef 分别给谁用？
.db（时序/功耗模型）给综合和 STA；.lef（物理抽象：尺寸、引脚位置）给布局布线。
为什么签核要用 PrimeTime 而不是布局布线工具自带的时序分析？
因为"自己检查自己"不可信，签核需要独立工具交叉验证，避免同一套引擎的系统性偏差。
