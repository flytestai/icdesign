阶段二导读：后端基本概念与 PR 理论

Stage 2 Guide: Backend Fundamentals and PR Theory

阶段二已从"占位"扩充为 7 讲正式内容（16 学时）。本页是这一阶段的地图：每讲讲什么、彼此怎么咬合、先学哪个后学哪个，以及学完你应该能回答哪些问题。

约 15 分钟 课表学时 0 导读阶段二PR学习路线
01

这一阶段解决什么问题

本章目标知道阶段二的 7 讲各讲什么、顺序为什么这么排；能判断自己卡在哪一讲；明确学完这一阶段应具备的能力边界——能读懂一份 PR 交接数据、能说清一份时序报告的前提条件、能听懂同事在说什么。

阶段一的 Linux 和 Tcl 是"手上的工具"，阶段二才进"后端的语言"。这一阶段不讲怎么点工具，只讲概念、文件和它们之间的关系——因为 PR 的绝大部分事故，根因都不在操作，而在"拿到的这份数据是什么、它意味着什么"。

课表上这一阶段标的是 4 学时，本站按实际需要扩到了 16 学时：概念类内容讲不透，后面 41 学时的 Innovus 实操就会全程"照抄步骤但不知道为什么"。

03

为什么是这个顺序

text
[1] PR 是什么（目标）        [2] 九步流程（路径）        |                             |        +-------------> [3] 数据清单：要哪些文件                                        |        [4] lef（形状） -> [5] lib/rc tech（时间） -> [6] MMMC（多套环境） -> [7] sdc（要求）

前两讲建立"我在干什么、要经过哪些工序"的整体感；第三讲把每道工序需要的文件列清楚；第四到第七讲逐个拆开这些文件。这个顺序不能颠倒——先知道有 lib 这么个东西，再学 lib 里写了什么；先知道有多个 corner，再理解 sdc 的 uncertainty 为什么不能给 0。

04

学完应该能回答的问题

后面每一讲的 :::check 都是这套问题的细化。如果下面这些你都能顺畅答出来，这一阶段就可以过了：

过关标准（都能做到才算学完）
  • PR 的输入和输出分别是什么文件？为什么说它是"逻辑连接变物理连接"？
  • 九步流程里，哪一步决定芯片面积？哪一步最容易出 DRC？
  • init 阶段少给了 mmmc 文件，会有什么现象？（提示：不报错，但时钟为 0）
  • tech lef 和 cell lef 各描述什么？lef 与 def 的区别是什么？
  • 一个 cell 的延迟由哪两个量决定？transition 的值从哪来？
  • tsc28_lvtssg0p81v125c.lib 这个文件名能读出哪些信息？
  • 为什么 setup 用慢 corner、hold 用快 corner？
  • set_input_delay 约束的到底是什么？只写 -max 不写 -min 会怎样？
学习建议

这一阶段的课不要只看不动手。每讲都带可以在浏览器里跑的练习终端（阶段一学的 Linux 命令全都能用），看到 lef、sdc 这类文件内容时，亲手 grep 一遍，记忆强度完全不一样。

配套资源：每讲底部有自测题，题库 可以随机抽题，术语表 能按阶段筛出这一阶段所有中英对照术语。

自测：先自己想，再点开答案
阶段二现在一共有几讲、多少学时？
7 讲，16 学时（课表原标 4 学时，按实际需要扩充）。
为什么把"数据准备"放在 lef 和 lib 之前讲？
先建立"要哪些文件"的清单，再逐个深入内容；否则打开 lef 时不知道它在整个流程里干什么用。
可以跳过阶段二直接学 Innovus 实操吗？
不建议。实操每一步都在用这一阶段的概念（floorplan 算面积、cts 理解 skew、route 理解 DRC），概念不清就只能照抄步骤。
