Place 诊断：从一条坏路径找到布局热点

Placement Diagnostics

区分布局阶段，沿着时序、密度和布线资源定位热点，并选择范围合适的布局约束验证原因。

预计学习 ≈12 分钟 课表学时 0 InnovusPlaceSTA拥塞Padding
01

Global、Detail 和 Scan Reorder 各做什么

资料来源

本讲参考钉钉目录第 09 项的主题安排，正文与案例为原创教学示例，不是钉钉原文、截图或项目参数的转载。

Global placement 给出标准单元的大致位置，权衡线长、时序与密度。合法化负责把单元放到允许的站点和摆放行并消除重叠；详细摆放在合法位置附近继续细调。有些流程把合法化嵌进详细摆放，不要把全局布局的中间状态当成交付件。比较合法性应从相同阶段恢复，核对未摆、重叠、行对齐和区域限制，而不是只看全局算法是否跑完。

Scan reorder 依据摆放调整允许重排的扫描单元连接顺序，目标是减少测试链绕线，不是通用时序修复。执行前确认链的顺序限制、链段与不可重排对象；执行后核对完整性，按项目约定同步扫描链描述和测试交付。除非扫描链本身是待验证变量，本讲的对比不引入重排。

02

从 STA 路径追到密度图和拥塞图

看到负裕量，先记模式、工艺角、路径类型、起终点和寄生估算口径；取报告中单元与网络的增量延迟，找出贡献最大的几段。即便最差裕量改善，也可能只是原来的那条路径不再排第一，仍应单独按原起终点取报告，并看同一场景的 WNS/TNS 作护栏。

把延迟高的网定位到版图，查它是否绕过宏边、穿过窄通道、连接大量负载，或者驱动单元本身较弱。密度图描述摆放压力；拥塞图描述布线需求相对轨道资源的情况，要下钻到层和方向。高密不一定拥塞，低密也不保证有足够轨道。多个证据位置重合只能提出假设，还要通过可逆的小改动验证。

03

选对干预范围：Padding 或 Partial Blockage

Padding 给一组摆放对象预留间距。按 cell 可覆盖指定库单元类型的适用实例，按 instance 只影响被定位的某些实例，按 module 则以某层级模块的对象为作用范围；实际支持的粒度及优先级以工具版本与流程为准。没有证据支持同类单元普遍有问题时，不先施加全局 cell padding，否则会改变多处密度，难以归因。

Partial blockage 面向一个地理窗口，限制该区域可用摆放容量；不移动阻挡走线的宏，也不会增加金属轨道。使用前确认工具参数表示的是「允许比例」还是「阻挡比例」；本讲明确用允许比例描述意图。比起对整个模块下约束，若问题只在一个窗口，有限区域的实验更方便观察是否把负担转移到邻区。

04

实训起点：先固定路径和观察窗口

使用合成数据，不需要 Innovus。功能慢角的寄存器间 setup 路径从 U_SRC/Q 到 U_DST/D，初始裕量为 -0.12 ns。高延迟网络 N_hot 从通道一头进入，在两块 Memory 之间经过 W0；目标层水平方向需要 48 条轨道等效资源，该窗估计可用 40 条，因此溢出为 8。摆放统计按固定物理可用面积作分母，不因试验容量限制而改变口径。

基线中 W0 可用 1,000 µm²，已占 860 µm²；W1 已占 1,200/2,000 µm²。先在相同数据库中确认 W0 内集中的是一小片组合逻辑，不是每个同类型库单元都会产生类似问题；再查供电占轨、引脚接入与阻挡，确认试验不需要先改变物理通道或供电。若高延迟其实来自多扇出或弱驱动，同样的密度实验就只能作为排除法。

05

实训执行：做单变量 A/B 对照

从同一布局起点分成 A 和 B，各自经过同口径的合法化、估算布线和 STA。A 不加区域限制；B 只在 W0 加局部 partial blockage，把允许容量设为物理可用面积的 70%。不改网表、宏和供电，保持同一视图、时钟模型、报告筛选和工具设置。这里描述操作意图，不提供与具体版本绑定的命令。

06

区分剩余问题：要不要继续压低容量？

不先把百分比调得更低。在两次报告中对照 W0 的资源分母：资源一直是 40，改动只降低了需求。剩下一条溢出，既可能来自已无法再迁出的网络，也可能是引脚接入迫使几条网挤入同一方向。缩小观测窗并按层查看，如果另一方向还有容量，也不能假定这条网可毫无代价地换向；它仍需要合法的层转换和接入位置。

回查 N_hot 时还要看驱动输出斜率、负载数量与网络延迟的变化。如果路径中某段单元延迟显著变化，就不要把全部裕量改善直接归给通道。另抽一条同接口、但没有穿过 W0 的路径，用来辨别是否是估算设置整体变化。若多条无关路径同方向跳变，应先查报告场景和输入，而非直接归因给局部限容。

最后打开新最差路径，核对它是否经过 W1 或其他刚被挤入的区域。如果新最差路径原先已经存在且本轮未退化，问题可能只是排序变化；若其自身裕量下降，再查是否跟迁移的单元或新增绕路有关。排序变化与引入回归是两件事，依靠原路径加新路径的前后报告才能区分。

07

失败与回滚：证据不支持就撤销修改

  • 若 W0 密度降而需求几乎不变，撤掉试验窗口，复查几何通道、宏引脚可达性和供电占轨，别反复压低容量。
  • 若 W1 或其他邻区新增溢出，或新最差路径退化，按记录恢复 A，再缩小干预范围或改试实例级 padding。
  • 若 B 出现非法摆放或场景不一致，先修复试验设置，不用不等价的报告宣布赢了。
  • 保存两支检查点、窗口边界与比例语义、原路径和新最差路径报告、分层拥塞和合法性结果。合入前继续复查项目要求的其他场景和后续布线。
08

练习：只做一项修改，怎么验证？

坏路径和组合单元集中在同一条宏间通道，而且没有某类库单元普遍出问题的证据。先试小范围区域限容，再对照密度、目标方向拥塞、同一路径裕量及相邻窗口。密度下降却没有任何拥塞改善时，应换调查假设，不是继续扩大原操作。

自测
为什么本例先试局部 partial blockage 而不是全局 cell padding？
证据指向通道这一地理窗口，不指向某种库单元；局部改动更易验证且影响范围更小。
B 的指定路径改善到 -0.05 ns，为什么全场景 WNS 仍为 -0.08 ns？
同场景已有另一条路径更差，必须同时追踪原路径与汇总指标。
W0 密度下降但拥塞原样不动，下一步查什么？
查实际通道宽度、可接入宏引脚、供电和布线阻挡是否让该层轨道资源固定不足。
09

独立深练：扫描链线更短，能保住冻结的位序吗？

模拟扫描链对照（非工具实测）。 测试交接将 A→B 冻结为相邻且同向的有序片段，两者都属于时钟域 CK0。L 是跨到 CK1 所需的锁存器，必须留在两域边界；C、D 都属于 CK1，允许互换，但必须同步测试链描述。每版都是从扫描输入 SI 沿实际串行连线追到 SO 的结果。

text
模拟快照    实际连接顺序                 扫描寄存器   估算链长(µm)S0 基线     SI→A→B→L→C→D→SO             4            520S1 候选     SI→B→A→L→C→D→SO             4            360S2 候选     SI→A→B→L→D→C→SO             4            410

先独立交付。 分别判定 S1、S2 是否可以进入测试复核，列出冻结段、域边界、允许变动段所需的证据。写出应归档的新位序，并解释为什么仅比对成员集合、链长或扫描寄存器数量不能作出这个决定。

标准判断。 S1 线最短，但把 A→B 颠倒为 B→A，不能保留。S2 保住冻结相邻关系，也让 L 仍处于 CK0 到 CK1 的边界，只重排获准的 C、D。从 SI 到 SO 的新寄存器次序为 A、B、D、C；L 要记在连接清单中，但不算新的扫描寄存器。链的成员未变不代表各位对应的寄存器未变。

验收与回退。 在合法化后的实际网表再逐级追链，查遗漏、重复、断链及锁存器位置。同步扫描链描述，按测试流程验证或更新向量，并复查移位模式时序。若交付位序对不上或跨域检查失败，恢复 S0 的链连接和配套测试描述，保留失败差异，不能只回退其中一份。
