Floorplan 进阶：从 Die Size 输入到 Kick-Off Run

Advanced Floorplan Preparation

核对 Die Size 上游条件，按连接关系安排引脚和 Memory，再把 GUI 验证结果固化为可复跑的脚本。

预计学习 ≈14 分钟 课表学时 0 InnovusFloorplanIO PinMemoryKick-Off Run
01

Die Size：先核对谁提供了什么

这一讲在流程里的位置

Floorplan 进阶 · 承接面积核算。面积算清了，接下来定 Die Size、对齐端口、脚本化 Kick-Off Run。本讲解决"脚本重跑结果和 GUI 不一致"这类高频事故。

资料来源

本讲参考钉钉目录第 08 项的主题安排，正文与练习为原创，不转载钉钉原文、图片或项目参数。TAUREN 仅保留为资料中的名词；这里不推断其内部流程，不提供其定制命令。

Die Size 不是把标准单元面积除以目标利用率就能定下来。先向上游确认模块占位和长宽比、相邻模块的接口方向、宏面积和标准单元面积估算，以及电源与布线预留。整芯片还要检查封装对边界的要求。把每项标为硬约束或待确认假设，记录来源、版本、单位及坐标原点。输入冲突时找提供方确认，不用工具静默覆盖。

把 Die 与 Core 分开记。Die 是外边界，Core 定义摆放与相关物理规划的工作区；四侧间距不一定相同。若上游只给宽高，还要补齐原点和边界归属；若相邻模块给的是顶层坐标，先写清模块坐标到顶层坐标的变换。不要把接口边和摆放行边界视为同一组坐标。

02

先对齐 IO Pin，再按层级看 Memory

端口先按信号对接方向划边，再核对允许的金属层、轨道对齐、组内顺序和占用区。总线不仅要位号齐全，也要写出「沿哪条边、从哪端到哪端」的顺序。例如东边从下往上是位号零到三，不能由 GUI 当前缩放视角或名字排序决定。若项目允许吸附，说明吸到什么轨道，以及吸附后是否仍属于原定端口组。

Memory 可以先按实例所属层级分组，GUI 上色后查看同组宏、控制逻辑和端口是否相距太远，再按真实连线和高扇出控制网调整。颜色只帮助识别，不施加物理约束。宏朝向改变的不只是外形，也会改变实际信号脚和电源脚的位置；翻转前核对允许朝向、供电接入以及宏间通道，不要以排得整齐作为验收依据。

03

脚本化：让 Kick-Off Run 能从头重复

GUI 用于试方案，正式交付需从干净的初始数据库复现。把 Die/Core、端口分配、宏的位置和朝向放进受版本管理的脚本或输入文件，保存上游清单和对照报告。Kick-Off Run 作为一次最小试跑，只承诺导入、应用 Floorplan、保存检查点并核对实际结果，不代表已经完成配电、时序或布线签核。边界与端口基本检查可回看 Floorplan 实操。

应用顺序应写清：建立边界，放置固定对象，再执行端口分配，最后导出实际坐标和朝向。若后续还有自动引脚脚本，控制谁对同一端口有最终写入权；否则某次导出恰好发生在覆盖前，会把并未生效的设置误当成结果。没有项目工具环境时，可以用下面的教学清单纸面验证变换和判定规则。

04

把坐标系写进交接清单：Die、Core、单位和原点

例中上游给模块 Die 局部坐标 (0,0)–(800,600) µm、Core (20,20)–(780,580) µm，东边是四位总线 DATA。接口表同时说明总线纵坐标以 Core 左下的纵坐标为参考，偏移为 180、200、220、240 µm，因此在 Die 坐标系应得到 y=200、220、240、260 µm。脚本固定 x=800，沿东边由下往上排列。此例约定这些点都在指定的合法轨道上，不涉及额外吸附。

05

整组端口低了 20 µm：平移还是吸附

从干净检查点跑第一次，端口顺序正确但全组比预期低 20 µm。先看 DATA 首尾和中间点的差值，判断是组整体平移还是镜像、排序、单位错误；再核对宏位置没变、是否发生吸附及后续脚本覆盖。本例审查发现端口脚本把 Core 相对偏移当作 Die 绝对 y 使用，修正时只给这组 y 加上 Core 左下的 y，不移动东边的 x，也不移动宏。

未分配数两次都是零，说明「已分配」不能代替坐标验收。修正后比对全部四位，而不只抽样首尾；确认边、层、顺序和每位坐标都一致，再将清单和生成物交给下一阶段。若要交给顶层，还应按声明的变换再输出顶层坐标，不能把这组局部坐标直接传过去。

06

换人换目录重跑：交付不能依赖 GUI 状态

把修正后的输入和脚本交给另一位同学，从相同导入步骤在新目录重跑。让他只读上游清单，不参考你的 GUI 截图。先按对象名排序再比较结果，忽略报告生成时间这类变化，但绝不忽略坐标、朝向、约束未应用和警告。对象若缺了，不要仅比较两份清单的交集，否则缺失对象会被自动藏掉。

在交接单标清三类位置：上游冻结的接口、允许有限调整的初始宏点、工具根据工艺网格推导出的点。只有上游已允许偏差的对象才按公差验收；本练习的四个端口应在明确的合法轨道上，直接比较位置即可。若后续 PowerPlan 需要挪宏来改善供电接入，把变更回填到 Floorplan 输入，并按来源重新核对信号脚和电源脚，不能只在下游数据库里留一份特例。

若需向顶层报告差异，先用一个已知参考点检查平移方向，再用第二点验证轴向是否被交换或镜像。平移能解释全组恒定差值，而翻转或交换轴通常会改变点间向量。把这两个判断分开，可避免用一个正确的首点掩盖整条总线方向错误。

07

约束没生效也要记：未应用项清单

  • 整组位移固定：核对原点、轴和偏移；差值各不相同：优先查逐位吸附与组顺序；两次结果不能混为同一错误。
  • 若修正后违反接入区或轨道要求，暂停合入，核对上游输入与合法轨道的冲突；不能强塞到最近位置。
  • 若宏的位置或朝向同次发生改变，恢复干净分支，限制变更只作用于特定端口坐标转换。
  • 交付保存输入版本、两次实际坐标、修正记录、约束未应用列表和成功检查点；不要只保存成功后的 GUI 截图。
08

GUI 手调正确，脚本重跑却偏移

GUI 手调正确而脚本重跑时整组沿边偏移，先对照 Die/Core、原点和单位，再查自动吸附或后写脚本。用首尾点的预期值和实际值做差是定位手段，不是全组验收；修正后必须从干净数据库重跑。

自测
为什么本例只给端口 y 加 20 µm，不给 x 也加 20 µm？
y 输入以 Core 左下为参考；x 来自 Die 东边，是已处于目标坐标系的绝对边界。
第一次全部端口都已分配，为何仍验收失败？
四位已落点但坐标都不符合接口清单，已分配状态不验证位置正确。
GUI 给两个 Memory 同色是否会改变它们的合法位置？
不会；颜色只是分组标记，实际位置由约束和数据库对象状态决定。
09

宏脚都有接入点，两根网能不能同时接出

模拟宏脚可达报告（非工具实测）。 两根独立信号网从同一侧接出 RAM0/D0 和 RAM0/D1。宏尺寸、位置和合法朝向均已确认，电源走线保持固定。本题枚举了窗内所有可用的接入路径，每条路径都包括引脚落点、过孔和第一段轨道。R1、R2 是各自只能容纳一根网的过孔走廊，进入不同走廊的路径互不干扰。

text
模拟接入报告       D0 可选路径(走廊)     D1 可选路径(走廊)    单脚无可用点K0 基线            P0(R1)                P1(R1)               0K1 局部换轨试跑    P0(R1), P2(R2)        P1(R1)               0

先独立交付。 为每个版本画出两根网到走廊的对应关系，尝试给两根网同时分配合法路径。写明是否允许进入下一阶段，以及需要用哪份报告证明不是“两个落点都存在但共用同一瓶颈”。不要用宏间净距或单脚通过数替代这一判定。

标准判断。 K0 的两个落点虽不同，却必须通过同一条容量为一的走廊，所以最多接出一根网。K1 应把 D0 分到 P2(R2)、D1 保留 P1(R1)；若先给 D0 抢占 R1，仍会把 D1 堵住。局部换轨有效，是因为新增了可与另一条路径共存的选择，不只是因为引脚可选点数增加。

验收与回退。 用同一窗的短程试布线同时接两根网，复查实际过孔、轨道、连通性、间距和邻网可达性，并确认没有占用电源保留。若签核发现 R2 实际不可用或影响邻网，撤回换轨分支并恢复 K0；将两网共用走廊登记为未解决项，不把基线标成通过。
