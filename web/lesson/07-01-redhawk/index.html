IR Drop 与 RedHawk：芯片为什么会死机

IR Drop & RedHawk

时序全绿、DRC 全清，芯片照样可能死机——因为电压不够。这一课讲静态与动态 IR drop 的物理来源、一次 1A/10mΩ 的手算、RedHawk 需要的七类输入、报告的三要素、EM 的平均电流与峰值电流，以及课程环境没有 RedHawk 时怎么练。

约 35 分钟 课表学时 2 IR dropEMRedHawk功耗完整性
01

两个真实故障

本章目标学完这一章，你能根据"什么时候出错"反推是动态 IR、静态 IR 还是 EM，并说出该查哪份报告。

故障一：跑一天偶发一次错误。

现象：常温、标称电压下跑功能测试，几小时才错一次，换个芯片可能一天都不错。加电压（比如从 0.9V 提到 0.95V）之后错误消失。降频也能缓解，但不能根治。

机理：某个区域的电源网格在时钟沿同时翻转时撑不住，电压瞬间塌下去。触发器在低压下延迟变长，setup 不够，采到上一拍的数据。错误是概率性的，因为它取决于当时的翻转组合和工艺偏差。

故障二：高温下失效。

现象：常温测试全过，放进 125℃ 烘箱跑一会儿就挂；或者芯片用了半年，出问题的频率越来越高。

机理：前者是温度让阈值电压下降、漏电上升，局部电流变大，IR drop 恶化；后者是电迁移（EM）——电流把金属原子慢慢"推走"，电阻逐渐变大，直到某天断路。

这两种都不是时序问题，也不是 DRC 问题，而是功耗完整性问题。

Power Integrity (PI)功耗完整性点击看解释

研究"电能能不能干净、稳定地送到每一个单元"。包含三件事：IR drop（电压掉多少）、EM（线能扛多久）、电源噪声（电压抖多厉害）。
它和时序是上下游关系：电压掉了，延迟就变；延迟变了，时序结论就作废。

怎么和时序问题区分？看三个特征：

特征时序问题功耗完整性问题
复现性稳定复现，同一输入必错概率性，跑很久才错一次
对电压的敏感度降压变差，但幅度可预测降压急剧恶化，稍微抬压就好
对频率的敏感度降频一定变好降频有帮助，但可能仍错（静态 IR）
空间分布集中在某条路径集中在某个区域（hotspot）
02

IR Drop 分两种

本章目标学完这一章，你能用 V = I × R 和 ΔV = L × di/dt 各手算一次压降，并判断它占标称电压的百分比是否超标。
IR Drop电压降点击看解释

电流流过有电阻的电源网络时产生的电压损失。V = I × R，I 是电流，R 是从电源 pad 到该单元的等效电阻。
芯片内部不是一个电阻，是一张三维的网格（mesh），所以实际计算要解节点方程——这就是 RedHawk 这类工具做的事。

两种压降的成因和它们在版图上的样子，先看一眼全景：

从图里要看出什么：压降是"位置"的问题，不只是"数值"的问题。同一个芯片，红区在哪，决定该加 stripe、补 via 还是加 decap。

静态 IR drop：电阻分压

所有单元都在消耗平均电流，电流从 pad 经过电源环（ring）、电源条（stripe）、via、再到单元，每一段都有电阻。

这条"从 pad 到单元"的送电路径，层层接力长这样：

从图里要看出什么：R 不是某一个电阻，是五级串联的结果。所以"加宽某一级"只救那一级的账，哪一级最细，哪一级就是瓶颈。

手算一次最简模型：某条支路总电流 1A，从 pad 到该单元的等效电阻 10mΩ，标称电压 0.9V。

  • V_drop = 1A × 10mΩ = 10mV
  • 占标称电压：10mV / 900mV = 1.1%

看起来很小。但真实芯片的电流远不止 1A：

电流10mΩ 上的压降占 0.9V
1A10mV1.1%
3A30mV3.3%
5A50mV5.6%

5.6% 已经超过静态 IR 的典型阈值（3%~5%）。 这就是为什么大电流模块（CPU 核、DSP、SerDes）附近的电源条要加密——不是为了"好看"，是为了把等效 R 降下来。R 减半，压降就减半。

Static IR Drop静态电压降点击看解释

按平均电流算出的压降，反映电源网格的"直流供电能力"。阈值通常取标称电压的 3%~5%（典型值，按项目规格）。
它不依赖激励波形，只需要每个单元的平均功耗，所以在没有 VCD 的时候也能算。

动态 IR drop：di/dt 和电感

真正危险的不是平均电流，是瞬间电流。

时钟沿到来的一瞬间，几万个触发器同时翻转。电流在几十到几百皮秒内从接近 0 冲到峰值。这个变化率 di/dt 会在电感上产生压降：

text
ΔV = L × di/dt

手算：封装加片内的等效电感 100pH，电流在 1ns 内上升 1A。

  • di/dt = 1A / 1ns = 1 × 10⁹ A/s
  • ΔV = 100 × 10⁻¹² × 1 × 10⁹ = 0.1V = 100mV
  • 占 0.9V：11%

11% 已经超过动态 IR 的典型阈值（8%~10%）。而且这还没算电阻压降的叠加。

更麻烦的是：动态压降发生在时钟沿附近，正好是触发器采样的时候。 静态压降是"整体矮一截"，动态压降是"关键时刻突然塌一下"，后者对时序的杀伤力大得多。

Dynamic IR Drop动态电压降点击看解释

时钟沿附近瞬时大电流引起的局部电压塌陷。由 L×di/dt 和瞬态 I(t)×R 共同决定，通常要求控制在标称电压的 8%~10% 以内（典型值）。
分析它必须有真实翻转信息（VCD/FSDB），因为要知道"哪个信号在哪个时刻翻转"。

Decoupling Capacitor (Decap)去耦电容点击看解释

放在单元附近的小电容，作用像"本地小水库"：瞬间大电流来时先由它供电，等电源网络反应过来再补上。
它降低的是动态压降，对静态压降没有帮助。decap 放得离负载越近越有效，放在芯片另一头基本没用。

维度静态 IR动态 IR
电流平均电流瞬时峰值电流
公式V = I × RΔV = L×di/dt + I(t)×R
需要什么平均功耗（report_power）真实翻转波形（VCD/FSDB）
典型阈值3%~5% VDD8%~10% VDD
修法加 stripe/via、降 R加 decap、降 di/dt、优化时钟树
常见坑 · 拿平均功耗去算动态 IR

现象：有人用 report_power 给出的总功耗除以电压得到平均电流，代入 V=IR，得出"IR drop 只有 2%，没问题"。流片后高频死机。

原因：动态压降的峰值电流可能是平均电流的 5~10 倍。平均值看起来安全，峰值早就超了。

规矩：静态和动态是两套分析。动态必须有 VCD；没有 VCD 时，只能做"假设翻转率"的趋势分析，结论必须标注"不能签核"。

03

RedHawk 需要什么输入

本章目标学完这一章，你能列出一份完整的输入清单，并说出每一样由哪个团队提供、缺了会怎样。

RedHawk 本身不做设计，它只做"给定版图和电流，解出每个节点的电压"。所以输入的质量决定结论的质量。

输入内容谁给缺了会怎样
DEF（设计交换格式）布局布线后的物理信息（单元位置、电源网格、布线）PR 工具导出完全没有几何，跑不了
LEF（库交换格式）单元和宏的物理抽象（尺寸、引脚、阻挡层）库无法建 3D 模型
Liberty（时序功耗库，.lib）功耗模型（内部功耗、漏电、输入电容）库算不出每个单元耗多少电
SPEF（寄生参数格式）寄生 RC提取工具（StarRC/QRC）电源网络的 R 不准，压降偏乐观
功耗活动文件（VCD/FSDB/SAIF）每个信号什么时候翻转仿真/验证团队动态 IR 只能靠假设翻转率
电源网络描述（UPF，统一电源格式）电源域、开关、always-on 区域低功耗设计多电源域设计算不对
工艺技术文件（tech file / EM 规则）各层电阻率、电流密度上限foundry算不了 EM，也算不准 R

三件事必须提前确认：

  1. DEF 和 SPEF 是同一版。版图改了但 SPEF 没重提，压降会算错，而且不会报错。
  2. VCD 覆盖了最坏场景。仿真跑的是"平均负载"还是"峰值负载"？后者才有意义。一个只跑 idle 模式的 VCD，动态 IR 一定是"全绿"。
  3. 电源网格是完整的。有些流程在 early stage 只摆了部分 stripe，这时候算出来的压降没有参考价值。

常见坑 · 用 idle 模式的 VCD 做动态 IR

现象：动态 IR 报告全绿，最大压降 2.1%，签核通过。芯片回来后跑高负载应用就死机。

原因：VCD 来自一个只做初始化的测试用例，大部分模块没开。翻转率极低，峰值电流自然小。

怎么查：看 VCD 覆盖的模块清单和总翻转次数，和"最坏场景"的设计规格对比。动态 IR 的结论只对生成它的那个场景成立，换场景必须重跑。

04

报告怎么看

本章目标学完这一章，你能从一份压降报告里读出三个数：最大压降及其百分比、位置、超标单元数，并据此提出修法。

RedHawk 的输出通常是"热图 + 统计表 + 违例清单"三件套。下面是一份示意报告（数值是构造的，不是实测，真实报告字段名以你项目版本为准）：

text
Voltage Drop Summary (VDD, static)  Max drop            : 42.3 mV  (4.70% of 0.90V)  Location            : (1240.5, 860.2)  near u_core/u_dsp  Avg drop            : 18.7 mV  Violating instances : 37   (threshold 4.0%)  Total instances     : 128430

四行信息，每行都有用：

  1. Max drop 和百分比：决定"过不过"。42.3mV / 4.70% 已经超过 4% 的阈值。
  2. Location：决定"从哪修"。带坐标和模块名，可以直接回到版图上找。
  3. Avg drop：判断是"局部热点"还是"整体供电不足"。平均 18.7mV、最大 42.3mV，说明是局部问题，不是全局。
  4. Violating instances / Total：37 / 128430 = 0.03%，说明问题集中在很小的区域，修起来有针对性。

热图怎么看

热图（heat map）是一张俯视图，颜色代表压降。看三件事：

  • 红色区域在哪：是不是集中在某个 macro 旁边、某个高翻转模块、或者电源条稀疏的角落。
  • 红色区域的形状：圆形热点多半是局部电流大；条状热点多半是电源条断了或太窄。
  • 和布局对照：热点是不是正好在几个大 macro 的夹缝里——那里常常既缺 stripe 又被 macro 挡住。

分布怎么读

比"最大值"更有信息量的是分布：

压降区间单元数含义
0~2%118000绝大多数，正常
2~4%10393偏高但可接受，关注趋势
4~5%35超标，必须修
> 5%2严重，优先修

如果 2~4% 区间特别大，说明整体供电偏紧，加几条 stripe 就能整体下移；如果只有 >5% 的极少数，说明是局部孤例，改那一个区域就够。

工作场景 · 定位到 u_dsp 之后怎么修

报告说压降最大在 u_core/u_dsp 附近，三种修法按代价排：

  1. 加密电源条：在那个区域多打几条 stripe，或把现有 stripe 加宽。最直接，通常当天见效。
  2. 补 via 阵列：如果瓶颈在层间（比如 M5 到 M6 只有一个 via），补一排 via 能把等效电阻降一个数量级。
  3. 降局部功耗：让 dsp 降低翻转率（改设计）、或把它的一部分逻辑挪走、或加 clock gating。代价最大，但根治。

先判断是"供电不够"还是"用电太猛"：看该区域的电流密度图。电流密度正常但压降大 → 供电网络问题（加 stripe/via）；电流密度也高 → 用电问题（降功耗/分散）。

05

EM：电迁移

本章目标学完这一章，你能说清平均电流和峰值电流各管什么、为什么 via 最先坏、以及三种修法。
Electromigration (EM)电迁移点击看解释

电流密度超过限值时，金属原子被电子流"推着"慢慢迁移，在某个地方留下空洞（void）、在另一个地方堆成小丘（hillock）。空洞让电阻变大，最后断路；小丘可能顶破绝缘层，造成短路。
它是累积性失效：不是一上电就坏，而是跑几个月到几年才坏。

一个类比：水管里水流太急，管壁会被冲刷变薄。EM 就是"电子风"把金属原子吹走。水流越急（电流密度越大）、时间越长，坏得越快。

平均电流 vs 峰值电流

电流决定什么对应失效
平均电流（RMS）长期寿命原子慢慢迁移，几个月到几年后断路
峰值电流瞬时能力局部焦耳热、熔断（毫秒级）

所以 EM 检查要跑两遍：平均电流查寿命，峰值电流查熔断。 只看一个都不完整。

寿命有个经验公式（Black's equation，布莱克方程）：

text
MTTF = A × J⁻ⁿ × exp(Ea / kT)

MTTF 是平均失效时间，J 是电流密度，n 通常取 1~2，Ea 是激活能，k 是玻尔兹曼常数，T 是绝对温度。

不用背公式，但要读出三件事：电流密度翻倍，寿命掉到 1/2 到 1/4；温度升高，寿命指数下降；所以高温测试能加速暴露 EM 问题。

为什么 via 是薄弱点

一条宽线能扛 10mA，但它和上层连接的地方可能只有两三个 via。电流在 via 处被"挤"进很小的截面，电流密度瞬间放大几倍。再加上 via 的阻挡层（barrier）很薄、拐角处电场集中，所以EM 违例经常第一个出现在 via 上。

修法也就很直接：

检查项位置修法
电源线 EMstripe / ring加宽、加并联条、换成更高层金属
信号线 EM大驱动单元的输出加宽、降低驱动强度、插缓冲分担
via EM层间连接加 via 数量（阵列）、换更大的 via
常见坑 · 只修了线宽，没修 via

现象：EM 报告里同一条 net 反复违例，加宽了线还是红。

原因：瓶颈在 via，不在线。线宽加倍但 via 数量没变，电流还是挤在那几个孔里。

怎么查：报告里看违例对象是 layer 还是 via；版图上数一下这条 net 在换层处的 via 个数。加 via 通常比加线宽便宜，优先做。

06

一节可以背下来的结论

本章目标学完这一章，你能用五句话向别人解释"为什么时序全绿还会死机"。
现象病因先查什么
低频正常、高频随机错动态 IR drop时钟沿附近的电压波形、VCD 场景
用久了越来越容易错EM平均电流密度报告、via
某个区域功能异常、降压更明显静态 IR drop压降热图、该区域 stripe/via 密度
上电时序异常、某块不工作power gating 时序UPF、switch 控制信号、always-on 网络
高温才失效温度 + IR/漏电正反馈高温 corner 的 IR 与功耗

五条可以背下来的结论：

  1. 时序全绿不等于芯片能工作。 电压掉 10%，单元延迟可能涨 10%~20%，setup 直接崩。
  2. 静态 IR 看平均电流和网格电阻，动态 IR 看 di/dt 和 decap。 两者阈值不同，修法不同。
  3. 动态 IR 必须有真实激励。 假设翻转率只能看趋势，不能签核。
  4. EM 是累积失效。 平均电流定寿命，峰值电流定熔断，via 是最先坏的地方。
  5. 修 IR 三件事：加 stripe、补 via、加 decap；修 EM 三件事：加宽、并联、加 via。

这张表的用法：拿到一个"芯片不稳定"的现象，先按第一列定位到最像的一行，再去看对应的报告。不要一上来就重跑时序——时序工具看不到电压，它只会告诉你"在标称电压下没问题"。

评审时被问"你怎么排除是 IR drop"，答案就是这张表：说出你查了哪一行、看了哪个数、结论是什么。能排除，和能修，是两种能力，前者更值钱。

07

课程环境怎么练：没有 RedHawk 怎么办

本章目标学完这一章，你能在没有 RedHawk license 的情况下，用输入清单和报告样例完成一次"纸面分析"，并明确说出哪些结论不能下。

课程环境里没有 RedHawk，也不会有真实的工艺 PDK 和 VCD。所以这一课不能"跑一遍看看"，只能练"读"和"算"。 这不是偷懒，真实项目里 80% 的时间也是在看报告和判断，而不是点按钮。

能练的三件事

  1. 列输入清单：拿到一个项目目录，逐项确认七类输入是否存在、版本是否一致。这是最容易出错、也最容易被跳过的一步。
  2. 读样例报告：用上面那份示意报告，练"三个数 + 一个判断"——最大压降多少、在哪、超标几个、属于局部还是整体。
  3. 手算量级：给电流和电阻算 V=IR，给电感和 di/dt 算 L×di/dt，判断百分比。能手算出量级，就不会被报告里的小数点骗。

明确不能做的事

  • 不能生成真实热图（需要完整 DEF + tech file + 求解器）。
  • 不能得出"这个设计能签核"的结论（没有工艺数据和激励）。
  • 不能引用具体公司的压降数字（那些是保密数据）。

如果面试被问"你做过 IR drop 吗"，正确的答法是："我读过 RedHawk 的报告，能解释静态/动态的区别和三个关键数；完整跑过一次需要 PDK 和 VCD，我在课程环境里没有条件，但我能列出输入清单并判断报告是否可信。"——这比编一个"我跑过"要安全得多。

动手动手：用一份报告做纸面诊断

任务：用课程环境 ~/backend_lab/soc/power/ 下的样例报告（ir_static_summary.rpt、em_violation.rpt，都是构造的样例数据），完成一次诊断并写 150 字结论。

步骤：

  1. 打开 ir_static_summary.rpt，抄下 max drop（mV 和 %）、location、violating instances。
  2. 算 max drop / 标称电压，判断是否超过 4%。
  3. 看违例单元数和总数，算占比，判断是局部还是整体。
  4. 打开 em_violation.rpt，统计违例按 layer / via 分类的条数。
  5. 按"供电不够 / 用电太猛"二分，给出至少两条修法并排序。

过关标准：结论里必须包含"超阈值多少、集中在哪个模块、是局部还是整体、先加 stripe 还是先补 via、为什么"。不能出现"建议进一步分析"这种没有结论的话。

自测：先自己想，再点开答案
静态 IR 和动态 IR 的物理来源分别是什么？
静态是平均电流在电源网格电阻上的分压（V=IR）；动态是瞬时电流变化在电感上的压降（L×di/dt）加上瞬态 IR。
1A 电流、10mΩ 电阻、0.9V 标称电压，压降占多少？
10mV，占 1.1%。电流到 5A 就是 50mV、5.6%，超过静态阈值。
为什么动态 IR 必须有 VCD？
要知道每个信号在什么时刻翻转，才能算出瞬时峰值电流；没有 VCD 只能用假设翻转率，结论只能看趋势。
RedHawk 的七类输入里，哪两类最容易被忽略？
功耗活动文件（VCD/FSDB/SAIF）和电源网络描述（UPF）；前者决定动态分析是否成立，后者决定多电源域是否算对。
一份压降报告要读哪三个数？
最大压降及占标称电压的百分比、发生位置（坐标 + 模块）、超标单元数及占比。
EM 的平均电流和峰值电流各决定什么？
平均电流（RMS）决定长期寿命，峰值电流决定瞬时熔断和局部过热。
为什么 via 是 EM 的薄弱点？
电流在 via 处被挤进很小的截面，电流密度放大数倍；阻挡层薄、拐角电场集中，所以最先失效。
"芯片用了半年才开始出错"最可能是什么？
EM 累积失效，电阻逐渐变大；不是逻辑 bug，也不是时序约束问题。
过关标准（都能做到才算学完）

  • 能手算 V=IR 和 L×di/dt，并判断百分比是否超过 3%~5% / 8%~10%
  • 能列出 RedHawk 的七类输入，说出每类由谁提供、缺了会怎样
  • 能从报告里读出最大压降、位置、超标数，并判断局部还是整体
  • 能说清平均电流与峰值电流的分工，以及 via 为什么最先坏
  • 能背出五条结论，并向别人解释"时序全绿为什么还会死机"
  • 能明确说出课程环境里哪些结论不能下，以及为什么
