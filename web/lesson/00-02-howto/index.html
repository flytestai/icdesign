01

这个站怎么用：三种练法、题库、术语与进度

How to Use This Course

同一节课有三种练法（读懂、模拟终端里敲、真机上跑），这一课告诉你每种练法的边界在哪，以及题库、术语表、搜索、笔记、进度看板各自解决什么问题。

约 18 分钟 课表学时 1 使用方法学习方法练习
01

每一课的固定结构

这门课每一章都是同样的八段，顺序固定。你不需要每次都读完，但八段缺一段就说明这一课没学完。

段落长什么样你在这段该做什么
本章目标蓝色条，一句话先看，判断这一章值不值得现在读
工作场景绿色块，写"谁在催你"把知识和岗位需求挂上钩，知道学了用在哪
概念正文 + 生活类比慢读，这一段决定你能不能举一反三
术语卡灰色卡片，"点击看解释"先猜再看。直接点开等于没记
命令 / 表格黑底代码块，注释是灰色的注意灰色注释行，那才是"为什么"
动手蓝色框，命令 + 预期输出必须自己跑一遍，哪怕是在页面里的模拟终端
常见坑橙色块，贴真实报错原文遇到同样报错时回来搜这段
自测紫色块，点"看答案"先在心里回答，再点开对照
为什么顺序是这样

"先给目标、再给场景、最后才给命令"不是排版偏好。0 基础最常见的失败方式是：先抄命令，抄完不知道自己在干嘛，第二天全忘。把目标和场景放在前面，是逼你先建立"这件事为什么存在"的记忆锚点。

02

三种练法，以及各自的边界

同一节课的练习可以分三层，越往下越接近真实工作：

层级在哪练能练到什么练不到什么
一、读懂这一页概念、判据、报告怎么读手感
二、模拟终端页面里的黑框（阶段一课程内）Linux 命令、管道、重定向、脚本真实权限、真机路径、EDA 工具
三、真机你自己的 Linux 服务器 / 虚拟机全部，包括 EDA 工具与报错需要装环境

判断标准很简单：如果你在模拟终端里能把一条管道命令拼出来，说明你理解了管道；但如果你要在真机上跑 icc2_shell，那必须去真机——模拟终端里没有 ICC2。

模拟终端浏览器里跑的一个假 Linux点击看解释

这一版课程在阶段一的课里内嵌了一个模拟终端。它有虚拟文件系统和 30 多个命令（ls/cd/cat/grep/sed/awk/sort/管道/重定向/脚本），输出和报错都按真实 Linux 的行为写。
它不能做的事：装软件、连网络、跑 EDA 工具、改真实文件。它的定位是"上车前在模拟器上练方向盘"，不是替代真机。

03

模拟终端怎么用

阶段一的课（01-01 到 01-06）里会出现这样的黑框：

  • 点一下黑框就能输入，回车执行；
  • ↑ ↓ 翻历史命令，Tab 补全命令名和文件名；
  • 输入 help 看所有可用命令；
  • 右上角"重置"把文件系统恢复原样（你新建的目录、改过的文件都会清掉）。

建议的第一个练习（在终端里依次敲）：

bash
pwd                      # 我在哪个目录ls -l                    # 这个目录有什么，权限是什么cd backend_lab/soc/pnr   # 进到布局布线目录ls reports               # 看报告目录cat reports/drc.rpt      # 看 DRC 报告（12 行）
常见坑 · 一上手就 cd 到不存在的目录

真实终端里你会看到：

shell
cd: /home/autumn/pnr: No such file or directory

这不是"命令错了"，是路径错了。先 pwd 看自己在哪，再 ls 看下一层有什么，是新手最该养成的两个动作。

04

题库、错题本、术语表、搜索

页面顶部那排入口不是装饰，各自解决一个具体问题：

入口解决什么问题怎么用最有效
题库"看懂了"和"记住了"是两件事每学完一课，抽 10 题；答错的点"不会，记下来"
错题本同一个概念反复错每周清一次；清空了再学下一阶段
术语表英文缩写看不懂、记不住遇到不认识的先查这里，再看它在哪一课出现
命令速查写脚本时忘了参数按工具分组（Linux / Innovus / ICC2 / PT），不用翻课文
搜索记得"讲过"但找不到在哪搜中文或英文都行，命中直接跳到那一小节
小技巧

不要连续刷。学完一课当天刷一次，第三天再刷一次，第七天再刷一次——这是间隔重复，比一口气刷 50 题有效得多。错题本就是替你记"哪几个概念还没过关"。

05

笔记与进度

每课最下面有"我的笔记"，保存后会同步到服务器（按浏览器匿名 ID 识别，不需要注册）。

笔记别抄课文，写这三种东西最有用：

  1. 还没懂的点：哪一句读了三遍还不通；
  2. 自己的一句话解释：用你妈能听懂的话解释 DRC；
  3. 下次要试什么：比如"试试把利用率从 0.3 改到 0.5，看 DRC 变成多少"。

进度看板（顶部"进度"）按阶段列出每课完成了几章，并给出"下一课"。卡住的时候先看进度看板，比在目录里翻要快。

06

一个可执行的 8 周计划

课表是 113 学时，加上本站补充的实战约 137 学时。按每周 15 小时算，大约 9 周。给一个更保守、更适合在职学习的排法：

周内容每周产出（可验收）
1阶段零 + 阶段一（Linux 前四课）能在模拟终端里用 grep+awk 从报告里捞出所有负 slack
2阶段一（Tcsh、脚本、git）写出一个带参数、会打印日志的 run.sh
3阶段二能白板画出八阶段流程图，说出每步的输入输出
4–6阶段三 Innovus跑完 floorplan → CTS → route，每步存盘，能读 DRC 报告
7阶段四 ICC2走通同一套流程，能说出命令对应关系
8阶段五 PT + PV用 PT 出 WNS，能解释每一条违例的成因
9阶段六～九STA 深水区 + 经验 + 简历与面试
过关标准（都能做到才算学完）
  • 能说出每一课八段结构里"哪一段决定你会不会举一反三"
  • 知道模拟终端能练什么、不能练什么
  • 在模拟终端里完成过：pwd → cd → ls -l → cat 这一串
  • 打开过题库并抽过一轮 10 题
  • 在至少一课里写过一条笔记并保存成功
自测：先自己想，再点开答案
模拟终端里能不能跑 icc2_shell？
不能。它只有虚拟文件系统和 30 多个 Linux 命令，没有 EDA 工具；工具必须在真机上跑。
"看懂了"和"学会了"的区别用什么检验？
用自测题检验。看懂是能跟上解释，学会是能不看解释自己说出因果；题库就是干这个的。
为什么笔记不建议抄课文？
抄课文是低效重复。有效的是记"还没懂的点""自己的一句话解释""下次要试什么"，这三类才推动进步。
错题本应该怎么用？
每周清一次，答对的移出；同一道题反复错，说明那个概念要回去重读，不是继续刷题。
这一课八段结构里，哪一段最容易被跳过但最不该跳？
"工作场景"和"自测"。前者决定你记不记得住用途，后者决定你以为自己会不会。
