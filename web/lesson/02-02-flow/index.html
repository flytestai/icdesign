后端八阶段：谁给谁交付什么

The 8-Stage Flow

把综合、布局规划、电源、布局、时钟树、布线、收尾、签核八个阶段串成一条线。每一阶段产什么文件、给谁用、卡住了会怎样。

约 38 分钟 课表学时 2 基础概念流程交付物
01

一条线看懂全流程

shell
RTL 代码   │  ① 综合 Synthesis            → 网表 .v + 约束 .sdc + 时序库 .db   ▼门级网表   │  ② 布局规划 Floorplan        → 芯片尺寸、引脚、宏单元位置  (.def)   │  ③ 电源规划 Power Plan       → 电源网格、电源环、通孔   │  ④ 布局 Placement            → 每个标准单元的坐标   │  ⑤ 时钟树 CTS                → 时钟缓冲器 + 平衡后的时钟网络   │  ⑥ 布线 Route                → 所有信号的金属连线   │  ⑦ 收尾 Chip Finish          → filler、DRC 修复、导出 GDSII   ▼   │  ⑧ 签核 Signoff              → STA 时序 + PV 物理验证 + IR/EM   ▼GDSII → 工厂
netlist网表点击看解释

综合的输出。里面不再是 always @(posedge clk)，而是一堆标准单元实例和它们之间的连线。
把它想成"配料表"：用了哪些门、各多少个、谁连谁。

02

① 综合：从"逻辑"到"门"

综合工具读三样东西：RTL 代码 + 时序约束（SDC）+ 标准单元库（.db），输出门级网表。

它要做的决策：一个 32 位加法器，用行波进位（面积小、慢）还是超前进位（面积大、快）？用哪个驱动能力的单元？

tcl
# 综合脚本的核心三行（DC 为例）read_verilog rtl/ipa_top.v          # 读设计link                              # 把模块和库里的单元对应起来compile_ultra                     # 真正开始优化、映射到门
SDC时序约束文件点击看解释

Synopsys Design Constraints。用一套 Tcl 命令告诉工具"我要跑多快"：时钟周期多少、输入输出延迟多少、哪些路径可以不管（false path）。
约束写错，后面所有努力都是白费——工具会照着一个错误的目标优化。

工作场景 · 综合没做好的后果

综合把时序优化得太激进，插了一堆大驱动单元，面积超了 20%。后端拿到网表，发现 die 尺寸怎么排都放不下。

这时候只能回去重综合（几小时），或者硬着头皮做（后面 DRC、时序全是坑）。

所以后端工程师拿到网表第一件事是看：单元数、面积、有没有明显的时序违例。

03

② 布局规划：决定这颗芯片的生死

Floorplan 要做三个决定，后面所有工作都受它约束：

  1. 芯片多大（die size）。太大浪费钱（一片晶圆切的 die 少），太小布不通。
  2. IO 引脚放哪。引脚位置是封装决定的，放错了信号要绕远路。
  3. 宏单元（SRAM 等）放哪。这是最关键的——放错了会造成局部拥塞，怎么布都布不通。
shell
┌─────────────────────────────┐│  ┌──────┐        ┌──────┐   ││  │ SRAM │        │ SRAM │   │  ← 宏单元靠边、对齐、留通道│  └──────┘        └──────┘   ││                             ││     标准单元区域（rows）      ││                             ││  ┌──────┐                   ││  │ SRAM │                   ││  └──────┘                   │└─────────────────────────────┘
Utilization利用率点击看解释

标准单元占用的面积 ÷ 可用面积。
- 太低（<40%）：芯片白白做大了，浪费钱。
- 太高（>85%）：没有空间走线，布不通、DRC 爆炸。
- 常用区间：60%~75%（看设计和工艺）。
利用率是 floorplan 阶段最重要的旋钮。

常见坑 · floorplan 偷懒，后面全是坑

新手常见做法：宏单元随便一放，赶紧往下跑，想着"反正后面能优化"。

结果：布线阶段局部拥塞，工具反复拆线重布，跑 8 小时 DRC 还有 6000 个违例。回头改宏单元位置，前面所有工作作废。

经验值：floorplan 花的时间应该占整个 PR 的 30%。

04

③ 电源规划：芯片的血脉

每个单元都要吃电。电源规划就是铺一张"电网"：电源环（power ring）、电源条（power stripe）、连到每个单元的电源轨（follow pin）。

shell
┌════════════════════════════┐   ← power ring（外圈）║  │    │    │    │    │    ║   ← stripe（纵向/横向电源条）║  │    │    │    │    │    ║║ ─┼────┼────┼────┼────┼─   ║   ← follow pin（每行标准单元的电源轨）└════════════════════════════┘

为什么重要：线太细 → 电阻大 → 电压掉（IR drop）→ 单元工作变慢甚至失效；线太粗 → 占地方 → 没地方走信号线。

IR Drop电压降点击看解释

电流流过有电阻的金属线，电压会下降。芯片内部某点的实际电压低于电源电压，这个差值就是 IR drop。
严重时单元"吃不饱电"，延迟变大甚至不工作。签核阶段会用 RedHawk 这类工具专门分析（阶段七）。

05

④ 布局：把单元摆进去

把网表里几万个标准单元，按行摆进标准单元区。目标很矛盾：

  • 放在一起 → 连线短、时序好，但局部太挤、布不通。
  • 摊开 → 好布线，但连线长、时序差。

工具的做法是先算一个"最优位置"（可能重叠），再逐步摊开（legalize）到合法位置。

Congestion拥塞点击看解释

某块区域的走线需求超过可用轨道数。表现是布线工具报 routing congestion，或者绕远路导致时序变差。
拥塞是布局质量的直接反馈。看到拥塞，先看是不是宏单元通道留窄了、或者利用率太高。

06

⑤ 时钟树：让时钟同时到达

时钟要送到每一个触发器。几万个触发器，如果直接从时钟源拉线，延迟差异巨大，时序根本没法收敛。

CTS（Clock Tree Synthesis）的做法：建一棵树，一层层插缓冲器（buffer），让到每个触发器的延迟尽可能相等。

shell
        clk 源          │     ┌────┴────┐   buf       buf   ┌┴┐       ┌┴┐  buf buf   buf buf  │ │ │ │   │ │ │ │  FF FF FF FF FF FF FF    ← 每个触发器
Skew时钟偏斜点击看解释

时钟到达不同触发器的时间差。CTS 的核心目标就是把 skew 做小。
典型目标：先进工艺 <50ps，成熟工艺 <100ps。

工作场景 · CTS 前后的差别有多大

我们用一套真实流程跑过对比：CTS 之前 hold 违例报到 −10ns 级别（因为时钟路径长短不一），CTS 之后收到 −0.07ns，再靠后面修一下就到 0。

没有 CTS，hold 根本没法收敛。 这也是为什么"跳过 CTS 直接布线"是新手最典型的错误。

07

⑥ 布线：把线连起来

给每个连接找一条物理上可走的路径，分两步：

  1. 全局布线（global route）：规划大致走哪条通道，像导航规划走哪条高速。
  2. 详细布线（detail route）：精确到具体轨道、具体层、具体过孔。

布线要同时满足：连通、不短路、满足 DRC、时序不太差。

Via过孔点击看解释

连接不同金属层的"楼梯"。M1 到 M2 要打一个 via，M2 到 M3 再打一个。
via 太多会占面积、增加电阻；via 太少或打错位置会 DRC 违例。

08

⑦ 收尾：让它能交给工厂

  • 插 filler：标准单元行里会有空隙，填上不功能的填充单元，保证每层密度均匀（否则工厂铣不平）。
  • 修 DRC：把剩下的违例逐条修掉。
  • 导出：DEF（布局布线信息）、GDSII（完整版图）、网表（带寄生信息）。
09

⑧ 签核：最后一道门

自测：先自己想，再点开答案
综合的输出三件套是什么？
门级网表 .v、时序约束 .sdc、时序库 .db（约束和库其实是输入，交付给下一环的是网表+约束）。
为什么 floorplan 阶段的宏单元位置这么关键？
宏单元面积大、位置固定，放错会造成局部拥塞和长连线，后面布线怎么优化都救不回来，只能回头重做。
CTS 解决的是什么问题？
时钟到各个触发器延迟不一致（skew 大），导致 hold 无法收敛。CTS 通过插入缓冲器建树，把 skew 压小。
Utilization 太高和太低分别有什么问题？
太高没有走线空间，布不通、DRC 多；太低芯片面积浪费，成本上升。
流片前 signoff 至少要过哪几项？
时序（STA）、DRC、LVS，通常还有 IR drop 和 EM。
