Tcsh 基础：芯片公司的默认 Shell

Tcsh Basics

芯片行业大量流程脚本是 tcsh 写的。这一课讲清 set 和 setenv 的区别、别名、通配符、foreach 循环，以及 tcsh 与 bash 最容易踩的五个语法差异。

约 40 分钟 课表学时 3 tcshshell脚本
01

为什么是 tcsh

你可能会问：Linux 默认不是 bash 吗，为什么还要学 tcsh？

因为历史。EDA 工具在 1990 年代定型，那会儿主流是 csh/tcsh，于是所有公司的环境脚本、流程脚本都写成了 tcsh，一直沿用到现在。你今天进公司，看到的 setup.csh、run.csh 基本都是 tcsh。

现实一点说：你可以用 bash 干活，但你读不懂 tcsh 脚本，就看不懂公司的流程。

Tcsh增强版 C Shell点击看解释

csh 的改进版，语法接近 C 语言。特点是变量分两类（shell 变量和环境变量），用 set 和 setenv 分别设置。提示符常见 % 或 >。
查看当前 shell：echo $SHELL；临时切进 tcsh：直接敲 tcsh，退出用 exit。

02

变量分两种，这是 tcsh 最容易搞混的地方

类型设置命令读取方式能否传给子进程
shell 变量（本地）set x = 1$x❌ 不能
环境变量setenv X 1$X✅ 能
csh
set n = 10                # 定义本地变量 n，等号两边可以有空格echo $n                   # 10 setenv PROJECT ipa        # 定义环境变量echo $PROJECT             # ipa set path = ( /usr/bin /bin $HOME/bin )   # path 是 tcsh 的特殊数组变量# 注意：tcsh 里 PATH 用小写 path，是数组不是冒号字符串
常见坑 · tcsh 的 path 是数组，不是冒号串

bash：

bash
export PATH=/a:/b:$PATH        # 冒号分隔的字符串

tcsh：

csh
set path = ( /a /b $path )     # 空格分隔的数组，小写

在 tcsh 里写 export PATH=... 会直接报错；写 setenv PATH /a:/b 虽然不报错，但很多工具读的是 path 数组，行为会不一致。记住：tcsh 加路径用 set path = ( 新目录 $path )。

03

别名：把长命令变短

csh
alias ll 'ls -lht'alias la 'ls -la'alias .. 'cd ..'alias grep 'grep --color=auto' # 看所有别名alias # 取消unalias ll

常驻要写进 ~/.cshrc。老工程师的 .cshrc 里通常有十几个别名，那是十几年攒下来的效率。

Alias别名点击看解释

给一条（或一串）命令起个短名字。敲 ll 等于敲 ls -lht。
别名只在当前 shell 有效，所以写在 .cshrc 里才会每次登录都有。

04

通配符与命令历史

csh
ls *.tcl              # * 匹配任意多个字符ls run?.log           # ? 匹配单个字符ls run[1-9].log       # [] 匹配范围内一个字符ls {a,b,c}.tcl        # {} 展开成 a.tcl b.tcl c.tcl，csh 特有，很好用 !!                    # 重复上一条命令!$                    # 上一条命令的最后一个参数!*                    # 上一条命令的所有参数history               # 看历史命令列表
小技巧
csh
ls /home/autumn/backend_lab/ipa_soc/pnr# 输出一堆文件cd !$                 # 等价于 cd /home/autumn/.../pnr

长路径只敲一次，后面用 !$ 复用。

模拟终端试：setenv PDK /home/autumn/pdk、echo $PDK、alias ll="ls -l"、ll
[autumn@eda ~]$
这里跑的是浏览器里的模拟环境：命令、输出、报错都按真实 Linux 的行为写，练手够用；真机上的路径与权限另有差异。
05

控制流：if 和 foreach

csh
# if：注意 then 和 endif 都是独立一行if ( -f run.tcl ) then    echo "found run.tcl"else    echo "no run.tcl"endif if ( $n > 5 ) then    echo "big"endif # foreach：遍历一组值，end 结束foreach f ( *.tcl )    echo "processing $f"end # 遍历数字：csh 没有 range，用 seq 生成foreach i ( `seq 1 5` )    echo "round $i"end

判定条件常用写法：

写法含义
-f file是普通文件
-d dir是目录
-e path存在（不管类型）
-z "$str"字符串为空
$a == $b数值相等
"$a" == "$b"字符串相等（加引号）
常见坑 · tcsh 与 bash 的五个致命差异
场景bashtcsh
设环境变量export A=1setenv A 1
设本地变量A=1set A = 1
if 语句if [ ... ]; thenif ( ... ) then
循环for x in ...; doforeach x ( ... )
脚本第一行#!/bin/bash#!/bin/tcsh -f

还有一条最坑的：tcsh 的 set 不给等号右边加引号时，空格会被当成语法。set msg = hello world 会报错，必须 set msg = "hello world"。

动手动手：写第一个 tcsh 脚本
csh
# 建文件 hello.cshcat > hello.csh <<'EOF'#!/bin/tcsh -f# -f 表示不读 .cshrc，脚本跑得更快、更可复现（重要！） set who = "backend engineer"setenv RUN_MODE "test" echo "hello, $who"echo "mode = $RUN_MODE" foreach f ( a b c )    echo "file: $f"endEOF chmod +x hello.csh./hello.csh

预期输出：

shell
hello, backend engineermode = testfile: afile: bfile: c

过关标准：把 foreach 改成遍历当前目录下所有 .tcl 文件；如果目录里没有 tcl 文件，脚本应该打印一句 "no tcl files"（提示：先用 ls *.tcl >& /dev/null 判断，>& 是 tcsh 的重定向写法）。

工作场景 · 你会在哪种场合用到这些
  • 组长给你一个 run_all.csh，让你"改一下 top 名字跑另一版"。你得看懂 setenv DESIGN xxx 在哪。
  • 你要批量跑 8 组利用率参数，手敲 8 次不如写个 foreach。
  • 工具的启动脚本报错，你得判断是 set path 写错了还是 setenv 漏了。

tcsh 不需要学到能写复杂程序，但要能读懂、能改。

过关标准（都能做到才算学完）
  • 分得清 set 和 setenv，知道哪个能传给子进程
  • 知道 tcsh 加 PATH 用 set path = ( ... $path )
  • 会写 if / foreach 的基本结构
  • 记得脚本第一行写 #!/bin/tcsh -f
  • 能说出 tcsh 与 bash 至少四个语法差异
自测：先自己想，再点开答案
tcsh 里设置环境变量用什么命令？
setenv NAME value（bash 是 export NAME=value）。
#!/bin/tcsh -f 里的 -f 是什么意思？
不读取用户的 .cshrc。好处是启动快、结果可复现，不受个人配置影响。
tcsh 里给 PATH 加目录正确写法是什么？
set path = ( /new/dir $path )，小写 path，是数组。
set msg = hello world 为什么会报错？
因为 tcsh 把空格当分隔符，认为 world 是多余参数。要写成 set msg = "hello world"。
!$ 是什么？
上一条命令的最后一个参数，常用于复用长路径。
